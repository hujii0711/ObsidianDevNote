
Next.js에서 가장 핵심적인 개념인 SSR(서버 사이드 렌더링)과 SSG(정적 사이트 생성)의 차이를 핵심만 콕 짚어 정리해 드릴게요!

웹페이지를 "언제 만들어서 사용자에게 보여줄 것인가?"의 타이밍 차이라고 이해하시면 아주 쉽습니다.

## 1. SSR (Server-Side Rendering, 서버 사이드 렌더링)

> **"사용자가 요청할 때마다 서버에서 새로 기가막히게 구워줄게."**

SSR은 사용자가 페이지에 접속(요청)할 때마다 서버에서 실시간으로 HTML을 생성하여 브라우저로 보내주는 방식입니다.

- **동작 방식:** 유저가 페이지 요청 $\rightarrow$ 서버가 최신 데이터 페칭 $\rightarrow$ HTML 동적 생성 $\rightarrow$ 브라우저에 전달 $\rightarrow$ Hydration(자바스크립트 결합)
    
- **Next.js 함수:** `getServerSideProps` (App Router에서는 `fetch(url, { cache: 'no-store' })` 또는 `dynamic = 'force-dynamic'`)
    

### 🍉 장점

- **항상 최신 데이터:** 실시간 주식 차트, SNS 피드처럼 1초 정보가 중요한 페이지에 완벽합니다.
    
- **보안:** API 키나 민감한 로직을 서버에서 처리하므로 클라이언트에 노출되지 않습니다.
    

### 🍉 단점

- **느린 초기 응답:** 사용자가 요청할 때마다 서버가 연산을 하고 데이터를 가져와야 하므로, 서버가 바쁘면 로딩 시간이 길어집니다.
    
- **서버 부하:** 사용자가 몰리면 서버 비용과 부담이 커집니다.
    

## 2. SSG (Static Site Generation, 정적 사이트 생성)

> **"빌드할 때 미리 다 구워놨어. 넌 가져다 쓰기만 해."**

SSG는 개발자가 코드를 배포하고 **빌드(Build)하는 시점**에 미리 HTML 페이지들을 모두 만들어 두는 방식입니다. 사용자가 요청하면 이미 완성된 파일을 CDN(콘텐츠 전송 네트워크)을 통해 번개처럼 빠르게 유저에게 던져줍니다.

- **동작 방식:** 개발자 빌드(Next.js Build) $\rightarrow$ 모든 페이지의 HTML 생성 $\rightarrow$ CDN에 저장 $\rightarrow$ 유저가 요청하면 이미 완성된 HTML 즉시 반환
    
- **Next.js 함수:** `getStaticProps` (App Router에서는 기본 `fetch` 동작이 SSG처럼 캐싱됨)
    

### 🍓 장점

- **압도적인 속도:** 서버가 실시간으로 연산할 필요가 없어서 페이지가 거의 즉시 뜹니다.
    
- **SEO(검색엔진 최적화) 최적화:** 완성된 HTML이 준비되어 있으므로 구글 크롤러가 읽기 매우 좋습니다.
    
- **서버 부하 제로:** 이미 만들어진 파일만 전달하므로 트래픽이 폭발해도 서버가 터지지 않습니다.
    

### 🍓 단점

- **동적 데이터 취약:** 빌드할 때의 데이터로 고정되기 때문에, 데이터가 자주 바뀌는 페이지에는 불리합니다. (이를 보완하기 위해 일정 시간마다 페이지를 백그라운드에서 새로 고치는 **ISR** 방식도 존재합니다.)
    

## 한눈에 비교하는 요약표

|**특징**|**SSR (Server-Side Rendering)**|**SSG (Static Site Generation)**|
|---|---|---|
|**HTML 생성 시점**|**사용자가 요청할 때마다** 매번 생성|**프로젝트 빌드할 때** 한 번 생성|
|**속도 (TTFB)**|비교적 느림 (서버 연산 시간 필요)|**매우 빠름** (CDN 캐싱)|
|**데이터 신선도**|항상 최신 상태 (실시간)|빌드 시점의 데이터 (과거 데이터일 수 있음)|
|**적합한 서비스**|마이페이지, 관리자 대시보드, 커뮤니티 피드|블로그, 회사 소개 페이지, 이용약관, 공식 문서|

### 💡 요약하자면!

사용자마다 다른 화면을 보여주어야 하거나 실시간 데이터가 중요하다면 **SSR**, 누가 접속해도 언제나 똑같은 화면을 보여줘도 상관없고 속도가 중요하다면 **SSG**를 선택하시면 됩니다. Next.js는 한 프로젝트 안에서 페이지별로 SSR과 SSG를 섞어서 쓸 수 있는 게 가장 큰 장점이에요.
