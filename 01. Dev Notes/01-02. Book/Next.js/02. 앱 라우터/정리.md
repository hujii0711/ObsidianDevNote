동적라우트, 캐치올 세그먼트, 옵셔널 캐치올 세그먼트는 페이지 라우터와 동일

- 라우트 핸들러
앱 라우터 버전의 라우트 핸들러는 폴더 구조만으로 새로운 API 엔드포인트를 생성하는 기능이다. 페이지 라우터 버전의 API 라우트를 대체하는 기능이다.
라우트 핸들어는 API 라우트처럼 주로 간단한 기능이나 테스트를 목적으로 설계한 것이어서 대규모 프로덕션에서 필요로 하는 결제나 인증 등의 복잡한 기능을 구현하는 데는 적합하지 않다.

- 그룹 라우팅
그룹 라우팅은 경로에 영향을 미치지 않는 특정 폴더를 생성해 경로가 다른 여러 페이지를 하나의 폴더로 묶어준다. 그룹 라우팅 기능을 활용하면 경로에 영향을 주지 않는 폴더를 생성할 수 있어 경로가 서로 다른 페이지도 공통의 레이아웃을 적용할 수 있다.

- 서버 컴포넌트
앱 라우터 버전의 모든 컴포넌트는 기본적으로 서버 컴포넌트로 설정한다. 
서버 컴포넌트는 리액트 18 버전에서 처음 공개한 새로운 유형의 컴포넌트로서 리액트 자체에서 제공하는 기능이다. 서버 컴포넌트는 말 그대로 서버에서만 실행되는 컴포넌트로서 클라이언트인 브라우저에서는 실행되지 않는다. 서버 컴포넌트의 특징을 활용하면 브라우저에서 실행할 컴포넌트의 개수를 줄여 페이지의 로딩 시간을 크게 단축할 수 있다.
페이지 라우터 버전은 초기 접속 요청을 처리하는 과정에서 불필요한 컴포넌트들 까지 자바스크립트 번들에 포함하기 때문에 결국 하이드레이션 과정이 지연되어 TTI가 늦어진다. 페이지 컴포넌트 중에 상호 작용이 없는 컴포넌트는 따로 분류해 번들에 포함되지 않도록 설정하면 된다. 이때 번들에 포함되지 않도록 분류된 컴포넌트를 서버 컴포넌트라고 한다.(컴포넌트 중에는 사용자와 직접 상호작용하지 않는 컴포넌트도 있다.)
서버 컴포넌트는 서버에서만 실행되는 컴포넌트이다. 따라서 서버 컴포넌트로 분류된 컴포넌트는 사전 렌더링을 위해 딱 한 번 실행되며, 번들에 포함되지 않기 때문에 브라우저에서 다시 실행되지 않는다.
웹 라우터 버전을 모든 컴포넌트를 기본적으로 서버 컴포넌트로 설정하면 서버 컴포넌트를 중심으로 다양한 기능을 제공한다. 앱 라우터 버전은 하나의 페이지를 서버 컴포넌트와 클라이언트 컴포넌트로 나누어 구성할 수 있다. 상호작용이 필요 없는 부분은 서버 컴포넌트로 만들고, 상호작용이 필요한 부분은 클라이언트 컴포넌트로 구성한다. 서버에서 실행되기 때문에 보안에 민감한 작업이나 데이터를 처리할 때 유용하다.

- 서버 컴포넌트의 결과물
서버 컴포넌트를 실행한 결과물은 HTML이 아닌 RSC Payload라고 하는 특수한 형태의 직렬화 데이터이다.
Payload는 우리말로 순수한 결과물 또는 순수한 데이터라는 뜻이다. 결국 RSC Payload는 리액트 서버 컴포넌트의 순수한 결과물 정도로 해석할 수 있다. RSC Payload는 서버 컴포넌트의 렌더링 결과뿐만 아니라, 클라이언트 컴포넌트의 파일 위치나 전달할 Props 값 등 클라이언트 컴포넌트와 연관된 정보도 모두 포함된다.
클라이언트 컴포넌트의 실행 결과 HTML + 서버 컴포넌트의 실행 결과 RSC Payload = 이 두 결과를 결합해 완성된 HTML 페이지를 만든다.

- 서버 컴포넌트에서 데이터 페칭
(데이터 페칭: 서로 다른 프로그램이 데이터를 교화하는 작업)
앱 라우터 버전에서는 컴포넌트가 직접 서버에서 데이터를 가져온다. 따라서 getServerSideProps와 같은 함수를 사용할 필요 없이 컴포넌트가 필요한 데이터를 직접 가져올 수 있어 데이터 전달이 훨씬 단순해졌다.

- 데이터 캐시
데이터 캐시란 벡엔드 서버에서 불러온 데이터를 캐시하는 기능이다. 이 기능을 활용하면 한 번 불러온 데이터를 백엔드 서버에 다시 요청하지 않고 재사용할 수 있어 성능을 크게 향상시킨다.
Next.js의 데이터 캐시는 '캐시키'라는 고유 식별자를 기준으로 데이터를 저장하고 관리한다. 캐시키는 요청 주소, 쿼리 파라미터, HTTP 헤더, 캐시 옵션을 해시한 결과로 생성된다. 이 4가지 가운데 하나라도 다르면 서로 다른 캐시키로 생성되며 별도의 캐시로 관리된다.
데이터 캐시를 확인하려면 .next/cache/fetch-cache 폴더를 확인하면 된다.

- 리퀘스트 메모이제이션
Next.js 서버에서 특정 페이지를 사전 렌더링할 때 페이지에 필요한 데이터를 불러오는 요청이 중복 수행되지 않도록 최적화하는 기능이다.
페이지 컴포넌트가 API를 중복 요청하는 경우, Next.js의 리퀘스트 메모이제이션이 자동으로 중복 요청을 한 번만 수행하도록 최적화한다.
리퀘스트 메모이제이션은 페이지를 사전 렌더링하는 과정에서 fetch 메서드로 요청한 데이터를 일시적으로 캐시해 데이터를 중복 요청하지 않도록 한다. 이때 리퀘스트 메모이제이션에 캐시된 데이터는 사전 렌더링을 진행하는 동안에만 유효하며 사전 렌더링이 종료되고 완성된 HTML 페이지를 브라우저에 전달하면 자동으로 소멸한다.
데이터를 영구적으로 캐시하는 데이터 캐시와는 다르다. 리퀘스트 메모이제이션은 사전 렌더링 과정에서 중복 요청을 방지하기 위해 일시적으로 데이터를 캐시하는 데 초점이 맞춰져 있다. 따라서 사전 렌더링이 종료되면 저장한 캐시도 함께 사라진다는 점에 주의해야 한다.
--> 앱 라우터 버전에서는 영구적으로 데이터를 캐시하는 데이터 캐시뿐만 아니라, 사전 렌더링 과정에서 활용할 수 있는 리퀘스트 메모이제이션도 제공한다.
이 기능들을 적절히 활용하면, 데이터의 중복 요청을 방지하고 효율적인 캐시 전략으로 성능을 최적화할 수 있다.

- 에러 처리
try-catch 외에도 error.tsx 파일을 이용하면 특정 레이아웃이나 페이지에서 발생한 에러를 감지하고 처리할 수 있다.
계층적인 에러 처리 방식: 가장 가까운 폴더에 있는 error.tsx 파일이 먼저 에러를 처리하고 폴더에 error.tsx가 없다면 부모 폴더로 올라가 상위 레벨의 error.tsx가 대신 에러를 처리하는 구조이다.
error.tsx 파일은 반드시 클라이언트 컴포넌트로 정의해야 한다. 이유는 Error 컴포넌트가 오류를 복구할 때 브라우저가 제공하는 기능을 사용하기 때문이다.
Next.js에서 에러가 발생하면 현재 에러를 핸들링하는 error.tsx 파일과 같은 위치에 있거나 그보다 상위에 있는 레이아웃만 렌더링한다. 따라서 Next.js는 에러를 처리하는 error.tsx 파일보다 하위에 있는 레이아웃이나 컴포넌트 파일은 렌더링하지 않는다.

- 서버의 페이지 캐시 = 풀 라우트 캐시
풀 라우트 캐시는 Next.js 서버에서 사전 렌더링 결과로 생성한 HTML 페이지를 캐시하는 기능이다.
풀 라우트 캐시 기능으로 서버에 캐시하고 이후 브라우저에서 접속 요청이 오면 빠르게 응답한다.
캐시의 대상이 되는 페이지는 동적 데이터를 포함하지 않는 페이지이다. 자동으로 빌드 타임에 생성하고 풀 라우트 캐시에 보관한다.
동적 데이터: 데이터 캐시 옵션이 cache: "no-store" 또는 next: {revalidate:0}으로 설정된 데이터 페칭을 포함하는 페이지, 동적 API를 사용하는 페이지(헤더, 쿠키, 쿼리스트링)
풀 라우트 캐시에 보관하는 페이지를 스태틱 페이지, 그렇지 않는 페이지는 다이나믹 페이지라고 한다.
스태틱 페이지는 빌드 타임에 미리 생성해 풀 라우트 캐시에 보관하고, 다이나믹 페이지는 풀 라우트 캐시에 보관하지 않고 접속 요청이 있을 때마다 실시간으로 새롭게 생성한다.
다이나믹 페이지에서는 데이터 캐시나 리퀘스트 메모이제이션을 활용하면 충분히 빠른 성능을 유지할 수 있다.
--> 페이지 라우터는 SSG, SSR 방식처럼 오직 페이지 단위로만 캐시할 수 있지만, 앱 라우터는 독립적으로 캐시 기능을 조합해 페이지 내부의 특정 컴포넌트나 API 요청 결과까지도 개별적으로 유연하게 최적화할 수 있다.

- 클라이언트의 페이지 캐시 = 라우터 캐시
브라우저에서 페이지의 데이터를 직접 캐시하는 기능이다. 이 기능은 사용자가 브라우저에서 페이지를 이동할 때 불필요한 데이터 요청을 방지해 페이지를 빠르게 이동하도록 도와준다.
클라이언트 라우터 캐시의 주요 목적은 브라우저에서 페이지를 이동할 때 두 페이지가 동일한 레이아웃 컴포넌트를 사용하는 경우 중복 요청을 방지하는 데 있다. 이를 위해 브라우저에서 레이아웃 컴포넌트의 결과물인 RSC Payload를 클라이언트 라우터 캐시에 보관하는 방식으로 동작한다.
클라이언트 라우터 캐시는 브라우저의 메모리에 저장되는 캐시 공간으로 Next.js 서버에서 받은 서버 컴포넌트의 결과물 (RSC Payload)을 레이아웃과 페이지 단위로 나누어 저장한다.

- 프리페칭
앱 라우터 버전에서는 JS Bundle뿐만 아니라 서버 컴포넌트의 결과물인 RSC Payload도 함께 프리페칭한다.
이때 클라이언트 라우터 캐시에는 RSC Payload만 저장된다.
결국 클라이언트 라우터 캐시는 프리페칭된 RSC Payload를 활용해 서버 데이터에 대한 불필요한 요청을 방지하고 동일한 레이아웃이나 페이지 데이터를 재사용하도록 최적화한다.

- 라우트 세그먼트 컨피그(Router Segment Config)
앱 라우터 버전은 특정 페이지의 동작을 명시적으로 설정하는 라우트 세그먼트 컨피그 기능을 제공한다.
이는 특정 페이지의 캐시 유무나 갱신등의 동작을 강제로 설정하는 Next.js의 한 기능으로 약속된 이름의 변수를 레이아웃이나 페이지 파일에서 내보내는 방식으로 설정한다.
