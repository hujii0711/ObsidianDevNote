동적라우트, 캐치올 세그먼트, 옵셔널 캐치올 세그먼트는 페이지 라우터와 동일

- 라우트 핸들러
앱 라우터 버전의 라우트 핸들러는 폴더 구조만으로 새로운 API 엔드포인트를 생성하는 기능이다. 페이지 라우터 버전의 API 라우트를 대체하는 기능이다.
라우트 핸들어는 API 라우트처럼 주로 간단한 기능이나 테스트를 목적으로 설계한 것이어서 대규모 프로덕션에서 필요로 하는 결제나 인증 등의 복잡한 기능을 구현하는 데는 적합하지 않다.

- 그룹 라우팅
그룹 라우팅은 경로에 영향을 미치지 않는 특정 폴더를 생성해 경로가 다른 여러 페이지를 하나의 폴더로 묶어준다. 그룹 라우팅 기능을 활용하면 경로에 영향을 주지 않는 폴더를 생성할 수 있어 경로가 서로 다른 페이지도 공통의 레이아웃을 적용할 수 있다.

- 서버 컴포넌트
앱 라우터 버전의 모든 컴포넌트는 기본적으로 서버 컴포넌트로 설정한다. 
서버 컴포넌트는 리액트 18 버전에서 처음 공개한 새로운 유형의 컴포넌트로서 리액트 자체에서 제공하는 기능이다. 서버 컴포넌트는 말 그대로 서버에서만 실행되는 컴포넌트로서 클라이언트인 브라우저에서는 실행되지 않는다. 서버 컴포넌트의 특징을 활용하면 브라우저에서 실행할 컴포넌트의 개수를 줄여 페이지의 로딩 시간을 크게 단축할 수 있다.
페이지 라우터 버전은 초기 접속 요청을 처리하는 과정에서 불필요한 컴포넌트들 까지 자바스크립트 번들에 포함하기 때문에 결국 하이드레이션 과정이 지연되어 TTI가 늦어진다. 페이지 컴포넌트 중에 상호 작용이 없는 컴포넌트는 따로 분류해 번들에 포함되지 않도록 설정하면 된다. 이때 번들에 포함되지 않도록 분류된 컴포넌트를 서버 컴포넌트라고 한다.(컴포넌트 중에는 사용자와 직접 상호작용하지 않는 컴포넌트도 있다.)
서버 컴포넌트는 서버에서만 실행되는 컴포넌트이다. 따라서 서버 컴포넌트로 분류된 컴포넌트는 사전 렌더링을 위해 딱 한 번 실행되며, 번들에 포함되지 않기 때문에 브라우저에서 다시 실행되지 않는다.
웹 라우터 버전을 모든 컴포넌트를 기본적으로 서버 컴포넌트로 설정하면 서버 컴포넌트를 중심으로 다양한 기능을 제공한다. 앱 라우터 버전은 하나의 페이지를 서버 컴포넌트와 클라이언트 컴포넌트로 나누어 구성할 수 있다. 상호작용이 필요 없는 부분은 서버 컴포넌트로 만들고, 상호작용이 필요한 부분은 클라이언트 컴포넌트로 구성한다. 서버에서 실행되기 때문에 보안에 민감한 작업이나 데이터를 처리할 때 유용하다.

- 서버 컴포넌트의 결과물
서버 컴포넌트를 실행한 결과물은 HTML이 아닌 RSC Payload라고 하는 특수한 형태의 직렬화 데이터이다.
Payload는 우리말로 순수한 결과물 또는 순수한 데이터라는 뜻이다. 결국 RSC Payload는 리액트 서버 컴포넌트의 순수한 결과물 정도로 해석할 수 있다. RSC Payload는 서버 컴포넌트의 렌더링 결과뿐만 아니라, 클라이언트 컴포넌트의 파일 위치나 전달할 Props 값 등 클라이언트 컴포넌트와 연관된 정보도 모두 포함된다.
클라이언트 컴포넌트의 실행 결과 HTML + 서버 컴포넌트의 실행 결과 RSC Payload = 이 두 결과를 결합해 완성된 HTML 페이지를 만든다.

- 서버 컴포넌트에서 데이터 페칭
앱 라우터 버전에서는 컴포넌트가 직접 서버에서 데이터를 가져온다. 따라서 getServerSideProps와 같은 함수를 사용할 필요 없이 컴포넌트가 필요한 데이터를 직접 가져올 수 있어 데이터 전달이 훨씬 단순해졌다.

- 데이터 캐시
데이터 캐시란 벡엔드 서버에서 불러온 데이터를 캐시하는 기능이다. 이 기능을 활용하면 한 번 불러온 데이터를 백엔드 서버에 다시 요청하지 않고 재사용할 수 있어 성능을 크게 향상시킨다.
Next.js의 데이터 캐시는 '캐시키'라는 고유 식별자를 기준으로 데이터를 저장하고 관리한다. 캐시키는 요청 주소, 쿼리 파라미터, HTTP 헤더, 캐시 옵션을 해시한 결과로 생성된다. 이 4가지 가운데 하나라도 다르면 서로 다른 캐시키로 생성되며 별도의 캐시로 관리된다.
데이터 캐시를 확인하려면 .next/cache/fetch-cache 폴더를 확인하면 된다.
