**`@wrap_model_call`이 적합합니다.**

모델을 동적으로 바꾸려면 모델 호출 직전에 요청(`ModelRequest`)의 `model`을 교체할 수 있어야 하는데, 이것은 `wrap_model_call`만 할 수 있습니다. `@before_model`은 state를 읽고 업데이트하는 훅이라 **어떤 모델로 호출할지는 바꿀 수 없습니다.**

|구분|`@wrap_model_call`|`@before_model`|
|---|---|---|
|모델 교체|가능 (`request.override(model=...)`)|불가|
|도구, 시스템 프롬프트 변경|가능|불가 (state만 변경)|
|반환값|`ModelResponse`|state 업데이트 dict 또는 None|
|적합한 용도|모델 선택, 폴백, 재시도|메시지 트리밍, 요약, 검증|

## 예제: 대화 길이에 따라 모델 선택

```python
from langchain.agents import create_agent
from langchain.agents.middleware import wrap_model_call, ModelRequest, ModelResponse
from langchain.chat_models import init_chat_model
from typing import Callable

basic_model = init_chat_model("openai:gpt-4.1-mini")
advanced_model = init_chat_model("openai:gpt-4.1")


@wrap_model_call
def dynamic_model_selection(
    request: ModelRequest,
    handler: Callable[[ModelRequest], ModelResponse],
) -> ModelResponse:
    """메시지 수에 따라 모델을 동적으로 선택"""
    message_count = len(request.state["messages"])

    if message_count > 10:
        model = advanced_model   # 긴 대화는 고성능 모델
    else:
        model = basic_model      # 짧은 대화는 경량 모델

    return handler(request.override(model=model))


agent = create_agent(
    model=basic_model,   # 기본 모델
    tools=[...],
    middleware=[dynamic_model_selection],
)
```

## 정리

- 모델, 도구, 시스템 프롬프트처럼 **모델 호출에 들어가는 요청 자체를 바꾸는 작업**은 `@wrap_model_call`
- state의 메시지를 정리하거나 값을 갱신하는 작업은 `@before_model`

`request.override(...)` 같은 메서드 이름과 `request.state` 접근 방식은 langchain 버전에 따라 다를 수 있으니, 설치된 버전의 문서를 확인해 보세요.
