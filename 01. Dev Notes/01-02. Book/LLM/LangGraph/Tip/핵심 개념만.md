- 에이전트
에이전트는 LLM과 Tool을 결합하여 복잡한 작업을 수행하는 시스템이다. 에이전트는 주어진 작업에 대해 추론하고, 필요한 도구를 선택하며, 목표를 향해 반복적으로 작업을 수행한다.

- StateGraph
LangGraph의 핵심 클래스로, 상태 기반 워크플로우로 정의한다. State 타입을 매개변수로 받아 그래프를 생성하고, add_node(), add_edge() 메서드로 노드와 에지를 추가한후 compile()로 실행 가능한 형태로 변환한다.

- 상태
그래프를 정의할때 그래프의 상태를 정의한다. 상태는 그래프 전체에서 공유되는 데이터 구조로, 노드들이 이 상태를 읽고 업데이트하며 협업한다.
	- 두가지 요소: 스키마, 리듀서 함수

- 노드
노드는 그래프의 실제 작업을 수행하는 파이썬 함수이다. 각 노드는 현재 상태를 입력으로 받아 처리를 수행하고, 상태 업데이트를 딕셔너리로 반환한다.
	- 노드함수의 인자
	1) state: 그래프의 현재 상태
	2) config: 실행 구성 정보를 포함하는 RunnableConfig 객체
	3) runtime: 런타임 컨텍스트 정보

- 에지
에지는 노드 간의 실행 흐름을 정의한다. 어떤 노드에서 어떤 노드로 이동할지를 결정하는 역할을 한다.
	- 에지의 유형
	1) 일반 에지: add_edge()
	2) 조건부 에지: add_conditional_edges()

- Send
Send는 동적으로 여러 노드 인스턴스를 병렬로 생성하여 실행하는 기능이다. 입력 데이터의 각 항목에 대해 독립적인 처리를 수행할 수 있다. 여러 노드에게 각각 다른 업무를 동시에 배분하고, 모든 결과를 모아서 취합하는 것과 같다.
조건부 에지 함수에서 Send 객체의 리스트를 반환하면, 각 Send가 지정한 노드가 해당 상태로 병렬 실행된다.

- Command
Command는 상태 업데이트와 제어 흐름을 하나의 반환 값으로 결합한다. 하나의 명령으로 이 데이터를 갱신하고 다음으로 이 노드를 실행하라고 지시하는 것이다.

- 재귀 제한
재귀 제한은 단일 실행에서 그래프가 실행할 수 있는 최대 슈퍼 스텝, 즉 노드 실행수를 제한한다.
그래프가 끝없이 실행되는 무한 루프를 방지하고 실행 시간을 제어하는 안전 장치 역할을 한다.

- 런타임
런타임은 에이전트 실행 중 필요한 정보를 도구와 미들웨어에 전달하는 실행 환경이다.
런타임 정보는 도구와 미들웨어 내에서 runtime 매개변수를 통해 접근할 수 있다.

- HITL
에이전트가 특정 작업을 수행하기 전에 반드시 사람의 승인을 받도록 하는 메커니즘이다.
	(1) HITL 미들웨어 흐름
		1) 모델이 도구 호출을 생성한다.
		2) 미들웨어가 도구 호출을 검사한다.
		3) 사람의 승인이 필요한 경우 인터럽트가 발생한다.
		4) 그래프 상태가 저장되고 실행이 일시 중지된다.
		5) 사람의 결정을 받아 실행이 재개된다.
	(2) HITL 미들웨어 사용법
		`1)` HumanTheLoopMiddleware
		`2)` interrupt_on: 어떤 도구가 승인을 필요로 하는지 지정(approve, edit, reject)
		`3)` 체크포인터: 상태를 저장하고 복원

- 미들웨어
미들웨어는 에이전트의 <mark style="background:#fff88f">모델 호출과 도구 실행 흐름 사이</mark>에 끼어들어 모니터링, 수정, 제어, 강제 등 다양한 역할을 수행한다. 이는 에이전트 실행의 모든 단계를 제어하고 커스터마이징하는 강력한 방법을 제공한다.
미들웨어는 에이전트 실행의 각 단계에서 순차적으로 실행되며, 요청과 응답을 가로채어 수정하거나 로깅을 할 수 있다.
미들웨어는 데이터가 흐르는 경로에 원하는 처리 로직을 삽입한다.
핵심 기능은 모니터링, 수정, 제어, 강제이다.

- 내장 미들웨어
	1) SummarizationMiddleware
	2) ModelCallLimitMiddleware
	3) ToolCallLimitMiddleware
	4) ModelFallbackMiddleware
	5) PIIMiddleware
	6) ToolRetryMiddleware

- 컨텍스트 엔지니어링
컨텍스트 엔지니어링은 에이전트가 작업에 필요한 정보와 도구를 적절한 방식으로 활용하도록 설계하는 방법이다. 에이전트의 동작을 세밀하게 조정하는 데 사용한다.

- 컨텍스트의 종류
	1) 모델 컨텍스트
	모델 호출에 들어가는 내용을 제어한다. 상태에 저장된 내용을 변경하지 않고 메시지, 도구 또는 프롬프트를 수정할 수 있다. 따라서 단일 호출에서만 유지되는 일시적 컨텍스트이다.
		1 시스템 프롬프트
		@dynamic_promp를 사용하면 런타임에 시스템 프롬프트를 동적으로 생성할 수 있다.
			상태 기반 시스템 프롬프트
			Store 기반 시스템 프롬프트
			런타임 컨텍스트 기반 시스템 프롬프트
		2 메시지
		@wrap_model_call를 사용하면 모델에 전달되는 메시지를 동적으로 수정할 수 있다.
		3 도구
		도구를 통해 모델이 데이터베이스, API, 외부 시스템과 상호 작용할 수 있다.
			상태 기반 도구 선택하기
			런타임 컨텍스트 기반 도구 선택하기
		4 모델
		@wrap_model_call를 사용하면 런타임에 모델을 변경할 수 있다.
	2) 도구 컨텍스트
	도구가 액세스하고 생성하고 내용을 제어한다. 영구적 컨텍스트이다.
	ToolRunTime 객체를 통해 상태, Store, 런타임 컨텍스트에 접근할 수 있으며, Command 객체를 반환하여 상태를 업데이트할 수 있다.
	3) 라이프사이클 컨텍스트
	모델 및 도구 호출 사이에 발생하는 작업을 제어한다. 영구적 컨텍스트이다.

- 가드레일
가드레일은 에이전트 실행 줄 주요 지점에 콘텐츠를 검증하고 필터링하려 안전하고 규정을 준수하는 AI 애플리케이션을 구축할 수 있도록 도와주는 보호 장치이다.

- 메모리
메모리는 에이전트가 이전 대화의 흐름을 이어가고, 같은 사용자와의 상호작용을 일관되게 유지하도록 돕는 기반이다. LangGraph에서는 체크포인터와 thread_id를 통해 실행 상태를 저장하고 불러오며, 대화가 길어질 때는 메시지를 정리하거나 요약해 필요한 맥락만 유지할 수 있다.
	- 체크 포인터: 그래프의 각 실행 단계의 상태가 저장하여 이후 동일한 대화를 이어서 진행할 수 있게 하는 컴포넌트이다.
	- thread_id: 대화 세션을 서로 독립적으로 관리할 수 있다.
