
## 한 번의 invoke 안에서의 실행 순서

도구 호출이 한 번 있는 경우를 기준으로 하면 이렇습니다.

```
1. @before_agent          ← 시작 시 1회
   ┌─ 루프 1 (모델이 도구 호출을 결정) ────────────────────┐
2. │ @before_model                                  │
3. │ @wrap_model_call  진입 → 모델 호출 → 종료           │
4. │ @after_model                                   │
5. │ (tools 노드: 도구 실행)                           │
   └────────────────────────────────────────────────┘
   ┌─ 루프 2 (모델이 최종 답변 생성) ─────────────────────┐
6. │ @before_model                                  │
7. │ @wrap_model_call  진입 → 모델 호출 → 종료           │
8. │ @after_model                                   │
   └────────────────────────────────────────────────┘
9. @after_agent           ← 종료 시 1회
```

| 순서  | 데코레이터              | 실행 횟수           |
| --- | ------------------ | --------------- |
| 1   | `@before_agent`    | invoke당 1회      |
| 2   | `@before_model`    | 모델 호출 전, 루프마다   |
| 3   | `@wrap_model_call` | 모델 호출을 감쌈, 루프마다 |
| 4   | `@after_model`     | 모델 호출 후, 루프마다   |
| 5   | `@after_agent`     | invoke당 1회      |

- 도구 호출이 없으면 루프는 1번만 돕니다.
- `@wrap_model_call`의 재시도는 `wrap` 내부에서 `handler`를 여러 번 부르는 것이라, 재시도가 일어나도 `before_model`/`after_model`은 루프당 1번만 실행됩니다.

## 미들웨어가 여러 개일 때

`middleware=[A, B]`라면:

|종류|순서|
|---|---|
|`before_agent`, `before_model`|A → B (리스트 순서)|
|`wrap_model_call`|A가 바깥, B가 안쪽 (A가 B를 감쌈)|
|`after_model`, `after_agent`|B → A (역순)|

## 순서 확인용 코드

```python
from langchain.agents import create_agent
from langchain.agents.middleware import (
    before_agent, before_model, after_model, after_agent, wrap_model_call,
)

@before_agent
def ba(state, runtime):
    print("1. before_agent")

@before_model
def bm(state, runtime):
    print("2. before_model")

@wrap_model_call
def wm(request, handler):
    print("3. wrap_model_call 진입")
    response = handler(request)
    print("3. wrap_model_call 종료")
    return response

@after_model
def am(state, runtime):
    print("4. after_model")

@after_agent
def aa(state, runtime):
    print("5. after_agent")

agent = create_agent(
    model="openai:gpt-4.1",
    tools=[get_weather],
    middleware=[ba, bm, wm, am, aa],
)

agent.invoke({"messages": [{"role": "user", "content": "서울 날씨 알려줘"}]})
```

예상 출력(도구 호출 1회):

```
1. before_agent
2. before_model
3. wrap_model_call 진입
4. wrap_model_call 종료
5. after_model
(도구 실행)
6. before_model
7. wrap_model_call 진입
8. wrap_model_call 종료
9. after_model
10. after_agent
```

리스트에 넣는 순서와 상관없이 실행 시점은 데코레이터 종류가 결정하고, 같은 종류끼리만 리스트 순서가 영향을 줍니다. 세부 동작은 설치된 langchain 버전에 따라 조금 다를 수 있습니다.

---

LangChain v1의 `langchain.agents.middleware` 데코레이터들입니다. 각각 에이전트 루프의 어느 지점에 끼어드는지가 다릅니다.

```
@before_agent → [ @before_model → @wrap_model_call(모델 호출) → @after_model → (도구 실행) ]  반복 → @after_agent
```

```python
from langchain.agents import create_agent
from langchain.agents.middleware import (
    before_agent, before_model, after_model, after_agent, wrap_model_call,
    AgentState, ModelRequest, ModelResponse,
)
from langgraph.runtime import Runtime
from typing import Callable, Any


# 1) 에이전트 시작 전 (invoke당 1회)
@before_agent
def on_agent_start(state: AgentState, runtime: Runtime) -> dict[str, Any] | None:
    print("[before_agent] 에이전트 시작, 메시지 수:", len(state["messages"]))
    return None  # dict를 반환하면 state가 업데이트됨


# 2) 모델 호출 전 (루프마다 매번)
@before_model
def on_model_start(state: AgentState, runtime: Runtime) -> dict[str, Any] | None:
    print("[before_model] 모델 호출 직전")
    return None


# 3) 모델 호출 후 (루프마다 매번)
@after_model
def on_model_end(state: AgentState, runtime: Runtime) -> dict[str, Any] | None:
    last = state["messages"][-1]
    print("[after_model] 모델 응답:", last.content[:50])
    return None


# 4) 에이전트 종료 후 (invoke당 1회)
@after_agent
def on_agent_end(state: AgentState, runtime: Runtime) -> dict[str, Any] | None:
    print("[after_agent] 에이전트 종료")
    return None


# 5) 모델 호출 감싸기: 재시도 로직
@wrap_model_call
def retry_model(
    request: ModelRequest,
    handler: Callable[[ModelRequest], ModelResponse],
) -> ModelResponse:
    max_retries = 3
    for attempt in range(max_retries):
        try:
            return handler(request)  # 실제 모델 호출
        except Exception as e:
            print(f"[wrap_model_call] 시도 {attempt + 1} 실패: {e}")
            if attempt == max_retries - 1:
                raise


agent = create_agent(
    model="openai:gpt-4.1",
    tools=[...],
    middleware=[
        on_agent_start,
        on_model_start,
        on_model_end,
        on_agent_end,
        retry_model,
    ],
)
```

**차이점 정리**

|데코레이터|실행 시점|횟수|주 용도|
|---|---|---|---|
|`@before_agent`|에이전트 시작|1회|입력 검증, 사용자 정보 로드|
|`@before_model`|모델 호출 직전|루프마다|메시지 트리밍, 요약, 프롬프트 가공|
|`@after_model`|모델 응답 직후|루프마다|출력 검증, 가드레일, 사람 승인|
|`@after_agent`|에이전트 종료|1회|결과 저장, 정리 작업|
|`@wrap_model_call`|모델 호출 자체를 감쌈|루프마다|재시도, 폴백 모델, 요청/응답 수정|

**참고**

- `before_*`/`after_*`는 state를 읽고 `dict`를 반환해 업데이트하는 "훅" 방식이고, `wrap_*`는 `handler`를 직접 호출하는 "감싸기" 방식이라 호출 자체를 제어할 수 있습니다(재시도, 캐싱, 모델 교체 등).
- 훅에서 `{"jump_to": "end"}` 같은 값을 반환해 흐름을 건너뛰게 할 수도 있는데, 이 경우 `@before_model(can_jump_to=["end"])`처럼 허용할 이동 대상을 선언해야 합니다.
- 재시도만 필요하다면 직접 짜지 않고 내장 `ModelRetryMiddleware`를 쓰는 편이 간단합니다. 다만 버전에 따라 이름과 시그니처가 다를 수 있으니 설치된 버전의 문서를 확인해 보세요.
- 위 임포트 경로(`langgraph.runtime.Runtime` 등)도 버전에 따라 조금씩 달라질 수 있습니다.
