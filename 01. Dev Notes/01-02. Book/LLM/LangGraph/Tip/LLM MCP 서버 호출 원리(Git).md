
핵심은 **LLM이 "Git 명령을 직접 실행"하는 게 아니라, "도구를 호출해 달라는 구조화된 요청"을 텍스트로 출력하고, MCP 클라이언트가 그 요청을 실제 MCP 서버로 전달해 실행하는 구조**라는 점입니다.

## 1. 구성 요소와 역할

|구성 요소|역할|
|---|---|
|**사용자**|"변경사항 커밋해줘" 같은 자연어 지시|
|**LLM**|어떤 도구를 어떤 인자로 호출할지 _결정_만 함 (실행 안 함)|
|**MCP 클라이언트(호스트 앱)**|LLM과 MCP 서버 사이의 중개자. 도구 목록 수집, 호출 전달, 결과 반환|
|**MCP 서버(Git)**|`git_status`, `git_diff`, `git_commit` 같은 도구를 노출하고 실제 git을 실행|

## 2. 동작 순서

**① 연결과 도구 발견 (초기화)**  
클라이언트가 MCP 서버를 실행(stdio) 또는 접속(HTTP)하고 JSON-RPC로 핸드셰이크를 합니다. 이어서 `tools/list`를 호출하면 서버가 자신이 제공하는 도구를 이름, 설명, 입력 스키마(JSON Schema)와 함께 알려줍니다.

```json
{
  "name": "git_commit",
  "description": "Records changes to the repository",
  "inputSchema": {
    "type": "object",
    "properties": {
      "repo_path": {"type": "string"},
      "message": {"type": "string"}
    },
    "required": ["repo_path", "message"]
  }
}
```

**② 도구 정보를 LLM에 전달**  
클라이언트는 이 도구 목록을 LLM API 호출 시 `tools` 파라미터(또는 프롬프트)에 포함시킵니다. 이 시점부터 LLM은 "내가 쓸 수 있는 도구가 무엇이고, 각각 어떤 인자를 받는지" 알게 됩니다.

**③ LLM의 판단 (tool use)**  
사용자가 "현재 변경사항 확인하고 커밋해줘"라고 하면, LLM은 도구 설명과 스키마를 보고 추론합니다. 그리고 일반 답변 대신 다음과 같은 구조화된 출력을 냅니다.

```json
{"type": "tool_use", "name": "git_status", "input": {"repo_path": "/home/me/project"}}
```

이것은 모델이 도구 호출 형식으로 출력하도록 학습(파인튜닝)되어 있기 때문에 가능합니다. 어떤 도구를 쓸지는 도구의 **description과 스키마가 자연어 단서** 역할을 해서 정해집니다.

**④ 클라이언트가 MCP 서버에 실행 요청**  
클라이언트는 이 출력을 파싱해서 MCP의 `tools/call` 요청으로 바꿔 서버에 보냅니다. (보통 이 단계에서 사용자 승인 팝업을 띄웁니다.)

**⑤ MCP 서버가 실제 Git 실행**  
Git MCP 서버가 `git status`를 실제로 실행(또는 GitPython 등 라이브러리 사용)하고 결과를 반환합니다.

**⑥ 결과를 LLM에 되돌려 반복**  
클라이언트는 결과를 `tool_result`로 LLM에 다시 넣습니다. LLM은 그 결과를 보고 다음 행동(`git_diff` → `git_add` → `git_commit`)을 또 결정합니다. 더 이상 호출할 도구가 없으면 사용자에게 최종 답변을 합니다.

## 3. 흐름 요약

```
사용자 ─ "커밋해줘" ─▶ 클라이언트 ─(질문 + 도구목록)─▶ LLM
                                                    │
                          tool_use: git_status ◀────┘
클라이언트 ─ tools/call ─▶ Git MCP 서버 ─ git 실행
클라이언트 ◀─ 결과 ────────┘
클라이언트 ─(tool_result)─▶ LLM ─ 다음 도구 호출 or 최종 답변 ─▶ 사용자
```

## 4. 핵심 원리 정리

- **자동으로 연동되는 것처럼 보이는 이유**: 도구 목록이 LLM 컨텍스트에 들어가 있고, LLM이 상황에 맞는 도구를 골라 호출 형식으로 출력하며, 클라이언트가 그 루프(에이전트 루프)를 자동으로 돌려주기 때문입니다.
- **MCP의 역할**: 도구 발견·호출·결과 반환의 _표준 프로토콜_입니다. 덕분에 Git 서버 하나만 만들면 Claude Desktop, Cursor, VS Code 등 어떤 MCP 클라이언트에서도 똑같이 쓸 수 있습니다.
- **보안**: LLM은 직접 시스템에 접근하지 못하고 서버가 노출한 도구만 쓸 수 있습니다. 또한 클라이언트가 호출 전 승인을 요구하거나, 서버가 접근 가능한 저장소 경로를 제한할 수 있습니다.

원하시면 직접 간단한 Git MCP 서버를 만드는 코드 예시(Python)도 보여드릴 수 있습니다.
