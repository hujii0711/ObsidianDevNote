
model = init_chat_model("claude")

agent = create_agent(
	model,
	system_prompt,
	tools =`[]`,
	context_schema,
	middleware,
	response_format
)
1) context_schema
context_schema 정의시 에이전트 호출 시 필요한 컨텍스트 정보를 전달할 수 있다.
에이전트 런타임에 저장될 컨텍스트의 구조를 정의할 수 있다. 컨텍스트를 dataclass 또는 Pydantic 모델로 정의하며, 에이전트를 호출할 때 context 매개변수로 전달한다. 이는 마치 함수에 설정 객체를 주입하는 의존성 주입 패턴과 유사하다.

2) response_format
response_format로 구조화된 출력을 설정하며, 결과는 에이전트 상태의 structured_reponse 키에 반환된다. 즉, 에이전트가 구조화된 데이터를 반환하는 방식을 정의한 것이다.
	- 조화된 출력 설정 방식
		1) ProviderStrategy: Langchain이 지원 모델에 대해 자동적으로 사용한다.
			Pydantic 모델, 데이터 클래스, TypeDict
		2) ToolStrategy: 지원되지 않는 모델의 경우 자동으로 이쪽으로 폴백된다.
			Pydantic 모델, Union 타입, tool_message_content
		3) 자동 선택

- @dynamic_prompt
시스템 프롬프트를 동적으로 생성해야하는 경우 사용한다. 동적 시스템 프롬프트를 활용하면 하나의 에이전트로도 다양한 응답 형식을 지원할 수 있다.

- 데코레이터 기반 미들웨어
각 데코레이터는 에이전트 실행의 특정 단계에서 동작하며, 함수 하나만 정의하면 바로 미들웨어에서 사용할 수 있다.
	- @before_model
	모델 호출 전 미들웨어에서 runtime을 통해 컨텍스트에 접근할 수 있다.
	
	- @after_model
	모델 호출 후 미들웨어에서 runtime을 통해 컨텍스트에 접근할 수 있다.
	HITL 미들웨어는 모델이 응답을 생성한 후 도구 호출이 실행되기 전에 동작하는 after_model 훅을 정의
	한다. after_model 훅은 모델 호출과 도구 실행 사이에 위치하므로, 도구가 실제로 실행되기 전에 사람
	의 개입이 이루어진다.
	
	- @before_agent
	에이전트 실행 전 커스텀 가드레일을 사용할 수 있다.
	
	- @after_agent
	에이전트 실행 후 커스텀 가드레일을 사용할 수 있다.
	
	- @wrap_model_call
	 wrap 스타일 훅은 실행을 가로채고 핸들러가 호출되는 시기를 완전히 제어하여 실행 자체를 감싸서 전체 흐
	 름을 제어한다.
	모델 호출 전에 요청을 검사하고 수정할 수 있는 미들웨어를 생성할 수 있다.
	
	- @wrap_tool_call

- ModelRequest
에이전트의 모델 호출 정보를 담은 요청 객체로, 미들웨어에서 요청을 검사하고 수정할 때 사용된다.

- request.override()(request: ModelRequest)
모델, 시스템 메시지, 도구 선택을 변경할 수 있다.

- 도구에서 런타임 접근하기
	- ToolRunTime
		ex. `func(runtime: ToolRunTime[UserContext])
		도구(@tool 함수) 안에서 ToolRunTime 매개변수를 사용하면 Runtime 객체(UserContext 데이터 클래스)에 접근할 수 있다.
		
		store 접근: runtime.store
		stream_writer: runtime.stream_writer

- 미들웨어에서 런타임 접근하기
	- @dynamic_prompt 
		ex. @dynamic_prompt def a(request: ModelRequest)
		@dynamic_prompt 데코레이터로 정의된 미들웨어에서 request.runtime을 통해 컨텍스트에 접근할 수 있다. 이를 활용하면 사용자별로 다른 시스템 프롬프트를 동적으로 생성할 수 있다.
	- @before_model
	- @after_model
