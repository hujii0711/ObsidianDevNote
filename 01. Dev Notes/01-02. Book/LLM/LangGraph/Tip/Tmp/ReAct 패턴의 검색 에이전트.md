### ReAct란

**Re**asoning(생각) + **Act**ing(행동)을 합친 말입니다. LLM이 한 번에 답을 내지 않고, 아래 과정을 되풀이합니다.

1. **생각**: "이 질문에 답하려면 최신 정보가 필요하다"
2. **행동**: 도구를 호출합니다. 예: `tavily_tool(query="2026 AI 반도체 시장")`
3. **관찰**: 도구가 돌려준 결과(검색 결과)를 읽습니다.
4. 정보가 충분하면 최종 답을 쓰고 끝냅니다. 모자라면 다른 검색어로 1번부터 다시 합니다.

### `create_agent`가 만드는 것

`create_agent`는 이 반복을 LangGraph 그래프로 만들어 줍니다. 노드는 두 개입니다.

```
START → [model] ──도구 호출 있음──→ [tools] ─┐
           ↑                                │
           └────────────────────────────────┘
           │
           └──도구 호출 없음──→ END
```

- `model` 노드: LLM이 메시지를 보고 도구를 부를지, 바로 답할지 정합니다.
- `tools` 노드: LLM이 요청한 도구(`tavily_tool`)를 실행하고, 결과를 `ToolMessage`로 대화에 붙입니다.
- LLM 응답에 도구 호출(`tool_calls`)이 없으면 끝납니다.

반복을 직접 짜지 않아도 되는 것이 장점입니다.

### 메시지 흐름 예시

```
HumanMessage : "최근 AI 반도체 동향 알려줘"
AIMessage    : tool_calls=[tavily_tool("AI 반도체 동향 2026")]   ← 생각+행동
ToolMessage  : [검색 결과 5건 ...]                               ← 관찰
AIMessage    : "최근 동향은 ... 입니다."                          ← 최종 답 (도구 호출 없음 → 종료)
```

### 그래프 노드로 감싸는 이유

[ex04.py:74](edu/ch13/ex04.py#L74)의 `create_agent_node`는 이 에이전트를 더 큰 팀 그래프의 **노드 하나**로 바꿉니다.

- 에이전트 내부의 여러 메시지(도구 호출, 검색 결과)는 버리고 **마지막 답만** 꺼냅니다(`result["messages"][-1]`).
- 그 답을 `HumanMessage(name="Searcher")`로 바꿔 돌려줍니다. 그래서 상위 supervisor는 "Searcher가 이렇게 보고했다"로만 봅니다. 검색 과정의 잡다한 메시지가 팀 전체 대화를 채우지 않습니다.

정리하면, 검색 에이전트는 **스스로 판단해 필요한 만큼 검색하고 그 결과를 정리해 보고하는 작은 일꾼**입니다. ch13의 계층형 팀에서는 Research Team의 일원입니다.

참고로 이 프로젝트의 4bit Qwen 같은 로컬 모델은 도구 호출 형식을 가끔 틀립니다. 그러면 검색 없이 바로 답하거나 같은 검색을 반복할 수 있습니다.
