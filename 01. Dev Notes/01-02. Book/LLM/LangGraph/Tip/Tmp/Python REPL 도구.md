
## Python REPL 도구는 무엇을 하나

[ex03.py](edu/ch13/ex03.py)의 `PythonREPLTool`은 **LLM이 만든 Python 코드를 실제로 실행하고 결과를 돌려주는 도구**입니다. REPL은 Read-Eval-Print Loop의 줄임말로, 코드를 읽어 실행하고 결과를 보여 주는 대화형 실행기를 말합니다.

### 왜 필요한가

LLM은 글을 만들 뿐 계산이나 파일 생성을 직접 하지 못합니다. 이 도구가 있으면 에이전트는 이렇게 일합니다.

1. LLM이 "이 작업에는 코드가 필요하다"고 판단하고 코드를 씁니다. 예: `import matplotlib; plt.bar(...); plt.savefig("chart.png")`
2. 그 코드를 `python_repl_tool`에 문자열로 넘깁니다.
3. 도구가 코드를 실행하고 **stdout에 찍힌 내용(`print` 결과)이나 에러 메시지**를 돌려줍니다.
4. LLM은 그 결과를 보고 답을 마무리합니다. 에러가 났다면 코드를 고쳐 다시 실행합니다.

결과는 `print`로 출력한 내용만 돌아옵니다. 그래서 LLM이 값을 확인하려면 코드에 `print(...)`를 넣어야 합니다.

### 이 챕터에서 맡은 역할

ch13은 여러 팀이 협업하는 계층형 에이전트 예제입니다. 이 도구는 [ex08.py:108](edu/ch13/ex08.py#L108)에서 **차트 생성 에이전트**에 들어갑니다.

```python
chart_generating_agent = create_agent(llm, tools=[read_document, python_repl_tool])
```

이 에이전트는 두 도구를 함께 씁니다.
- `read_document`(ex02): 저장된 문서에서 데이터를 읽습니다.
- `python_repl_tool`: 읽은 데이터로 matplotlib 차트를 그리거나 표를 계산·가공합니다.

정리하면 리서치 팀은 정보를 찾고, 문서 팀은 글을 쓰고, Python REPL은 **계산과 시각화**를 맡습니다.

### 주의할 점

- **보안**: LLM이 쓴 코드를 아무 제한 없이 실행합니다. 파일 삭제나 네트워크 접근도 막지 않고, 현재 프로세스와 같은 권한으로 돕니다. `langchain_experimental` 패키지에 들어 있는 것도 이 위험 때문입니다. 학습용으로는 괜찮지만 실제 서비스에서는 Docker 같은 샌드박스에서 실행해야 합니다.
- **상태 유지**: 같은 도구 인스턴스 안에서는 앞서 실행한 코드의 변수가 다음 실행에도 남아 있습니다. 그래서 여러 번 나눠 실행해도 이어서 작업할 수 있습니다.
- **로컬 LLM과의 궁합**: 이 프로젝트의 4bit Qwen처럼 작은 모델은 긴 코드를 도구 인자로 넘기다가 형식을 깨뜨릴 수 있습니다. 차트 단계에서 실패가 잦다면 이 부분부터 의심해 보면 됩니다.
