
네 가지 용어는 **작업(또는 데이터)의 제어권이 이동하는 방식**과 **병렬 처리 흐름의 방향**을 나타내는 개념으로, 소프트웨어 아키텍처, 분산 시스템, 그리고 최근에는 **멀티 에이전트(Multi-Agent) 워크플로우** 설계에서 핵심적으로 쓰입니다.


|**용어**|**영어 표기**|**흐름 방향**|**핵심 개념**|**주요 활용 맥락**|
|---|---|---|---|---|
|**핸드오프**|Handoff|$1 \rightarrow 1$ (이양)|작업의 주도권과 상태를 다른 주체에게 완전히 넘김|멀티 에이전트 라우팅, 네트워크 로밍, 업무 인계|
|**핸드인**|Hand-in|$1 \rightarrow 1$ (제출/반환)|위임받거나 수행한 작업의 결과물을 상위·원래 주체에게 돌려줌|서브에이전트 결과 보고, 과제·산출물 제출|
|**팬아웃**|Fan-out|$1 \rightarrow N$ (분산)|하나의 입력·요청을 여러 하위 작업이나 워커로 동시에 복제·분배|병렬 처리, 이벤트 브로드캐스트, 동시 에이전트 호출|
|**팬인**|Fan-in|$N \rightarrow 1$ (취합)|병렬로 처리된 여러 결과를 하나로 모아서 집계·병합|MapReduce, 결과 요약(Synthesizer), 배치(Batch) 적재|

### 1. 핸드오프 (Handoff) — "이제 네가 맡아서 진행해"

현재 작업을 처리하던 주체가 **실행 제어권(Control)과 문맥(Context)을 다른 주체에게 넘겨주는 것**입니다.
넘겨준 주체는 해당 작업의 전면에서 물러나고, 넘겨받은 주체가 새로운 담당자가 됩니다.

- **멀티 에이전트 시스템:** 고객 상담 봇(Triage Agent)이 문의를 분류한 뒤, 환불 전담 에이전트(Refund Agent)에게 대화 제어권을 완전히 넘기는 방식입니다. (OpenAI Agents SDK, LangGraph 등의 핵심 패턴)
- **네트워크/통신:** 이동 중인 스마트폰이 기존 기지국에서 다음 기지국으로 통신 연결을 끊김 없이 넘기는 기술(Handover와 유사)을 말합니다.

### 2. 핸드인 (Hand-in) — "요청하신 작업 끝냈습니다, 여기 결과물입니다"

원래 영어에서 과제나 보고서를 '제출하다'라는 뜻에서 유래했으며, 시스템 흐름에서는 **위임받은 하위 작업(Sub-task)을 마친 뒤 결과물과 제어권을 호출자(Parent)에게 반환하는 동작**을 의미합니다.

- **핸드오프와의 차이:** 핸드오프가 **수평적·연속적인 바통 터치**($A \rightarrow B \rightarrow C$)에 가깝다면, 핸드인은 **계층적 위임 후 복귀**($A \rightarrow B \rightarrow A$)의 마무리 단계에 초점을 맞춥니다. 오케스트레이터(관리자)가 서브에이전트에게 조사를 시킨 뒤, 서브에이전트가 결과를 정리해 오케스트레이터에게 다시 넘겨주는 과정이 여기에 해당합니다.

### 3. 팬아웃 (Fan-out) — "한 번에 여러 곳으로 뿌리기"

부채(Fan)가 펼쳐지는 모양처럼, **하나의 트리거(요청/데이터)가 여러 경로 또는 여러 워커(Worker)로 동시에 분기되는 구조**입니다. 처리 속도를 높이기 위한 병렬화(Parallelism)의 시작점입니다.

- **분산 시스템/메시징:** 하나의 이벤트를 메시지 브로커(SNS, Kafka 등)에 발행하면, 알림 서비스·로그 적재·결제 정산 워커가 동시에 각자의 처리를 시작하는 패턴입니다.

- **AI 워크플로우:** 사용자의 리서치 주제를 받자마자 `웹 검색 에이전트`, `논문 검색 에이전트`, `뉴스 검색 에이전트` 3개를 동시에 병렬 실행하는 단계입니다.

### 4. 팬인 (Fan-in) — "흩어진 결과를 하나로 모으기"

팬아웃과 짝을 이루는 개념으로, **여러 경로에서 병렬로 처리된 출력물들을 단일 지점으로 모아 결합·정제하는 구조**입니다.

- **데이터 파이프라인:** 여러 마이크로서비스에서 쏟아지는 로그를 단일 데이터 웨어하우스(BigQuery, Elasticsearch 등)로 수집하거나, 분할 처리된 데이터를 하나로 합치는 과정입니다.

- **AI 워크플로우:** 팬아웃으로 동시에 실행했던 3개 검색 에이전트의 결과물이 모두 도착할 때까지 기다린 뒤, 최종 요약 에이전트(Aggregator/Synthesizer)가 이를 취합해 하나의 답변으로 작성하는 단계입니다.

### 한눈에 보는 조합 패턴

실제 아키텍처에서는 이 개념들이 단독으로 쓰이기보다 조합되어 파이프라인을 이룹니다.

- **순차 위임형 (Handoff 체인):** `접수 에이전트` $\xrightarrow{\text{Handoff}}$ `기술지원 에이전트` $\xrightarrow{\text{Handoff}}$ `결제 에이전트`

- **병렬 분산-취합형 (Fan-out / Fan-in):** `메인 요청` $\xrightarrow{\text{Fan-out}}$ `[워커 A, 워커 B, 워커 C 동시 실행]` $\xrightarrow{\text{Fan-in}}$ `최종 결과 병합`
