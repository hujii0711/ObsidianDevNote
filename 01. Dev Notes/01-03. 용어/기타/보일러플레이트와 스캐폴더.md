개발 프로젝트를 시작하거나 초기 설정을 할 때 자주 접하는 보일러플레이트(Boilerplate)와 스캐폴딩(Scaffolding / Scaffolder)은 둘 다 "반복적인 초기 작업을 줄여준다"는 목적을 가집니다.

하지만 두 개념의 핵심적인 차이는 **"이미 완성된 틀을 복사해 쓰느냐(정적)"**, 아니면 "사용자 요구에 맞춰 도구를 통해 동적으로 생성하느냐(동적)"에 있습니다.

그 차이점을 핵심 위주로 명확하게 정리해 드리겠습니다.

## 1. 핵심 차이점 요약

|**구분**|**보일러플레이트 (Boilerplate)**|**스캐폴더 (Scaffolder / Scaffolding)**|
|---|---|---|
|**개념**|변경 없이 반복적으로 재사용되는 **코드 조각이나 프로젝트 템플릿**|프로젝트 구조나 코드를 자동으로 만들어주는 **생성 도구(Tool/CLI)**|
|**작동 방식**|준비된 레포지토리를 **Clone(복사)**하거나 파일 붙여넣기|명령어(CLI)나 UI를 통해 설정을 입력받아 **동적 생성**|
|**유연성**|**낮음** (제공된 구조를 그대로 사용, 불필요한 코드도 포함됨)|**높음** (옵션 선택에 따라 필요한 파일만 맞춤형으로 생성)|
|**제공 형태**|GitHub 스타터 킷, 프로젝트 템플릿 디렉터리|`CRA`, `Vite`, `Yeoman`, Backstage Scaffolder 등|

## 2. 보일러플레이트 (Boilerplate)

> **"이미 구워져 나온 벽돌 (복사 + 붙여넣기)"**

보일러플레이트는 기술 스택, 폴더 구조, 빌드 설정(Webpack, Vite 등), Lint 설정(ESLint, Prettier), 기본 라이브러리(Redux, Tailwind 등)가 **이미 다 세팅되어 있는 완성된 프로젝트 판형**입니다.

- **특징:** 누군가 미리 만들어둔 GitHub 저장소를 `git clone`하여 그대로 시작하는 경우가 많습니다.
    
- **장점:** 환경 설정에 시간을 낭비하지 않고 바로 비즈니스 로직 개발에 들어갈 수 있습니다.
    
- **단점:** 내 프로젝트에 필요 없는 라이브러리나 코드가 포함되어 있을 수 있어서, 필요 없는 부분을 직접 지우는 ‘청소 작업’이 필요할 수 있습니다.
    
- **대표적인 예:** * GitHub에 있는 수많은 `nextjs-tailwind-typescript-starter` 레포지토리
    
    - 법률 문서나 계약서에서 이름만 바꿔 쓰는 표준 문구
        

## 3. 스캐폴더 (Scaffolder)

> **"건축 현장의 거푸집/비계 (주문에 맞춘 자동 생성 도구)"**

스캐폴더는 정적인 파일 모음이 아니라, 코드를 생성해 주는 '프로그램(도구)'입니다. 개발자가 터미널이나 UI에서 몇 가지 옵션을 선택하면, 그 선택에 맞는 최적의 뼈대를 그 자리에서 조합하여 만들어줍니다.

- **특징:** 단순 초기 프로젝트 생성뿐만 아니라, 개발 도중에 새로운 컴포넌트, API 라우트, DB 마이그레이션 파일 등을 추가할 때도 명령어로 실행(`generate`)하여 사용할 수 있습니다.
    
- **장점:** 딱 필요한 옵션만 골라서 생성하므로 불필요한 코드가 없고, 사내 표준이나 구조를 강제하기 좋습니다.
    
- **단점:** 스캐폴딩 도구(CLI) 자체를 다루는 방법을 익혀야 하며, 기업 맞춤형 스캐폴더를 만들려면 별도의 도구 개발 공수가 듭니다.
    
- **대표적인 예:**
    
    - `npm create vite@latest` (대화형으로 React, Vue, TS 등을 선택하여 생성)
        
    - `NestJS CLI` (`nest g co users` 명령어로 특정 폴더에 controller를 자동 생성하고 모듈에 자동 등록)
        
    - 플랫폼 엔지니어링에서 사용하는 `Backstage Software Templates (Scaffolder)` (사내 표준 마이크로서비스 뼈대 생성)
        

## 4. 비유로 이해하기

- **보일러플레이트:** 밀키트(Mealkit)입니다. 찌개에 필요한 모든 재료와 양념이 정량으로 포장되어 있어서, 가져다가 끓이기만 하면 됩니다. (안 먹는 야채가 있어도 일단 들어있음)
    
- **스캐폴더:** 서브웨이처럼 키오스크에서 재료를 하나씩 골라 담으면 그 자리에서 만들어주는 **커스텀 샌드위치 기계**입니다. "빵은 화이트로 해주고, 소스는 빼주세요" 하면 딱 그렇게만 만들어줍니다.
    

## 5. 두 개념의 결합

현대 개발 환경에서는 이 둘이 분리되어 쓰이기보다 "스캐폴더가 보일러플레이트를 주입해 주는 방식"으로 함께 작동합니다.

예를 들어 `create-next-app`이라는 **스캐폴더**를 실행하여 "TypeScript 쓸래? ESLint 쓸래?"라는 질문에 답변하면, 스캐폴더가 그 답변 조합에 맞는 최적의 **보일러플레이트 코드**를 내부적으로 조립하여 내 컴퓨터에 떨어뜨려 주는 구조입니다.

혹시 현재 준비 중이신 프로젝트 아키텍처나 사내 개발 프로세스 표준화(플랫폼 엔지니어링 등) 관점에서 스캐폴더 도입을 고민 중이신가요?
