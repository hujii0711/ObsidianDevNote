
- 분산 모델
  프로젝트에 참여하는 모든 클라이언트(개발자)가 전체 저장소에 대한 개별적인 로컬 저장소를 갖고 작업하는 형태이다. (클라이언트 각자가 온전한 전체 저장소의 사본을 갖는다.)
  이 모델은 서버뿐만 아니라 프로젝트에 참여하는 모든 컴퓨터 각각에 로컬 저장소가 있으므로 저장소와 하는 모든 상호작용이 로컬 저장소에도 반영될 수 있다.

- git merge시 충돌 해결
  충돌 난 두 브랜치 중 하나의 내용을 선택하거나, 두 수정 내역을 합치는 등 수동으로 충돌을 해결해야 한다.

- 포크: 다른 사람의 원격 저장소를 내 계정으로 복사하는 기능(현재 프로세스를 나눠서 새로운 프로세스를 만드는 행위) 만약 포크를 하지 않는다면 내 것이 아닌 저장소, 즉 쓰기 권한이 없는 원격 저장소를 사용하는 것이므로 자유롭게 파일을 수정하여 원격 저장소에 반영하는 것이 불가능해진다. 내 계정에 저장소를 복사해모녀 마음대로 이것저것 시도해볼 수 있다.

- 풀 리퀘스트: 포크한 저장소를 수정해 다시 원본 저장소에 병합해달라는 요청을 보내 사용자 사이의 상호 작용을 일으키게 하는 기능.
  풀 리퀘스트 전체 목록을 모아서 보여준다. Issues와 마찬가지로 목록마다 댓글 형태로 토론할 수 있다. 

- Issues: 저장소 안에서 사용자들 사이의 문제를 논의하는 기능

- Wiki: 공유할 정보나 개발 문서, 참고 자료 등을 작성하기 위한 기능이다. 마크다운이나 위키위키 문법을 사용한다.

- Watch: 해당 버튼을 클릭하면 원격 저장소의 활동 내역을 사용자에게 알려준다. 오른쪽 숫자는 현재 활동 내역을 보고 있는 사람의 수

- Star: 해당 원격 저장소에 관심이 있을 때 클릭한다. 오른쪽 숫자는 관심이 있는 사람의 수

- Releases: 원격 저장소의 태그 수를 나타낸다. 즉 특정 버전에 표식을 주고 싶을 때 사용한다. 이 표식을 통해서 특정 버전을 다운로드할 수 있다.

- Contributor: 원격 저장소에 커밋 혹은 풀 리퀘스트가 받아들여진 사용자 수이다. 이 저장소가 오픈 소스라면 이 오픈 소스에 공헌한 사람의 수라고 생각하면 된다.

- Issues: 해당 원격 저장소와 주요 이슈 사항을 기재한 후 관리한다. 게시판 형태이면 댓글 형태로 토론이 이뤄진다. 이슈로는 무엇이든 다룰 수 있지만, 보틍은 문제점이나 개선점을 이야기한다고 생각하면 된다.

- Pulse: 해당 원격 저장소의 최근 변경 내역을 확인할 수 있다. 최대 한달까지의 변경 내역을 확인할 수 있으며 풀 리퀘스트 몇 개중에 몇 개가 받아들여졌나, 이슈는 몇 개가 있고 몇 개가 해결되었나, 해당 풀 리퀘스트와 이슈에 관련된 활동을 볼 수 있다.

- clone: GitHub에서 로컬 환경으로 복사하는 작업을 클론이라고 하고, GitHub안에서 원격 저장소를 복사하는 작업을 포크라고 한다.

- origin: 원격 저장소의 별칭

- fetch: 로컬 저장소의 커밋들을 원격 저장소와 맞추는 작업. 페치는 원격 저장소의 커밋들을 로컬 저장소로 가져온다. 사용자는 로컬로 가져온 커밋들을 자신이 여태까지 한 로컬 저장소의 작업과 적절히 병합해서 원격 저장소에 제출해야 한다.
	git fetch: 원격 저장소의 모든 변경 내역을 로컬 저장소에 다운로드 한다.

- git pull: git fetch + git merge

- git tag: 커밋을 참조하기 쉽도록 알기 쉬운 이름을 붙인다. (저장소의 커밋에 태그를 붙인다.)

- git revert: 이전에 작성한 커밋을 지운다. 그런데 특정 커밋의 내용을 지우는 새로운 커밋을 만들어 지운 내역이 변경된다. 중요한 사실은 실제로 되돌리는 것이 아니라 되돌리는 것 같은 효과를 내는 것이다. 대상 커밋까지 변경 내역을 거꾸로 적용하는 새 커밋을 만드는 것이다.(이전 커밋이 남겨진다.)

- git reset: 어떤 커밋을 버리고 이전의 특정 버전으로 다시 되돌릴 때 사용한다. git revert와 다른 점은 지운 커밋 내역을 남기지 않는다는 점이다.(이전 커밋 남기지 않는다.)
  변경 내역이 생겨서 git add 명령을 실행해 커밋할 준비가 된 파일을 스테이징 영역에서 제거한다. 파일 변경 내역은 보존된다.

- git rebase: git merge 처럼 병합할 때 사용한다. 하지만 브랜치가 많을 경우 브랜치 이력을 확인하면서 병합한다.

- git diff: 마지막 커밋과 현재 변경 내용을 비교해 보여준다.

- git stash: Staged 상태에 있는 커밋되지 않는 변경 내역을 stash라는 임시 공간에 저장한다.
	git stash pop: stash에 마지막으로 저장된 변경 내역을 현재 브랜치에 적용한다.
	git stash list: stash에 저장된 변경 내역의 목록을 출력한다.
	git stash drop: 마지막으로 저장된 변경 내역을 삭제한다.

- git rm 파일이름: 저장소에서 버전 관리 중인 파일을 삭제한다. 그와 더불어 실제 로컬 파일도 삭제한다. 삭제 기록도 저장소에 남는다.
	git rm --cahed 파일이름: 저장소에서 버전 관리 중인 파일만 삭제한다. 로컬 파일을 그대로 남는다.
	git mv 파일이름 변경될 파일 이름: 저장소에서 버전 관리 중인 파일의 이름을 변경한다. 변경 기록도 저장소에 남는다.
