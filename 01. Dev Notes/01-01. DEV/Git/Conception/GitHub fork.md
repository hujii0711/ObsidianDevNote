
## Fork란?

Fork는 다른 사람의 GitHub 저장소(repository)를 **내 GitHub 계정으로 통째로 복사**해 오는 기능입니다. 원본 저장소와는 별개로 내 소유의 독립된 복사본이 만들어지며, 이 복사본에서는 내가 마음대로 코드를 수정하고 커밋할 수 있습니다.

## 왜 사용하나요?

가장 흔한 이유는 **내가 직접 쓰기 권한이 없는 저장소에 기여(contribute)하고 싶을 때**입니다. 예를 들어 어떤 오픈소스 프로젝트에 버그 수정이나 기능 추가를 제안하고 싶은데, 원본 저장소에는 보통 권한이 없어서 직접 푸시할 수 없습니다. 이때 fork를 떠서 내 복사본에서 작업한 뒤, 그 변경 사항을 원본에 반영해 달라고 요청하는 흐름을 사용합니다.

그 외에도 어떤 프로젝트를 기반으로 나만의 다른 방향으로 발전시키고 싶을 때(독립적인 파생 프로젝트), 또는 단순히 코드를 자유롭게 실험해 보고 싶을 때도 사용합니다.

## 기본 작업 흐름

오픈소스 기여의 전형적인 흐름은 다음과 같습니다:

1. **Fork** — 원본 저장소를 내 계정으로 복사
2. **Clone** — 내 fork를 로컬 컴퓨터로 내려받기
3. **수정 & 커밋** — 코드를 변경하고 커밋
4. **Push** — 변경 사항을 내 fork(GitHub)에 올리기
5. **Pull Request(PR)** — 원본 저장소에 "내 변경 사항을 반영해 주세요"라고 요청

원본 저장소의 관리자가 PR을 검토하고 승인하면, 내 변경 사항이 원본에 병합(merge)됩니다.

## Fork vs Clone vs Branch

혼동하기 쉬운 개념들을 구분하면:

- **Fork**: GitHub 서버 상에서 내 계정으로 저장소 전체를 복사 (소유권이 나에게 생김)
- **Clone**: 저장소를 내 로컬 컴퓨터로 내려받기 (GitHub와 로컬 간 작업)
- **Branch**: 하나의 저장소 안에서 작업 갈래를 나누는 것 (저장소 내부)

## 참고할 점

Fork한 저장소는 원본과 연결이 유지되기 때문에, 원본에 새로운 변경 사항이 생기면 내 fork를 **동기화(sync)**해서 최신 상태로 맞출 수 있습니다. 시간이 지나면 fork가 원본보다 뒤처질 수 있으니, 기여하기 전에 동기화해 두는 것이 좋습니다.
