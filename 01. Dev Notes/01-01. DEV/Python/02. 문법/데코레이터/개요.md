파이썬의 데코레이터는 기본적으로 다른 함수를 수정하지 않고 그 기능을 확장하거나 변경할 수 있도록 해주는 고급 기능이다.
데코레이터는 함수를 다른 함수의 인자로써 받아 어떤 처리를 한 후 그 함수를 반환하거나 다른 함수를 반환한다.

## 1. 데코레이터가 뭔가요?

데코레이터는 **"함수를 감싸서 추가 기능을 붙여주는 함수"**예요. 원래 함수의 코드는 건드리지 않고, 그 앞뒤로 새로운 동작(로깅, 시간 측정, 권한 체크 등)을 끼워 넣을 수 있게 해줍니다.

`@log` 같은 문법은 사실 아래 코드를 짧게 쓴 것과 완전히 같아요:

```python
def add(a, b):
    return a + b
add = log(add)   # @log는 이 줄을 자동으로 해주는 것!
```

즉, `add`라는 이름이 이제는 원래의 `add` 함수가 아니라, `log(add)`가 반환한 `wrapper` 함수를 가리키게 됩니다.

## 2. 첫 번째 예제 (`log`) 분석

```python
def log(func):
    def wrapper(*args, **kwargs):
        print(args)
        print(kwargs)
        print(f"{func.__name__} 호출됨")
        return func(*args, **kwargs)
    return wrapper
```

- `log(func)` : 꾸며줄 대상 함수(`func`)를 인자로 받습니다.
- 그 안에 `wrapper`라는 **새 함수를 정의**하고, 이 `wrapper`를 반환합니다.
- 나중에 `add(1, 3)`을 호출하면, 실제로는 `add` 자리에 들어있는 `wrapper(1, 3)`이 호출되는 거예요.

**`*args, **kwargs`가 뭔가요?**

- `*args` : 위치 인자들을 튜플로 묶어서 받음 → `add(1, 3)`이면 `args = (1, 3)`
- `**kwargs` : 키워드 인자들을 딕셔너리로 묶어서 받음 → `add(a=1, b=3)`이면 `kwargs = {'a': 1, 'b': 3}`
- 이렇게 받아두면, `wrapper`가 **어떤 함수든, 인자가 몇 개든 상관없이** 그대로 원래 함수(`func`)에 전달해 줄 수 있어요.

### `print(add(1, 3))` 실행 흐름

1. `add(1, 3)` 호출 → 사실은 `wrapper(1, 3)`이 실행됨
2. `args = (1, 3)`, `kwargs = {}` 출력
3. `"add 호출됨"` 출력 (`func.__name__`은 원래 함수 이름인 `"add"`)
4. `func(*args, **kwargs)` → 즉 `add(1, 3)`을 진짜로 실행 → `1 + 3 = 4` 반환
5. 그 `4`가 `wrapper`의 반환값이 되고, `print(add(1,3))`이 `4`를 출력

**출력 결과:**

```
(1, 3)
{}
add 호출됨
4
```

`multiply(1, 3)`도 완전히 같은 방식으로 동작해요. `func.__name__`이 `"multiply"`로 바뀌는 것만 다릅니다.

## 3. 두 번째 예제 (`log_before_after`) 분석

```python
def log_before_after(func):
    def wrapper(*args, **kwargs):
        print(f"[전] {func.__name__} 호출됨, 인자={args}, {kwargs}")
        result = func(*args, **kwargs)
        print(f"[후] {func.__name__} 반환값={result}")
        return result
    return wrapper
```

구조는 첫 번째와 똑같지만, **함수 실행 전/후로 로그를 나눠서 찍는** 점이 달라요.

- `func(*args, **kwargs)`를 바로 `return`하지 않고, `result` 변수에 **저장**해뒀다가
- 그 결과를 출력한 다음에 `return result`로 반환합니다.
- 이렇게 결과를 변수에 담아두는 이유는, **함수 실행 후에도** 그 결과값을 가지고 뭔가(여기서는 출력)를 하고 싶기 때문이에요.

### `print(subtract(10, 3))` 실행 흐름

1. `wrapper(10, 3)` 실행 시작
2. `[전] subtract 호출됨, 인자=(10, 3), {}` 출력
3. 실제 `subtract(10, 3)` 실행 → `10 - 3 = 7` → `result = 7`
4. `[후] subtract 반환값=7` 출력
5. `7`을 반환 → `print(subtract(10,3))`이 `7` 출력

**출력 결과:**

```
[전] subtract 호출됨, 인자=(10, 3), {}
[후] subtract 반환값=7
7
```

## 4. 핵심 요약

|개념|설명|
|---|---|
|데코레이터|함수를 인자로 받아 새 함수(wrapper)로 감싸서 반환하는 함수|
|`@log`|`add = log(add)`를 줄여 쓴 문법|
|`*args, **kwargs`|원래 함수가 어떤 인자를 받든 그대로 전달해주기 위한 장치|
|`func.__name__`|감싸진 원래 함수의 이름 (디버깅/로깅에 유용)|
|실행 전/후 로직|`result = func(...)`처럼 결과를 변수에 저장해두면 실행 후 처리도 가능|

정리하면, 두 데코레이터 모두 **"원래 함수 호출을 가로채서, 앞뒤로 로그를 찍고, 다시 원래 함수를 실행해준다"**는 같은 패턴이에요. 차이는 로그를 호출 _전에만_ 찍느냐, _전후로_ 나눠서 찍느냐일 뿐입니다. 이 패턴에 익숙해지면 실행 시간 측정, 로그인 체크, 캐싱 같은 실무 데코레이터도 쉽게 이해할 수 있어요.
