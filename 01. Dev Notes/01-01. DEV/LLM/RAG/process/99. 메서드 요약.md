### 1. 문서 로더
```python
loader = PyPDFLoader(FILE_PATH)
text_splitter = RecursiveCharacterTextSplitter(chunk_size=200, chunk_overlap=0)

docs = loader.load()
split_docs = loader.load_and_split(text_splitter=text_splitter)
loader.lazy_load()
adocs = loader.aload()
```

#### (1) loader.load_and_split(text_splitter)  -> List[Document]
LangChain의 `load_and_split()`은 문서를 불러오는 작업(Load)과 텍스트를 잘게 쪼개는 작업(Split)을 한 번에 수행해 주는 메서드입니다.

- **일체형 처리**: 원래라면 문서를 로드한 뒤(`loader.load()`) 별도의 텍스트 분할기를 거쳐야 하지만, 이 메서드를 사용하면 한 줄로 문서를 불러오고 곧바로 청크(Chunk) 단위로 분할할 수 있습니다.
- **반환 값**: 분할된 텍스트 조각들이 담긴 `Document` 객체 리스트를 반환합니다.

작성하신 코드에서 `split_docs = loader.load_and_split(text_splitter)`는 **PDF 파일을 읽어오자마자** 앞서 정의한 `text_splitter` 규칙(크기 200)에 맞춰 즉시 쪼개어 `split_docs`에 저장하는 역할을 합니다.

### 2. 청킹
```python
text_splitter = RecursiveCharacterTextSplitter
text_splitter.create_documents([file])
chunks = text_splitter.split_text(file)

loader = TextLoader("file.txt", encoding="utf-8")
docs = loader.load()
split_docs = text_splitter.split_documents(docs)
```

#### (1) create_documents(List[str]) -> List[Document]
LangChain의 `create_documents()`는 **순수 텍스트(문자열 리스트)를 입력받아, 지정된 규칙에 따라 쪼갠 뒤 LangChain의 `Document` 객체 리스트로 변환**해 주는 메서드입니다.

- **`Document` 객체 생성**: 단순한 문자열(`str`) 조각들을 LangChain에서 표준으로 사용하는 `Document` 객체(`page_content`와 `metadata` 속성을 가짐)로 감싸줍니다.
- **벡터 저장소 연계 준비**: 쪼개진 텍스트들이 곧바로 벡터 디스크(Vector Store)나 LLM 체인에 입력될 수 있도록 포맷을 맞춰줍니다.

**참고 사항**
질문하신 코드에서 `[file]`을 전달할 때, `file`이 파일 객체나 경로가 아니라 텍스트 내용이 담긴 문자열
(str)이어야 정상적으로 텍스트 분할이 수행됩니다.
만약 파일 전체 내용의 문자열이라면`[file_content_str]` 형태로 전달해야 합니다.

#### (2) split_text(str) -> List[str]
LangChain의 `split_text()`는 **하나의 긴 문자열(텍스트)을 입력받아, 설정된 규칙(청크 크기, 오버랩 등)에 따라 잘게 쪼갠 뒤 '순수 문자열 리스트(`List[str]`)'로 반환**해 주는 메서드입니다.

- **순수 문자열 반환**: 앞서 본 `create_documents()`가 LangChain의 `Document` 객체(메타데이터 포함) 형태로 반환하는 것과 달리, `split_text()`는 오직 **텍스트 조각(`str`)들만 담긴 파이썬 기본 리스트**를 반환합니다.
- **단일 텍스트 처리**: 하나의 큰 텍스트 파일 내용(문자열)을 통째로 넣고, 가공된 텍스트 조각 문자열들을 곧바로 코드에서 활용하고 싶을 때 유용합니다.

#### (3) split_documents(List[Document]) -> List[Document]
LangChain의 `split_documents()`는 **이미 로드되어 있는 LangChain의 `Document` 객체 리스트를 입력받아, 설정된 규칙에 따라 텍스트를 쪼갠 뒤 새로운 `Document` 객체 리스트로 반환**해 주는 메서드입니다.

- **`Document` 구조 유지**: 문자열만 쪼개는 것이 아니라, 각 문서가 가지고 있던 **기존 메타데이터(`metadata`, 예: 파일 경로, 페이지 번호 등)를 그대로 유지**하면서 내용만 청크 단위로 쪼갭니다.
- **표준적인 분할 방식**: 앞서 살펴본 <mark style="background:#ff4d4f">loader.load_and_split()과 내부적으로 거의 같은 역할</mark>을 합니다. 차이점은 `load_and_split()`이 '로드와 분할을 한 번에' 처리하는 반면, 이 방식은 `loader.load()`로 문서를 먼저 읽은 뒤 **분할 단계만 따로 독립적으로 수행**할 때 사용합니다.

 **참고 사항**
작성하신 코드처럼 `TextLoader` 등으로 불러온 `docs`(`Document` 객체 리스트)를 입력으로 넣어야 에러 없이 정상적으로 쪼개진 `Document` 리스트를 얻을 수 있습니다.

### 4. 벡터스토어

```python
db = Chroma.from_documents(
	documents=split_doc1, embedding=OpenAIEmbeddings(), collection_name="my_db"
)
```

#### (1) from_documents()
LangChain의 `Chroma.from_documents()`는 **문서(`Document`) 리스트를 입력받아 임베딩(Vectorization) 작업을 거친 뒤, 이를 Chroma 벡터 데이터베이스에 곧바로 저장하고 DB 객체를 생성**해 주는 클래스 메서드입니다.

- **<mark style="background:#ff4d4f">원스톱 벡터화 및 적재</mark>**: 텍스트 조각들이 담긴 `documents`를 받아 지정한 임베딩 모델(예: `OpenAIEmbeddings()`)을 통해 벡터로 변환하고, 이를 Chroma DB에 자동으로 저장합니다.
- **벡터 DB 객체 반환**: 저장 완료 후, 이후에 유사도 검색(`similarity_search`) 등을 수행할 수 있도록 조작 가능한 `db` 객체를 반환합니다.
- **컬렉션 관리**: `collection_name="my_db"`처럼 파라미터를 지정하여 데이터베이스 내에서 사용할 특정 컬렉션(테이블) 이름을 설정할 수 있습니다.

**참고 사항**
이 메서드를 사용하면 '임베딩 모델 생성 ➡️ 문서 벡터화 ➡️ DB에 추가'하는 복잡한 과정을 한 줄의 코드로 간단하게 처리할 수 있습니다.

#### (2) from_texts()
```python
db2 = Chroma.from_texts(
	["안녕하세요. 정말 반갑습니다.", "제 이름은 테디입니다."],
	embedding=OpenAIEmbeddings(),
)
```
LangChain의 `Chroma.from_texts()`는 **순수 문자열(텍스트) 리스트**를 직접 입력받아, 내부적으로 임베딩(Vectorization)을 거친 뒤 Chroma 벡터 데이터베이스에 저장하고 DB 객체를 생성해 주는 클래스 메서드입니다.
- **Raw 텍스트 직접 처리**: 앞서 본 `from_documents()`와 달리, `Document` 객체로 미리 감쌀 필요 없이 파이썬의 기본 문자열 리스트(`List[str]`)를 바로 전달하여 간편하게 벡터 DB를 구축할 수 있습니다.
- **원스톱 벡터화 및 적재**: 문자열 입력, 임베딩 모델(`OpenAIEmbeddings`)을 통한 벡터 변환, Chroma DB 저장 과정을 한 번에 처리합니다.
- **`from_documents()`와의 차이점**:
    - `from_documents()`는 메타데이터가 포함된 `Document` 객체 리스트를 처리할 때 사용합니다.
    - `from_texts()`는 별도의 객체 생성 과정 없이 순수 텍스트 문자열들을 빠르게 벡터 DB에 넣고 싶을 때 유용합니다. (내부적으로 문자열들을 `Document` 객체로 자동 변환하여 처리합니다.)
