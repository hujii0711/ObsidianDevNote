

|구성 요소|신체 비유|설명|
|---|---|---|
|**LLM**|두뇌|판단하고 결정합니다. 혼자서는 아무것도 실행하지 못합니다.|
|**도구 (Tools)**|손과 발|파일 읽기/쓰기, 검색, API 호출처럼 실제로 세상에 작용합니다.|
|**State (상태)**|단기 기억, 혈액|모든 부위가 공유하는 현재 상황과 데이터입니다.|
|**LangGraph**|신경계|어느 부위가 언제 움직일지 신호를 전달하고 순서를 조율합니다.|
|**체크포인터**|장기 기억, 일기장|중간 상태를 저장해서 나중에 이어갑니다.|
|**에이전트**|몸 전체|두뇌, 손발, 신경계가 합쳐져 하나의 행동 주체가 된 것입니다.|

## 어떤 점이 달랐나

**에이전트는 "몸통"이라기보다 "몸 전체"입니다.** 에이전트는 별개의 부품이 아니라 LLM, 도구, 제어 흐름이 결합된 결과물입니다. 그래서 LangGraph로 만든 그래프가 곧 에이전트가 될 수도 있습니다.

**LangGraph는 모세혈관보다 신경계에 가깝습니다.** 모세혈관은 영양분(데이터)을 나르는 역할인데, LangGraph의 핵심은 **"다음에 무엇을 할지"를 제어**하는 데 있습니다. 데이터 전달(State)과 흐름 제어(Edge, 분기, 루프)를 모두 담당하므로, 혈관과 신경을 합친 쪽이 더 정확합니다.

## 한 문장으로

> LLM이 생각하고, 도구가 행동하고, LangGraph가 "생각 → 행동 → 확인 → 다시 생각"의 순환을 이어 준다.

## 예외 한 가지

LangGraph가 필수는 아닙니다. 앞서 본 OpenClaw나 Hermes는 LangGraph 없이 자체 루프로 같은 신경계 역할을 구현했습니다. 신경계를 라이브러리로 구성할지 직접 만들지의 차이일 뿐, 구조는 같습니다.


---

## 에이전트를 만드는 세 가지 방법

|방법|위치|설명|
|---|---|---|
|**`create_agent`**|LangChain (`langchain.agents`)|LangChain 1.0에서 도입된 표준 방식입니다. 모델, 도구, 시스템 프롬프트만 주면 됩니다.|
|**`create_react_agent`**|LangGraph (`langgraph.prebuilt`)|예전 방식입니다. `create_agent`로 대체되는 방향이라 새로 시작한다면 `create_agent`를 권합니다.|
|**직접 그래프 구성**|LangGraph (`StateGraph`)|노드와 엣지를 직접 설계합니다. 분기, 승인, 멀티 에이전트처럼 커스터마이징이 필요할 때 씁니다.|

## 예시 (`create_agent`)

```python
from langchain.agents import create_agent
from langchain_core.tools import tool

@tool
def read_file(path: str) -> str:
    """파일 내용을 읽는다."""
    return open(path).read()

agent = create_agent(
    model="anthropic:claude-sonnet-4-5",   # 사용 가능한 모델명으로 교체
    tools=[read_file],
    system_prompt="너는 코드 수정을 돕는 어시스턴트다.",
)

result = agent.invoke({"messages": [("user", "main.py를 읽고 요약해줘")]})
```

JavaScript에서도 `createAgent`로 같은 방식입니다.

## 선택 기준

- **빠르게 도구 쓰는 에이전트가 필요하다** → `create_agent`
- **흐름을 세밀하게 제어해야 한다** (조건 분기, 사람 승인 지점, 여러 에이전트 협업) → `StateGraph`로 직접 구성
- 둘은 배타적이지 않습니다. `create_agent`로 만든 에이전트를 큰 그래프의 노드(서브그래프)로 넣는 식으로 섞어 쓸 수 있습니다.

## 정리

- **LangChain**은 모델, 도구, 에이전트 생성 같은 부품과 고수준 API를 제공합니다.
- **LangGraph**는 그 에이전트가 실행되는 엔진이자, 직접 흐름을 설계할 때 쓰는 저수준 도구입니다.

---
LangGraph는 "LLM이 여러 단계를 거치며 판단하고 행동하는" 앱에 잘 맞습니다. 대표적인 종류를 정리하면 다음과 같습니다.

## 1. 도구를 쓰는 AI 어시스턴트

- **고객지원 봇**: 주문 조회, 환불 처리, FAQ 검색을 도구로 연결하고, 처리할 수 없으면 상담원에게 넘깁니다.
- **사내 업무 비서**: 캘린더, 메일, 슬랙, 문서를 조회하고 일정 잡기나 요약을 대신합니다.
- **데이터 분석 에이전트**: "지난달 매출 보여 줘"라는 요청을 SQL로 바꿔 실행하고, 오류가 나면 쿼리를 고쳐 다시 시도한 뒤 결과를 설명합니다.

## 2. 검색·지식 기반 앱 (고급 RAG)

- **자기 점검형 문서 Q&A**: 검색 → 답변 생성 → 근거가 부족하면 질문을 바꿔 재검색하는 루프를 돕니다.
- **리서치 에이전트**: 주제를 쪼개 여러 곳을 검색하고, 결과를 종합해 보고서를 씁니다.

## 3. 코딩·콘텐츠 생성 앱

- **코드 수정 에이전트**: 코드 수정 → 테스트 실행 → 실패 시 재수정을 반복합니다. (앞서 말씀드린 구조)
- **글쓰기 파이프라인**: 초안 작성 → 검토 → 수정 → 최종본으로 이어지는 흐름을 만듭니다.
- **번역·검수 워크플로**: 번역 후 다른 에이전트가 오역을 점검해 재번역합니다.

## 4. 사람 승인이 필요한 업무 자동화

- **이메일 자동 답장**: 초안을 만들고 사람이 승인하면 발송합니다.
- **결제·계약·배포 보조**: 위험한 단계 직전에 멈춰서 확인을 받고 재개합니다.
- **문서 검토 흐름**: 계약서나 이력서를 1차로 분석하고, 사람이 최종 판단합니다.

## 5. 멀티 에이전트 시스템

- **팀 구조 에이전트**: 감독자가 작업을 나눠 주고, 리서처, 작성자, 검수자 에이전트가 협업합니다.
- **전문가 라우팅 챗봇**: 질문 유형(법률, 기술, 결제)에 따라 담당 에이전트로 연결합니다.

## 6. 장기 대화·개인화 앱

- **기억하는 챗봇**: 사용자별 선호와 이전 대화를 저장하고 이어서 대화합니다. (튜터, 코치, 상담형 앱)
- **학습 도우미**: 학습 진도를 기억하고, 틀린 부분 위주로 문제를 냅니다.

## 앱 유형별로 쓰는 LangGraph 기능

|앱 유형|핵심 기능|
|---|---|
|도구 사용 에이전트|`ToolNode`, 조건부 엣지, 루프|
|승인형 자동화|`interrupt()`, 체크포인터|
|멀티 에이전트|서브그래프, `Command`(handoff)|
|기억형 챗봇|체크포인터, 스토어|
|실시간 UI|`stream` (진행 상황 스트리밍)|

## 어떤 형태로 배포하나?

- **웹/모바일 앱의 백엔드 API**: FastAPI나 Express/Next.js에 붙입니다.
- **메신저 봇**: 슬랙, 텔레그램, 카카오톡 등과 연동합니다.
- **내부 도구**: 사내 시스템에 연결된 자동화 에이전트로 씁니다.

처음 만든다면 **"도구 1~2개를 쓰는 챗봇 + 대화 기억"**부터 시작하는 것을 권합니다. 필요한 개념을 대부분 다룰 수 있는 크기입니다. 만들고 싶은 앱이 있으시면 알려 주세요. 구조에 맞는 그래프 설계를 같이 잡아 드리겠습니다.
