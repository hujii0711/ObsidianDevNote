
**Chat / Conversation 형식 (멀티턴 대화)**

OpenAI나 Anthropic 스타일의 채팅 모델 학습에 흔히 쓰이는 형식으로, role 기반 메시지 배열입니다.
```json
{
  "messages": [
    {"role": "system", "content": "너는 친절한 한국어 어시스턴트야."},
    {"role": "user", "content": "파이썬으로 피보나치 수열 짜줘."},
    {"role": "assistant", "content": "다음은 피보나치 수열을 구현한 코드입니다...\n```python\ndef fib(n): ...\n```"}
  ]
}
```

이 형식은 `messages`라는 배열 안에 대화를 구성하는 각 발화(turn)를 순서대로 담은 구조예요. 각 메시지는 `role`과 `content`라는 두 속성을 가집니다.

**role 속성**

대화에서 누가 말하고 있는지를 나타냅니다. 보통 세 가지 값을 사용해요.

`system`은 모델의 전반적인 행동 방식, 성격, 제약조건을 설정하는 역할입니다. 대화가 시작되기 전에 모델에게 "너는 이런 존재야"라고 미리 알려주는 지침이에요. 위 예시에서는 "너는 친절한 한국어 어시스턴트야"라고 설정해서, 모델이 이후 응답할 때 친절한 톤과 한국어를 사용하도록 유도합니다. system 메시지는 보통 대화당 한 번만 있고, 사용자에게 직접 보이지 않는 경우가 많아요.

`user`는 실제 사용자가 입력한 질문이나 요청을 나타냅니다. 위 예시에서는 "파이썬으로 피보나치 수열 짜줘"가 사용자의 요청이에요.

`assistant`는 모델이 생성해야 할(또는 생성한) 응답을 나타냅니다. 학습 데이터에서는 이 부분이 바로 모델이 학습을 통해 흉내내야 할 정답 출력이에요. 즉 파인튜닝 시 loss 계산은 보통 이 assistant 메시지에 대해서만 이루어지고, system과 user 메시지는 입력(컨텍스트)으로만 사용됩니다.

**content 속성**

해당 role이 실제로 말한 텍스트 내용 자체입니다. assistant의 content를 보면 마크다운 코드 블록(```python ... ```)이 그대로 텍스트로 들어가 있는데, 이는 모델이 코드 형식으로 응답하는 패턴까지 학습하도록 하기 위함이에요.

**구조 전체의 의미**

이 messages 배열 전체가 하나의 학습 샘플(example)이 되고, 모델은 system + user 메시지를 입력으로 받았을 때 assistant 메시지와 같은 출력을 내도록 가중치를 조정합니다. 멀티턴 대화라면 이 배열 안에 user-assistant 쌍이 여러 번 반복되어 들어갈 수도 있어요 (예: user → assistant → user → assistant...). 이 경우 일반적으로 마지막 assistant 메시지, 혹은 모든 assistant 메시지에 대해 loss를 계산하는 방식으로 학습이 진행됩니다.
