
**24/7 에이전트**는 사람이 계속 붙어서 지시를 내리지 않아도, AI 에이전트가 하루 종일·일주일 내내 스스로 작업을 감지하고 실행하는 방식을 말합니다. 지금까지 얘기 나눈 Hermes 맥락에서 보면, "채팅창에 물어볼 때만 응답하는 챗봇"과 대비되는 **상시 가동형 자율 에이전트**라고 이해하시면 됩니다.

## 핵심 개념

| 구분    | 일반 챗봇          | 24/7 에이전트                               |
| ----- | -------------- | --------------------------------------- |
| 트리거   | 사람이 메시지를 보낼 때만 | 스케줄(크론), 이벤트, 조건 감지로 스스로 시작             |
| 실행 주체 | 매 턴 사람이 개입     | 백그라운드에서 독립적으로 루프 실행                     |
| 예시    | "이 코드 리뷰해줘"    | 매일 오전 9시 이메일 확인 → 우선순위 정리 → 요약 보고 자동 전송 |

## 어떻게 동작하나 (구성 요소)

1. **트리거(Trigger)**
    - 시간 기반: 크론(cron) 스케줄 — "매시간", "매일 오전 8시" 등
    - 이벤트 기반: 새 이메일 도착, 파일 변경, Webhook, 특정 로그 패턴 감지 등

2. **메모리(Memory)**
    - 앞서 말씀드린 Hermes의 4단계 메모리 시스템처럼, 이전에 뭘 했는지·무슨 판단을 내렸는지 기억해야 반복 작업에서 일관성이 생깁니다.

3. **도구 접근(Tool Use)**
    - 파일 시스템, 이메일, 캘린더, 웹, 데이터베이스 등에 접근할 수 있는 MCP 서버·API 연동

4. **자기 감독(Self-loop / Observe-Act)**
    - 스스로 결과를 확인하고, 실패하면 재시도하거나 다른 접근을 시도하는 루프

## 실제 사용 예시

- **개발**: 야간에 CI 빌드 실패 감지 → 원인 분석 → 간단한 수정 PR 자동 생성
- **운영**: 서버 로그 24시간 모니터링 → 이상 징후 발견 시 알림 또는 자동 대응
- **개인 비서**: 매일 아침 이메일·캘린더·뉴스 요약해서 브리핑 (지금 제가 갖고 있는 "morning" 스킬도 비슷한 개념입니다)
- **리서치**: 특정 키워드로 새 논문/뉴스가 올라오면 자동 수집·요약

## 주의할 점

- **비용**: 상시 가동이라 API 토큰 소모가 계속 발생합니다. 그래서 이전에 말씀드린 대로 저비용 모델(로컬 Qwen, DeepSeek V4-Flash 등)로 상시 루프를 돌리고, 판단이 중요한 순간에만 고성능 모델로 승격시키는 라우팅 전략이 자주 쓰입니다.
- **권한 범위**: 사람 개입 없이 도구를 계속 호출하다 보니, 파일 삭제·이메일 발송 같은 되돌리기 어려운 작업에는 승인 단계나 샌드박스 격리가 필요합니다. 앞서 말씀드린 오픈클로 사고(메일함 삭제) 사례가 바로 이런 위험을 보여주는 예입니다.
- **컨텍스트 관리**: 계속 쌓이는 로그·메모리를 정리하지 않으면 컨텍스트가 비대해져 성능이 떨어지므로, 요약·정리(compaction) 메커니즘이 중요합니다.
