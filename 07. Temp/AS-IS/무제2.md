
## 아니요 — 두 가지 다른 메커니즘이 섞여 있습니다

출력화면 바인딩은 **컨트롤명이 아니라 `.scn`의 MapInfo가 명시한 짝**으로 이루어집니다. 컨트롤명으로 자동 매칭하는 메커니즘도 **따로 존재하지만**, 그건 다른 저장소를 씁니다.

## ① 출력화면 경로 — LinkData 키는 "봉투"일 뿐입니다


**키가 화면당 하나뿐이고, 값은 Device XML 전체 덩어리입니다.** 컨트롤 개수와 무관합니다 — 컨트롤이 50개든 1개든 LinkData 항목은 딱 1건입니다.

## 맞습니다 — 이번 건은 진짜 화면별 격리입니다

직전에 물어보신 `"<FD>-pbprt(<화면>)"` 케이스와는 다릅니다. 그건 전역 `pbprt-name`을 거치는 핸드오프였지만, **이번 `"<화면번호>-<디바이스타입>"`은 소비자가 자기 화면번호로 키를 직접 조립**합니다.

## 두 그룹의 성격

### ① `pbprt-copies` / `pbprt-fcopies` — 전역 고정 키 ✓

```cpp

Platform->SetLinkData(_T("pbprt-fcopies"), strFCopies);   // 앞면 매수
Platform->SetLinkData(_T("pbprt-bcopies"), strBCopies);   // 뒷면 매수
Platform->SetLinkData(_T("pbprt-common"),  strInfo);      // V0/V1/V3/V4
```

키에 화면 식별자가 전혀 없습니다. **전 화면이 공유하는 슬롯 하나**입니다.

다만 소비자가 **읽고 즉시 비웁니다**:


> 같은 `pbprt-` 계열인데 **`pbprt-prtopt`만 비우지 않습니다** ([DeviceScreen.cpp:1427](vscode-webview://0kn1upfq0pgov6joeqae9ant0ihtbuu2v197965giu348gn7f4ei/iworks4-src/iWorks_KB_Unicode/Custom/IztCustomKB/Screen/DeviceScreen.cpp#L1427)). 앞서 지적한 그 예외입니다.

## 다만 두 가지 단서

**① 격리 기준은 "출력 대상 화면"입니다.** `m_strRevScreenNo`는 전문 헤더 `Scrno`([TranMCI.cpp:3122](vscode-webview://0kn1upfq0pgov6joeqae9ant0ihtbuu2v197965giu348gn7f4ei/iworks4-src/iWorks_KB_Unicode/Custom/IztCustomKB/Tran/TranMCI.cpp#L3122))이지, 거래를 보낸 화면이 아닙니다. **서로 다른 업무화면 A·B가 같은 공통 출력화면 X를 쓰면 키가 겹칩니다.**

**② 저장소 자체는 여전히 전역입니다.** `theApp.m_mapLinkData` 하나뿐이고([PowerWorks.h:247](vscode-webview://0kn1upfq0pgov6joeqae9ant0ihtbuu2v197965giu348gn7f4ei/iworks4-src/iWorks_KB_Unicode/PowerWorks/PowerWorks.h#L247)), 프레임워크가 화면 단위로 격리해주는 게 아니라 **키 문자열 규약이 격리를 만듭니다.** 그래서 키를 잘못 짜면(= `pbprt-prtopt`처럼) 바로 전역 오염이 됩니다.

**③ 이 키는 소비 후 지워지지 않습니다.** [Kes.cpp:3709](vscode-webview://0kn1upfq0pgov6joeqae9ant0ihtbuu2v197965giu348gn7f4ei/iworks4-src/iWorks_KB_Unicode/Custom/IztCustomKB/Screen/Kes.cpp#L3709)에 `GetLinkData`만 있고 `RemoveLinkData`가 없습니다. 원래 지우는 코드가 [ScreenDoc.cpp:613~632](vscode-webview://0kn1upfq0pgov6joeqae9ant0ihtbuu2v197965giu348gn7f4ei/iworks4-src/iWorks_KB_Unicode/PowerWorks/ScreenDoc.cpp#L613)에 있었지만 통째로 주석 처리된 상태입니다. 역설적으로 **격리가 잘 된 이 키가 누적은 더 심합니다** — 키가 화면마다 달라서 덮어쓰기에 의한 자연 정리가 일어나지 않기 때문입니다.

## 주의할 점

**① `Find("_")`가 첫 번째 언더스코어를 찾습니다** ([Kes.cpp:3710](vscode-webview://0kn1upfq0pgov6joeqae9ant0ihtbuu2v197965giu348gn7f4ei/iworks4-src/iWorks_KB_Unicode/Custom/IztCustomKB/Screen/Kes.cpp#L3710)). `strTranCode`에 `_`가 포함되면 전문코드가 잘리고 XML 앞부분이 함께 날아갑니다. 생산자가 `strTranCode + _T("_") + strData`로 단순 결합하므로([TranMCI.cpp:4342](vscode-webview://0kn1upfq0pgov6joeqae9ant0ihtbuu2v197965giu348gn7f4ei/iworks4-src/iWorks_KB_Unicode/Custom/IztCustomKB/Tran/TranMCI.cpp#L4342)) 구분자 이스케이프가 없습니다.

**② `SetID()`가 화면의 Tran을 바꿉니다.** 전문이 보낸 `trancode`에 해당하는 Tran이 화면 MapInfo에 없으면 `GetTran()`이 엉뚱한 객체를 주거나 NULL이 되고, **컨트롤 바인딩이 통째로 누락**됩니다. 코드가 `GetTran()` NULL 체크를 3번 반복하는 이유입니다.

**③ `ClearData(_T("o"))`로 기존 출력값이 먼저 지워집니다.** 화면이 이미 열려 있던 상태에서 재호출되면 이전 데이터가 남지 않습니다 — 단 `SCREEN_DATAAPPEND` + IBSheet `AppendMode`인 경우만 그리드 행이 누적됩니다.

**④ 실제 Custom 클래스는 `.scn`이 정합니다.** `CKes`는 가장 흔한 업무화면 클래스일 뿐이고, 같은 `bOutputScreen` 패턴이 [Mci.cpp:634](vscode-webview://0kn1upfq0pgov6joeqae9ant0ihtbuu2v197965giu348gn7f4ei/iworks4-src/iWorks_KB_Unicode/Custom/IztCustomKB/Screen/Mci.cpp#L634), [BPRGiro.cpp:238](vscode-webview://0kn1upfq0pgov6joeqae9ant0ihtbuu2v197965giu348gn7f4ei/iworks4-src/iWorks_KB_Unicode/Custom/IztCustomKB/Screen/BPRGiro.cpp#L238), [KBPPR.cpp:238](vscode-webview://0kn1upfq0pgov6joeqae9ant0ihtbuu2v197965giu348gn7f4ei/iworks4-src/iWorks_KB_Unicode/Custom/IztCustomKB/Screen/KBPPR.cpp#L238), [MiniSingleView.cpp:59](vscode-webview://0kn1upfq0pgov6joeqae9ant0ihtbuu2v197965giu348gn7f4ei/iworks4-src/iWorks_KB_Unicode/Custom/IztCustomKB/Screen/MiniSingleView.cpp#L59)에도 각각 구현돼 있습니다. `.scn`의 Class 속성이 `DeviceScreen`이면 전장표용 [CDeviceScreen::ScreenOpenComplete()](vscode-webview://0kn1upfq0pgov6joeqae9ant0ihtbuu2v197965giu348gn7f4ei/iworks4-src/iWorks_KB_Unicode/Custom/IztCustomKB/Screen/DeviceScreen.cpp#L75)가 돌면서 **완전히 다른 경로**(`pbprt-name` 배턴 방식)를 탑니다.

**⑤ 회수한 LinkData를 지우지 않습니다.** `GetLinkData` 뒤에 `RemoveLinkData`가 없어, 화면이 어떤 이유로 `ScreenOpenComplete`를 다시 타면 **직전 거래 데이터를 그대로 재사용**합니다.
