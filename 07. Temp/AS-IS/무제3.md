

## 3중 매칭 — `strLinkData`와 `strDevice`가 세 축을 모두 공급합니다

```
생산자 (TranMCI.cpp:4339~4343)                          MapInfo (.scn)
─────────────────────────────────────────────────────────────────────────────
strDeviceType = "screen"  ──────────────────────────► <Device Device="screen">   ②
                          ┌─────────────────────────► <TranID TranId="KJI0400341"> ①
strTranCode = "KJI0400341"┘
      +  "_"  +
strData = <Device ...>
            <Fld id="acctNo"  value="123"/> ─────────► <Item TranItem="acctNo"
            <Fld id="custNm"  value="홍길동"/>                CtrlId="edtAccountNo"/>  ③
            <Grid id="trxList"> ... </Grid>
          </Device>
```

### ① `strTranCode` → 어느 `<TranID>` 블록을 쓸지

```cpp
// Kes.cpp:3712
CString strTran = strData.Find("_") 앞부분;       // "KJI0400341"
m_pScreenInfo->SetID(strTran);                    // m_mapTrans["KJI0400341"] 의 CTransaction 선택
...

```

화면에 전문이 여러 개 매핑돼 있을 때 **어느 매핑 세트를 쓸지 고르는 스위치**입니다. 이게 없으면 화면이 마지막에 로드된 Tran을 쓰게 됩니다.

### ② `strDeviceType` → `<Device>` 중 어느 것

```cpp
// TranMCI.cpp:6540
m_pTran->BindOutputData(lpDeviceType);     // "screen"
```

`BindOutputData("screen")`은 `GetOutputData(strFD, "screen")`으로 **screen 디바이스 항목만** 골라 바인딩합니다([Transaction.cpp:1348](vscode-webview://0kn1upfq0pgov6joeqae9ant0ihtbuu2v197965giu348gn7f4ei/iworks4-src/iWorks_KB_Unicode/PowerWorks/Transaction.cpp#L1348)). 같은 전문의 `pbprt` 항목은 건드리지 않습니다.

### ③ `strData` 안의 `<Fld id="...">` → `TranItem="..."`

```cpp
// TranMCI.cpp:5926~5931  ParseFieldData(strFD, strDeviceType, strID, strValue)

```


## 정리하면

`strLinkData`는 **"어느 매핑표를 쓸지(전문코드) + 무엇을 채울지(항목 값들)"** 를 한 문자열에 담은 것이고, `strDevice` 키는 **"누구에게 배달할지(화면번호) + 어느 섹션인지(디바이스타입)"** 를 담고 있습니다. 네 가지가 모두 MapInfo의 네 축과 1:1로 대응합니다.

|전달물|역할|MapInfo 대응|
|---|---|---|
|`strDevice`의 `m_strRevScreenNo`|배달지|(화면 자체 = `.scn` 파일)|
|`strDevice`의 `strDeviceType`|섹션 선택|`<Device Device="screen">`|
|`strLinkData`의 `strTranCode`|매핑표 선택|`<TranID TranId="…">`|
|`strLinkData`의 `strData`|실제 값|`<Item TranItem="…">` ↔ `<Fld id="…">`|

## 한 가지 주의

`.scn` MapInfo의 `TranItem="acctNo"`는 **전문 정의(FD)의 항목명**이지 LinkData 키가 아닙니다. `Platform->SetLinkData("acctNo", "123")`을 아무리 해도 이 경로에는 들어가지 않습니다 — `FindSingleItem()`이 찾는 대상은 `m_mapLinkData`가 아니라 파싱된 `CTranData` 객체이기 때문입니다.

그리고 MapInfo에 매핑이 없는 항목은 `pItem->GetControl()`이 NULL이라 **조용히 건너뜁니다.** 전문에는 값이 왔는데 화면에 안 찍힌다면 십중팔구 이 경우이고, `[<컨트롤명>] 수신 데이터 설정 전` 로그가 안 남는 것으로 확인할 수 있습니다.
