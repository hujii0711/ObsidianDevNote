안녕하세요! 처음 보면 낯선 요소가 많은 코드라 하나씩 풀어서 설명드릴게요.

## 전체 구조

```cpp
void CScriptFunction::ShowPane(LPCTSTR frameName, BOOL bShow, BOOL bRefresh)
{
	m_pPlatformAPI->ShowPane(frameName, bShow, bRefresh);
}
```

이것은 **클래스의 멤버 함수 정의**입니다. 한 부분씩 살펴보겠습니다.

---

### 1. `void` ― 반환 타입
함수가 끝났을 때 돌려주는 값이 **없다**는 뜻입니다. `return 값;`을 쓰지 않는 함수입니다.

### 2. `CScriptFunction::ShowPane` ― 소속과 이름
- `::`는 **범위 지정 연산자(scope resolution operator)**입니다.
- "`CScriptFunction` 클래스에 소속된 `ShowPane`이라는 함수"라는 뜻입니다.
- C++에서는 보통 헤더 파일(.h)에 클래스와 함수 **선언**을 쓰고, .cpp 파일에 실제 **구현(정의)**을 씁니다. 이 코드는 .cpp 쪽 구현부라서 `클래스이름::`을 붙여 "이 함수가 어느 클래스 것인지" 명시하는 것입니다.

헤더에는 아마 이렇게 선언되어 있을 겁니다:
```cpp
class CScriptFunction
{
public:
	void ShowPane(LPCTSTR frameName, BOOL bShow, BOOL bRefresh);  // 선언만
	// ...
};
```

### 3. 매개변수(파라미터) 3개

| 매개변수 | 타입 | 의미 |
|---|---|---|
| `frameName` | `LPCTSTR` | 창(pane)의 이름 문자열 |
| `bShow` | `BOOL` | 보여줄지 여부 (참/거짓) |
| `bRefresh` | `BOOL` | 새로고침할지 여부 (참/거짓) |

여기서 `LPCTSTR`, `BOOL`은 표준 C++ 타입이 아니라 **Windows API(WinAPI)에서 정의한 타입**입니다:

- **`LPCTSTR`** = **L**ong **P**ointer to **C**onstant **T**CHAR **STR**ing
  - 쉽게 말해 "**읽기 전용 문자열 포인터**"입니다 (`const TCHAR*`).
  - 프로젝트 설정에 따라 유니코드 빌드면 `const wchar_t*`, 아니면 `const char*`가 됩니다.
- **`BOOL`** = Windows에서 정의한 참/거짓 타입 (실제로는 `int`). C++ 표준의 소문자 `bool`과는 다른, 더 오래된 Windows 스타일입니다. `TRUE`/`FALSE` 값을 씁니다.

참고로 `bShow`, `bRefresh`의 `b` 접두사는 "boolean"이라는 뜻의 **헝가리안 표기법**이고, 클래스 이름 앞의 `C`도 "Class"를 뜻하는 MFC 시대의 관례입니다.

### 4. 함수 본문 ― 위임(delegation)

```cpp
m_pPlatformAPI->ShowPane(frameName, bShow, bRefresh);
```

- `m_pPlatformAPI`: 클래스의 **멤버 변수**입니다. `m_`은 "member", `p`는 "pointer"라는 관례적 접두사 → "포인터 타입 멤버 변수"라는 힌트입니다.
- `->`: **포인터를 통해 멤버에 접근**하는 연산자입니다. `m_pPlatformAPI`가 어떤 객체를 가리키는 포인터이므로, 그 객체의 `ShowPane` 함수를 호출하는 것입니다.
  - 포인터가 아닌 일반 객체라면 `.`을 씁니다: `obj.ShowPane(...)`
- 받은 매개변수 3개를 **그대로 전달**하고 있습니다.

# 추가 1. C++ 함수 기본 문법 정리

## 1-1. 함수의 4요소

```cpp
반환타입  함수이름 ( 매개변수 목록 )  { 본문 }

BSTR     GetTheme (       void      ) { ... return ...; }
```

| 요소 | 의미 | 규칙 |
|---|---|---|
| 반환타입 | 함수가 끝나며 돌려주는 값의 타입 | 없으면 `void` |
| 함수이름 | 호출할 때 쓰는 이름 | 클래스 소속이면 `클래스::이름` |
| 매개변수 | 호출자가 넘겨주는 입력값 | 없으면 `(void)` 또는 `()` |
| 본문 | 실제 실행 코드 | `return 값;`으로 종료(void면 생략 가능) |

## 1-2. 선언(declaration)과 정의(definition)의 분리

C++은 보통 **헤더(.h)에 "이런 함수가 있다"는 선언만** 쓰고, **소스(.cpp)에 실제 구현(정의)**을 씁니다.

```cpp
// ScriptFunction.h ― 선언 (목차 역할)
class CScriptFunction : public CCmdTarget
{
	void Message(LPCTSTR message);      // 세미콜론으로 끝 = 선언만
};

// ScriptFunction.cpp ― 정의 (본문)
void CScriptFunction::Message(LPCTSTR message)   // 클래스이름:: 필수
{
	...
}
```

- `::`(범위 지정 연산자)는 "이 함수가 어느 클래스 소속인지"를 명시합니다.
- `.cpp`에서 어떤 함수를 발견하면 **같은 이름을 `.h`에서 찾아 선언(반환타입·매개변수)을 먼저 확인**하는 습관이 분석의 기본입니다.

## 1-3. 값 전달 vs 포인터 전달

```cpp
void f(int n);        // 값 전달: 복사본을 받음 (원본 안 바뀜)
void f(CString *p);   // 포인터 전달: 주소를 받음 (원본 접근 가능)
void f(CString &r);   // 참조 전달: 별명을 받음 (원본 접근 가능, * 없이 사용)
```

포인터 변수를 쓸 때의 두 연산자:

```cpp
m_pScreenAPI->Alert(...);   // 포인터가 가리키는 객체의 멤버 호출 (->)
obj.Alert(...);             // 일반 객체의 멤버 호출 (.)
```

포인터는 **아무것도 안 가리킬 수 있으므로(NULL)** 쓰기 전에 반드시 검사합니다. 이 파일의 거의 모든 함수에 나오는 패턴입니다:

```cpp
if (m_pScreenAPI)          // NULL이 아니면 (= 화면 API가 꽂혀 있으면)
	m_pScreenAPI->Trace(message);
```

|---|---|---|

## 2-2. 문자열 3종 변환 (이 파일 최다 빈출 패턴)

// LPCTSTR로 받아서 → CString으로 가공 → BSTR로 반환
BSTR CScriptFunction::어떤함수(LPCTSTR input)

## 2-3. 함수 본문의 정형 패턴 (5단계)

이 파일 함수의 90%는 아래 골격의 변형입니다 ([Message() 예시, 1082행](IztScript/ScriptFunction.cpp#L1082)):

```cpp
void CScriptFunction::Message(LPCTSTR message)
{
	CStaticLog::Write(LOG_WORKS, LEVEL_INFO, _T("...시작"));  // ① 로그
	AFX_MANAGE_STATE(AfxGetAppModuleState());                  // ② MFC 상태 전환
	if (m_pScreenAPI)                                          // ③ NULL 가드
		m_pScreenAPI->Message(message, MT_STATUS1);            // ④ 위임(핵심 1줄)
	CStaticLog::Write(LOG_WORKS, LEVEL_INFO, _T("...끝"));    // ⑤ 로그
}
```

- **①⑤ `CStaticLog::Write`**: 파일 로그. `클래스이름::함수(` 없이 호출하는 건 `static` 함수라는 뜻(객체 없이 호출 가능).
- **② `AFX_MANAGE_STATE`**: "지금부터 이 DLL의 MFC 리소스를 쓰겠다"는 DLL 경계 필수 매크로. 의미만 알고 넘어가면 됩니다.
- **③④**: 실제 일은 `m_pScreenAPI`(화면) 또는 `m_pPlatformAPI`(플랫폼)에 위임 ― 어느 쪽인지가 그 함수의 관할을 말해줍니다.

## 2-4. 디스패치 맵 ― 스크립트 이름과 C++ 함수의 연결표

[BEGIN_DISPATCH_MAP](IztScript/ScriptFunction.cpp#L107) 블록이 이 파일의 "전화번호부"입니다:

```cpp
BEGIN_DISPATCH_MAP(CScriptFunction, CCmdTarget)
	// 속성(객체): 스크립트의 System.xxx, Global.xxx가 이것
	DISP_PROPERTY_EX_ID(CScriptFunction, "System", dispidSystem, GetSystem, SetSystem, VT_DISPATCH)
	// 함수: "스크립트이름" → C++함수, 반환타입, 매개변수타입들
	DISP_FUNCTION_ID(CScriptFunction, "ShowPane", dispidShowPane, ShowPane, VT_EMPTY, VTS_BSTR VTS_BOOL VTS_BOOL)
END_DISPATCH_MAP()
```

읽는 법: `DISP_FUNCTION_ID(클래스, "스크립트에서 부르는 이름", 고유번호, 실제 C++ 함수, 반환타입, 매개변수 타입 나열)`

- `VT_EMPTY`=반환 없음, `VT_BSTR`=문자열 반환, `VT_I4`=정수 반환, `VT_DISPATCH`=객체 반환
- `VTS_BSTR VTS_BOOL VTS_BOOL` = "(문자열, 불리언, 불리언) 3개를 받는다" (공백으로 나열, 쉼표 없음)

**분석 순서**: 화면 스크립트에서 함수 이름 발견 → 이 맵에서 검색 → 연결된 C++ 함수 구현부로 이동.

## 2-5. VARIANT 다루기 ― 타입 검사 후 사용

스크립트는 타입이 느슨해서, 아무 값이나 `VARIANT`로 들어옵니다. C++ 쪽은 `.vt`(variant type) 필드로 실제 타입을 확인하고 꺼냅니다:

```cpp
if (vCloseTime.vt == VT_I4)        // 담긴 게 32비트 정수라면
	nTime = vCloseTime.lVal;       // .lVal로 꺼냄
// VT_BSTR이면 .bstrVal, VT_BOOL이면 .boolVal, VT_DISPATCH면 .pdispVal
```
