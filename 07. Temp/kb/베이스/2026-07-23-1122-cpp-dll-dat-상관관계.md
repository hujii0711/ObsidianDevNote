## CPP, DLL, DAT 파일의 상관관계

세 파일은 **소스 코드 → 실행 바이너리 → 데이터**라는 역할 관계로 연결됩니다.

### 1. 각 파일의 역할

| 파일 | 정체 | 역할 |
|------|------|------|
| `.cpp` | C++ 소스 코드 | 사람이 읽고 쓰는 **원본 코드** (텍스트) |
| `.dll` | 컴파일된 바이너리 | cpp를 컴파일/링크해서 만든 **실행 가능한 기계어 코드** |
| `.dat` | 데이터 파일 | 프로그램이 읽거나 쓰는 **데이터** (형식은 프로그램 마음대로) |

### 2. 관계 흐름

```
[개발 단계]
  Function.cpp  ──컴파일──▶  Function.obj  ──링크──▶  Function.dll
  (소스 코드)                 (중간 산출물)              (배포되는 바이너리)

[실행 단계]
  MyApp.exe ──로드──▶ Function.dll ──읽기/쓰기──▶ Config.dat
  (프로그램)          (기능 제공)                  (설정/데이터 저장)
```

- **cpp → dll**: 개발자가 작성한 `.cpp` 소스를 컴파일러(Visual Studio 등)가 컴파일하면 `.dll`이 생성됩니다. 즉 **dll은 cpp의 결과물**입니다. 배포할 때는 cpp 없이 dll만 있으면 동작합니다.
- **dll → dat**: 실행 중인 dll(또는 exe) 코드가 `.dat` 파일을 열어 설정값, 캐시, 저장 데이터 등을 **읽고 씁니다**. dat는 코드가 아니라 **코드가 다루는 재료**입니다.

### 3. 비유하자면

- `.cpp` = **요리 레시피 원고** (사람이 읽는 글)
- `.dll` = **요리사** (레시피대로 훈련된, 실제로 일하는 존재)
- `.dat` = **식재료/재고 장부** (요리사가 사용하는 데이터)

### 4. 실무에서 중요한 점

1. **dat나 dll만 보고 cpp를 복원하기는 어렵습니다** ― 컴파일은 단방향이라, dll을 역컴파일해도 원본 cpp는 나오지 않습니다.
2. **dat 파일의 형식은 표준이 없습니다** ― 그 파일을 만든 프로그램(dll/exe)의 코드가 정의한 구조여야만 해석 가능합니다.
3. **수정 위치가 다릅니다** ― 로직을 바꾸려면 cpp 수정 후 재컴파일해서 dll 교체, 데이터만 바꾸려면 dat만 수정하면 됩니다.
