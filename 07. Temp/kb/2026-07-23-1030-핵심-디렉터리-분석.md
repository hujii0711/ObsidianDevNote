## 1. [Bin/](Bin/) ― 부트스트랩·자동배포·모니터링 (기동의 시작점)

**역할**: 단말 기동 시 가장 먼저 실행되어 서버에서 콘텐츠를 내려받아 나머지 디렉터리를 채우는 계층.

- **에이전트 5종**이 존재하며 exe별 XML 설정으로 구분됩니다 ― [IZTnGiantAgent2.xml](Bin/IZTnGiantAgent2.xml)(운영, `fadapd.kbstar.com`, TCP 29010), PLUS(스테이징, 사내IP `10.38.115.21`, TCP 29110), Dev(개발, TCP 29020), TheK(더케이 브랜드 변형). **접속 서버·포트 대역·로그 플래그** 세 축으로 환경을 격리해 동일 PC에서 동시 실행이 가능한 구조입니다.
- [info.xml](Bin/info.xml) ― **전체 배포 목차** (`totalfile="108632"`, version 2019060404). 서버경로↔로컬경로 매핑을 담고, `SMUpdate2.exe`가 이걸 기준으로 증분 다운로드합니다.
- [TermInfo.ini](Bin/TermInfo.ini) ― 단말 신원(IP/MAC/지점코드/단말번호/그룹사코드 `KB0`).
- `IztMonitoringAgent.exe` ― 단말 상태·버전을 `CAAManagerWEB/mci.do`로 상신하고 [Log/](Log/)에 기록하는 주체 (현재 Log는 비어 있음 = 미기동 스냅샷).
- ※ **발견**: [SMUpdateDev.xml](Bin/SMUpdateDev.xml)에 `AFTERRUN="URL,http://channel.shinhan.com:9011/iWorks/login.jsp"` ― **신한은행 URL 잔존**. Inzent 공용 부트스트랩을 은행별로 복제하며 남은 흔적으로 보입니다.

## 2. [Solution/](Solution/) · [SolutionT/](SolutionT/) ― 화면·거래 메타데이터 저장소 (업무의 실체)

**역할**: 프로그래밍 소스 대신 화면(.scn)·프레임(.frm)·거래(.trn)를 XML로 정의한 로우코드 저장소. **Solution = 운영 배포본, SolutionT = 테스트·샘플 작업본** (SolutionT 화면번호에 `T`가 삽입되고 "복사본" 파일이 존재).

- **`.scn` 화면** (Solution 144개): `<BODY>`에 좌표 기반 컨트롤(Text/Button/Edit/Combo/IBSheet 그리드 등 30여 종) + 말미 `<SCRIPT><![CDATA[...]]>`에 **JavaScript 이벤트 로직 내장**. 라이프사이클은 `OnInitScreen()` → `OnSendKey()` → `OnEndTran()`.
- **`.trn` 거래**: `<TRANSACTION TranClass="TranMCILogin" SvcCode="KJI">` 아래 고정길이 입출력 필드(`<Fld id len>`) 정의. TranClass로 로그인/로그오프/책임자승인(Ovr)/취소 등 처리기 유형을 지정.
- **전문 구조**: [FSIn.xml](Solution/System/Trn/FSIn.xml)이 봉투(envelope) ― `inputCommon`(채널공통헤더) + `inputChannel` + `tranHeader`(거래공통헤더/KYC) + `data`(거래별 본문)를 XPath로 조립한 **XML 기반 MCI 전문**. `*_TOBE.xml`은 차세대 전문 규격 병행 보관본.
- **화면→거래 연결**: 스크립트에서 `SetTranID("KHC0407040")` → `Tran.SetInFDData(필드id, 값)` → `Tran.ASend()` 송신 → `OnEndTran()`에서 `Tran.GetOutFDData()`로 응답을 화면에 바인딩. 거래코드의 앞 3자리(KHC/KFD/KIG/KJI...)가 **업무 서비스코드**입니다.
- [KBFrame.frm](Solution/System/Frame/KBFrame.frm) ― 단말 셸 레이아웃. 속성명이 한글(`가로크기`, `패널영역조정`)이며, 패널에 `JoinScreenNo`로 메인화면을 결합.
- `SYPASSBOOK.prn` ― 통장 물리 인쇄양식(CPI/LPI/여백/이젝트 정의).

## 3. [Config/](Config/) ― 단말의 "두뇌" (환경·업무 구성 메타데이터)

**역할**: UI/장치/네트워크 환경 + 업무 패키지·권한·공통함수를 모두 담는 중심 디렉터리.

- [EnvSetting.xml](Config/EnvSetting.xml) ― 화면 동시오픈 10개, E2E 암호화 ON, 책임자승인 PW SHA256 등 단말 운영 옵션.
- `connection*.ini` ― 통신 세션 정의. `HTTP=Sessionhttp.dll`처럼 **프로토콜이 플러그인 DLL 방식**(HTTP/TCP/SOAP/TMax), 문자셋 MS949. ASIS/TOBE MCI 분리.
- `CommonFunction_*.xml` **약 130개** ― 업무약어(KHC/CAF/ACM/PPR...)별 공통 JavaScript 함수 라이브러리. [CommonFunctionList.xml](Config/CommonFunctionList.xml)이 약어→권한→파일 매핑 인덱스.
- `BzPackage1~15.xml` ― 좌측 업무트리 구성(예금/외환/여신/압류/부동산담보 등 15개 대분류).
- [ActiveXList.xml](Config/ActiveXList.xml) ― 사용 허용 OCX 화이트리스트 약 60종(바코드, 통장스캔, 녹취, CTI, 생체인증 등).
- `IztDevice_type.ini`(장치 선택지 카탈로그, 평문) ↔ `IztDevice.ini`(실제 바인딩 값, **암호화**) 쌍.
- `functionList_개발/스테이징/운영.dat`(실제로는 JSON) ― 환경별 포털 링크. 환경 전환은 `ModeSelect.exe`가 파일 교체하는 방식.

## 4. [iWorks/](iWorks/) · [iWorksD/](iWorksD/) ― 실행 엔진 바이너리

**역할**: 엔진 DLL·업무 OCX가 모인 바이너리 계층. **iWorks = 운영 릴리스, iWorksD = 디버그 빌드**(iWorksD의 DLL들이 Unicode Debug 변종 `...UD.dll`인 것으로 확인).

- **엔진 코어**: `nGiantWorks2.exe`(메인 셸) + `IztScreen/IztScript/IztTran/IztSession/IztCommon.dll` 등 ― 화면 렌더링·스크립트 실행·전문 처리·세션을 각각 담당.
- **기능별 OCX**: IBSheet(그리드), AES/SEED(암호화), OZ Report(리포트), KBFileTransfer(이미지 전송), Record_Mdl(녹취), ContactAgent(CTI), UBIPortal(.NET 기반 KB 메신저 연동) 등.
- [64_KB_단말엔진등록.bat](iWorks/64_KB_단말엔진등록.bat) ― 64bit OS에서 `SysWOW64\regsvr32`로 **32비트 COM 등록**하는 설치 스크립트.

## 4-1. [IztScript/](IztScript/) ― 엔진 스크립트 모듈 소스 ★2026-07-23 신규 추가

**역할**: 위 엔진 코어 중 `IztScript.dll`을 빌드하는 **MFC 기반 C++/COM 소스 프로젝트**. 배포본만 있던 프로젝트에 처음으로 추가된 네이티브 소스입니다.

- [ScriptFunction.cpp](IztScript/ScriptFunction.cpp) (8,778줄) ― 화면 스크립트에 노출되는 **내장함수 실제 구현** (IDL 기준 347개 메서드 / 고유 이름 290개, `Config/Function.xml` 카탈로그의 49개는 일부에 불과)
- [ScriptControl.h](IztScript/ScriptControl.h) ― **MS Script Control(msscript.ocx)** 래퍼: `.scn`의 JScript를 실행하는 호스팅 계층
- `GlobalData/LocalData/LinkData/SystemInfo/UserInfo.cpp` ― 스크립트 전역 Key-Value 저장 객체
- `Image.cpp` + `siFormRecog.lib` ― 이미지 처리·OCR/ICR (네이티브 라이브러리 의존)
- `IztScript.sln`·`.vcxproj` ― VS 빌드 프로젝트, 산출물이 `iWorks\IztScript.dll`
- ※ 나머지 엔진 모듈(`IztScreen`·`IztSession`·`IztTran` 등)의 소스는 여전히 미확보(벤더 보유)

## 5. [Device/](Device/) · [IztDevice/](IztDevice/) · [Data/](Data/) ― 장치 드라이버와 거래 기록

- **Device\DLL** (38개): 통장프린터(`IztPr2.Dll`), 카드발급기 7종(Evolis/TP9000/CE840...), 핀패드 4종, MSR, TWAIN 스캐너, 이미지 코덱(`EZTiff/EZPdf...`). 핵심은 `IztDeviceDll.dll` ― 엔진과 개별 드라이버를 잇는 **장치 추상화 레이어**. 확장자가 .txt인 파일들은 문서가 아니라 **JavaCard 애플릿 바이너리**(IC카드/핀패드 로드용)입니다.
- **IztDevice** ― 인쇄 스풀 작업공간(spooling→printed→return→journal). 현재 비어 있음.
- **Data\Journal** ― 실제 거래 저널: `JourS<단말><일자>.mdb`(**Access DB**) + 일자별 암호화 `.ini` 항목 + `TranSeq*.ini`(거래일련번호 채번). 저널 보존 365일 정책([DefaultSetting.xml](Config/DefaultSetting.xml)).

## 종합: 기동부터 거래까지의 흐름

1. `temp\Start.bat` → `Bin\PWS.exe` 기동 → `SMUpdate2.exe`가 CRC 매니페스트(`DOWN-*.xml`) 비교로 증분 업데이트
2. `iWorks\nGiantWorks2.exe`가 엔진 DLL + OCX 로드, `KBFrame.frm`으로 셸 구성
3. 로그인(`TranMCILogin`) → `UserData`로 개인 UI 복원
4. 업무 선택(BzPackage 트리) → `.scn` 화면 렌더 → `Code\*.dat`로 콤보 채움 → 스크립트가 `Tran.ASend()`로 MCI XML 전문 송수신
5. 인쇄는 `IztDeviceDll.dll`→`Device\DLL` 드라이버, 거래 기록은 `Data\Journal\*.mdb`에 암호화 저장

**참고할 점 2가지**: ① 이 배포본에는 KB 내부 서버 IP·URL이 평문으로 다수 포함되어 있어 민감정보로 취급이 필요하고, ② `Bin\SMUpdateDev.xml`에 신한은행 URL이 잔존해 있어 Dev 부트 시 오설정 소지가 있습니다.

필요하시면 이 내용을 `docs/export`로 저장하거나, 특정 계층(예: MCI 전문 규격, 화면 스크립트 API)을 더 파고들 수 있습니다.
