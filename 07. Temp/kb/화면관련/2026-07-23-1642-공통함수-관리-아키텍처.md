조사를 마쳤습니다. 이 프로젝트(iWorks 프레임워크)의 공통함수 아키텍처는 **"XML 저장소에 스크립트 소스를 선언 → 엔진이 실행 시 화면 스크립트 컨텍스트에 주입"** 하는 구조입니다.

## ① 선언 형식 ― `<node>` + CDATA 스크립트 소스

공통함수는 컴파일된 라이브러리가 아니라 **XML 안에 JScript 소스 그대로** 선언됩니다. `node name`이 함수 시그니처, CDATA가 함수 본문입니다:

```xml
<!-- Config/CommonFunction.xml -->
<FUNCTION>
    <node name="GetCommonBrnName(ctlName1,ctlName2)">
        <contents><![CDATA[/*
        부점코드를 입력하면 부점명을 조회하는 함수
        사용법: GetCommonBrnName(부점코드, 부점명)
        주의사항: 사용하고자 하는 화면에 전행공통의 KJI0481140 트랜을 추가해야함.
        */
        ctlName1.Data = ctlName1.Data.replace(/(^\s*)|(\s*$)/, '');
        if (ctlName1.Data.length == 4) {
            SetTranID("KJI0481140");
            Tran.SetInFDData("KJI0481140","brncd",ctlName1.Data);
            Tran.WaitSend();      // 동기 송신 ― 공통함수 내부에서 완결
            if (Tran.bError == false) {
                ctlName2.Data = Tran.GetOutMultiDataByIndex(
                    "screen","grid/dataBook","brnHanglName","0");
            }
        }
        ...]]></contents>
    </node>
</FUNCTION>
```

주목할 설계 포인트:
- **컨트롤 객체를 인자로 전달** ― `GetCommonBrnName(brncd, brnName)`처럼 화면의 컨트롤 자체를 넘겨서, 공통함수가 어느 화면에서든 `.Data` 읽기/쓰기 가능 (컨트롤명에 비의존)
- **동기 통신 사용** ― 화면 로직은 `Tran.ASend()`(비동기)+`OnEndTran` 콜백이지만, 공통함수는 `Tran.WaitSend()`(동기)+`Tran.GetOutMultiData*()` API로 **함수 내부에서 송수신을 완결**시켜 화면의 `OnEndTran`과 얽히지 않게 함

## ② 스코프 관리 ― CommonFunctionList.xml (인덱스 + 권한)

업무별 공통함수 파일은 [CommonFunctionList.xml](Config/CommonFunctionList.xml)이 **업무코드(SvcCode) 기준으로 로딩 범위를 제어**합니다:

```xml
<node name="KAE" auth="KAE|"          filename="CommonFunction_KAE.xml"/>
<node name="KBC" auth="KBC|KBK|KBJ|KIT|" filename="CommonFunction_KBC.xml"/>
<node name="KBF" auth="KBF|MAD|MAG|MAO|MED|" filename="CommonFunction_KBF.xml"/>
```

- `auth="KBC|KBK|KBJ|KIT|"` → KBC 공통함수 파일은 KBC뿐 아니라 KBK/KBJ/KIT 업무 화면에서도 사용 가능 (파이프 구분 다중 권한)
- 전행 공통([CommonFunction.xml](Config/CommonFunction.xml))은 모든 화면에 무조건 로딩, 업무별 파일은 권한에 맞는 것만 로딩 → **이름 충돌 방지 + 메모리 절약**
- 업무별 함수는 `KAE_getGwamok`, `KAE_callSubPage`처럼 **업무코드 접두어 네이밍 컨벤션**으로 전행 공통과 구분

배포 시에는 [functionList.dat](Config/) (개발/스테이징/운영 3벌)로 컴파일되어 내려갑니다.

## ③ 호출 방식 ― 화면에서는 그냥 함수명으로 호출

엔진(IztScript.dll의 MS Script Control 호스팅)이 공통함수를 화면 스크립트와 **같은 실행 컨텍스트에 주입**하므로, 화면 스크립트에서는 import 선언 없이 바로 호출합니다:

```javascript
// ZPT00000901.scn <SCRIPT> ― 부점코드 입력 검증 이벤트
function brncd_OnValidate() {
    if ((inquryDstic1.Data == "1") && (brnName.Data != "")) {
        GetCommonBrnName(brncd, brnName);   // 전행 공통함수 호출
    }
}
```

## ④ 화면-공통함수 간 계약(Contract) ― 전문(Tran) 등록

통신하는 공통함수를 쓰려면 **화면 쪽 MapInfo에 해당 전문을 등록해야** 합니다. [ZPT00000901.scn](Solution/ZP/Screen/ZPT00000901.scn)의 MapInfo에 실제로 이렇게 선언되어 있습니다:

```xml
<TranID TranId="KJI0481140" TranClass="MCI" SvcCode="KJI" Timeout="120"
        InputFS="FSIn" OutputFS="FSOut">
    <OUTPUT>
        <Device/>    <!-- 매핑 비움: 공통함수가 Tran.GetOutMultiData API로 직접 추출 -->
    </OUTPUT>
</TranID>
```

- INPUT/OUTPUT 매핑을 **비워두는 것**이 특징 ― 자동 바인딩 대신 공통함수 내부에서 `Tran.SetInFDData()`/`Tran.GetOutMultiDataByIndex()`로 직접 넣고 꺼내기 때문
- 이 규약은 강제되지 않고 **주석의 "주의사항"으로만 문서화**되어 있어서, 화면 개발자가 전문 등록을 빠뜨리면 런타임 오류가 나는 느슨한 계약 구조입니다

## 요약

| 계층 | 위치 | 형태 | 관리 방식 |
|------|------|------|----------|
| 엔진 내장함수 | `IztScript/` → `iWorks/IztScript.dll` | C++ COM (290여 개) | 벤더/엔진 빌드 |
| 전행 공통함수 | [Config/CommonFunction.xml](Config/CommonFunction.xml) | XML+CDATA 스크립트 (41개) | 전 화면 자동 로딩 |
| 업무별 공통함수 | `Config/CommonFunction_{업무코드}.xml` | XML+CDATA 스크립트 | [CommonFunctionList.xml](Config/CommonFunctionList.xml)의 `auth`로 스코프 제어 |
| 화면 로컬 함수 | `.scn` 내 `<SCRIPT>` | JScript | 화면 전용 |

핵심은 **"소스 저장소로서의 XML + 권한 기반 선택 로딩 + 동일 스크립트 컨텍스트 주입"**이며, 공통함수가 통신할 때는 화면 MapInfo에 전문 등록이 필요한 암묵적 계약이 있다는 점입니다. 특정 공통함수의 전체 소스나 업무별 파일 내용을 더 보시겠으면 말씀해 주세요.
