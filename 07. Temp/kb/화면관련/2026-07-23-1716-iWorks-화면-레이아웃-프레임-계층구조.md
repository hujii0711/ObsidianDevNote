# iWorks 화면 로딩 시 레이아웃 및 프레임 계층구조

## 1. 큰 그림 ― "프레임(.frm) 껍데기 + 화면(.scn) 조각들의 조립"

iWorks 단말은 화면을 하나의 통짜 UI로 만들지 않습니다. **바깥 골격은 `.frm`(프레임)이 정의하고, 골격의 각 구역(PANE) 안에 독립적인 `.scn`(화면)이 끼워지는 조립식 구조**입니다.

```
nGiantWorks2.exe (메인 윈도우, MDI)
   │  Config.xml → MDI="Y", MainFrame="2"
   │  RTConfig.xml → <Frame><Node id="KBFrame.frm"/>   ← 어떤 프레임을 쓸지 결정
   ▼
KBFrame.frm 로드 (전체 레이아웃 골격, 1140×1044 기준)
   │  TOP / LEFT / RIGHT / BOTTOM / CHILDFRAME / FLOATING 구역별 PANE 생성
   ▼
OnLoadFrame() 스크립트 실행 → 각 PANE의 Panel에 화면번호 바인딩
   │  예: Panel3.Data = "SYTopFrame"  (상단바 화면을 상단 패널에 장착)
   ▼
각 PANE에 SY*.scn 시스템 화면 로드 + 중앙 MDI 영역에 업무화면(.scn) 로드
```

- 어떤 프레임을 쓸지는 [RTConfig.xml](Config/RTConfig.xml)의 `<Frame><Node id="KBFrame.frm"/>`가 결정합니다.
- 메인 윈도우 자체는 **MDI**(Multiple Document Interface)라서 업무화면 여러 개를 탭으로 동시에 띄웁니다 ([MultiFrame.xml](Config/MultiFrame.xml)의 `MDITabShow=Y`, 창구단말 외에 콜센터단말 등 프레임 변형도 여기 정의).

## 2. KBFrame.frm의 구역(섹션) 구조

[KBFrame.frm](Solution/System/Frame/KBFrame.frm)의 XML 최상위 계층은 **위치 기반 섹션**입니다:

```
<FRAME 가로크기=1140 세로크기=1044>
 ├─ <TOP>            상단 고정 영역
 ├─ <LEFT>           좌측 고정 영역
 ├─ <RIGHT>          우측 슬라이드/확장 영역
 ├─ <BOTTOM>         하단 상태바
 ├─ <CHILDFRAME>     중앙 업무화면(MDI 자식) 영역에 덧붙는 부가 패널
 ├─ <FLOATING>       떠 있는 팝업성 패널 (메가메뉴 등)
 ├─ <FLOATING_MINI>  전체메뉴 등 미니 플로팅 패널
 ├─ <DIV>            영역 분할선 좌표 (레이아웃 격자)
 └─ <SCRIPT>         OnLoadFrame() ― 패널↔화면 바인딩
```

각 섹션 안의 계층은 항상 **`PANE` → `CONTROL`(주로 Container Panel) → (임베드된 화면)** 3단입니다.

핵심 메커니즘 두 가지:

1. **JoinScreen 임베딩** ― PANE 안의 `Panel` 컨트롤이 `Container="1" JoinScreen="1"` 속성을 가지면 "다른 화면을 담는 액자"가 됩니다. 디자인타임 기본값은 `JoinScreenNo` 속성이고, 실제로는 프레임 스크립트 `OnLoadFrame()`에서 `패널명.Data = "화면번호"` 대입으로 **런타임에 어떤 .scn을 끼울지 결정**합니다 (KBFrame.frm 맨 아래 `<SCRIPT>` 참조). 즉 프레임의 각 구역도 결국 전부 `.scn` 화면입니다.
2. **화면번호로 참조** ― 바인딩 값은 파일 경로가 아니라 화면번호(`SYTopFrame`, `KAE04101101` 등)입니다. 시스템 프레임용 화면들은 [Solution/System/Screen/](Solution/System/Screen/)에, 업무화면은 각 업무 폴더에 있습니다.

## 4. 업무화면(.scn) 내부의 계층구조

중앙 작업영역에 로드되는 개별 화면의 구조 (예: [ZPK00000010.scn](Solution/ZP/Screen/ZPK00000010.scn) ― 표준 단일입력형 템플릿):

```
<SCREEN InheritMode="0">
 ├─ <MENU/>                          화면 자체 메뉴 (거의 미사용)
 ├─ <BODY ScreenNo="ZPK00000010"     화면번호(=식별자)
 │        ScreenType="AType"          화면 유형
 │        ScreenX="1075" ScreenY="700" 화면 크기 ← 중앙 작업영역 크기와 일치
 │        CustomClass="Kes">          C++ 쪽 커스텀 클래스 연결(IztCustomKB.dll)
 │   ├─ <COMMON>                     공통버튼(CommonButton1~8) 설정
 │   │     예: CommonButton1 Caption="실행" ← 프레임이 제공하는 공통 실행버튼 제어
 │   ├─ <CONTROL CType="GroupBox" Container="1">   컨트롤 트리 (Container 중첩)
 │   │     └─ <CONTROL CType="Edit"/> <CONTROL CType="Grid"/> ...
 │   └─ <SCRIPT><![CDATA[ JScript ]]></SCRIPT>     화면 이벤트/업무 로직
 └─
```

- 컨트롤 계층은 `Container="1"`인 컨트롤(Panel, GroupBox, TAB→TABPAGE)이 자식 `<CONTROL>`을 중첩 포함하는 트리입니다. 프레임 쪽도 동일한 문법입니다 (예: LeftExtendFrame의 `TAB → TABPAGE → MenuTab → TABPAGE` 4단 중첩).
- `<COMMON>`의 CommonButton은 화면 안에 있는 버튼이 아니라 **프레임이 제공하는 공통 버튼영역을 화면이 선언적으로 제어**하는 부분입니다. 시스템 화면([SY-InternalTop.scn](Solution/System/Screen/SY-InternalTop.scn))은 전부 `Visible="0"`, 업무화면은 "실행" 등을 켭니다.
- `CustomClass` 속성으로 XML 화면과 C++ 커스텀 동작 클래스([RTConfig.xml](Config/RTConfig.xml)의 `IztCustomKB.dll`)가 연결됩니다.

## 5. 로딩 시퀀스 정리

1. **기동**: `nGiantWorks2.exe` 실행 → [Config.xml](Config.xml)(환경: DEV/Test/Real, MDI 여부) → [Config/RTConfig.xml](Config/RTConfig.xml)에서 프레임 파일(`KBFrame.frm`)과 커스텀 DLL 결정
2. **프레임 구축**: `.frm` 파싱 → TOP/LEFT/RIGHT/BOTTOM/FLOATING의 PANE·컨트롤 생성 (아직 빈 골격)
3. **`OnLoadFrame()` 실행**: 각 컨테이너 Panel의 `.Data`에 화면번호 대입 → 해당 `.scn`들이 각 구역에 로드되고, 각 화면의 자체 `<SCRIPT>` 로드 이벤트가 돌면서 메뉴트리·상태바·고객정보 등이 채워짐
4. **업무화면 오픈**: 로그인([SYLoginPage.scn](Solution/System/Screen/SYLoginPage.scn)) 후 시작화면([SY-StartS.scn](Solution/System/Screen/SY-StartS.scn)) → 메뉴 선택 시 [Solution.xml](Config/Solution.xml)의 메뉴트리(`ScnNo` → 화면번호)로 해당 `.scn`을 **중앙 MDI 자식창**으로 로드 (여러 개가 탭으로 공존)
5. **런타임 제어**: 이후 각 PANE의 표시/숨김은 스크립트 내장함수로 제어 ― [ScriptFunction.h:566](IztScript/ScriptFunction.h#L566)의 `ShowPane(frameName, bShow, bRefresh)`(PANE ID를 이름으로 지정), `ShowPortlet`(우측 슬라이드 패널), `ScreenCloseAndOpen`(화면 전환) 등이 `m_pPlatformAPI`를 통해 프레임 엔진(IztScreen.dll 계열)에 위임됩니다.

## 6. 한 줄 요약

**"메인 MDI 윈도우 → KBFrame.frm(구역별 PANE 골격) → 각 PANE의 Container Panel → 거기 임베드된 SY*.scn 시스템 화면들 + 중앙 MDI 영역의 업무 .scn"** 이라는 4단 계층이며, 프레임과 화면의 연결고리는 `Panel.Data = "화면번호"`(JoinScreen), 런타임 표시 제어는 `ShowPane`/`ShowPortlet` 계열 내장함수입니다. 웹으로 치면 `.frm`은 상단바·사이드바가 있는 레이아웃 템플릿, 각 PANE은 `<iframe>`, `.scn`은 그 안에 로드되는 개별 페이지에 해당합니다.

원하시면 이 내용을 기존 형식대로 [docs/export/](docs/export/)에 정리해 드리거나, 특정 부분(예: `ShowPane`/`ShowPortlet`의 동작 차이, SYTopFrame 내부 구조)을 더 깊게 파볼 수 있습니다.
