[ZPT00000901.scn](Solution/ZP/Screen/ZPT00000901.scn) (섭외정보 일괄등록 화면)을 예시로 서버 통신 데이터 처리 로직을 설명드리겠습니다. (.scn 파일은 EUC-KR 인코딩이라 변환해서 분석했습니다.)

## .scn 화면의 서버 통신 구조

.scn 파일은 XML 기반이며 서버 통신 관점에서 3개 영역으로 구성됩니다:

```
<SCREEN>
 ├─ <BODY>     : 화면 컨트롤 정의 (Edit, Grid, Combo 등)
 ├─ <MapInfo>  : 전문(트랜잭션) 정의 ― 컨트롤 ↔ 전문필드 매핑
 └─ <SCRIPT>   : 이벤트 스크립트 ― 전문 송신/수신 처리
</SCREEN>
```

### ① MapInfo ― 전문 정의 및 필드 매핑 ([ZPT00000901.scn:303-407](Solution/ZP/Screen/ZPT00000901.scn#L303-L407))

`TranID` 단위로 서버 전문을 선언하고, INPUT(송신)/OUTPUT(수신) 필드를 화면 컨트롤에 매핑합니다:

```xml
<TranID TranId="KAA0495841" TranClass="MCI" SvcCode="KAA" Timeout="120"
        InputFS="FSIn" OutputFS="FSOut">
    <INPUT>   <!-- 송신: 화면 컨트롤 → 전문 필드 -->
        <Item TranItem="inquryDstic" CtrlId="inquryDstic" Type="Edit" Len="1"/>
        <Item TranItem="mgtbrn"      CtrlId="brncd"       Type="Edit" Len="4"/>
        <Item TranItem="mgtEmpid"    CtrlId="empid"       Type="Edit" Len="7"/>
        <Item TranItem="nextKey"     CtrlId="nextKey"     Type="Edit" Len="100"/>
    </INPUT>
    <OUTPUT>  <!-- 수신: 전문 필드 → 화면 컨트롤 -->
        <Device Device="screen(KAE00001000)" FormID="KAE00001000">
            <Item TranItem="custLstHist/dataBook" CtrlId="GRID1" Type="Multi">
                <Item TranItem="custIdnfr"    CtrlId="custIdnfr"    Len="10"/>
                <Item TranItem="dtalsCustnm1" CtrlId="dtalsCustnm1" Len="52"/>
                ...
            </Item>
            <Item TranItem="custLstHist/nextKey" CtrlId="nextKey" Len="100"/>
        </Device>
    </OUTPUT>
</TranID>
```

- **TranClass="MCI"**: MCI(대외계 인터페이스) 채널을 통해 서버와 통신
- **Type="Multi"**: 반복부(occurs) 데이터를 그리드에 자동 바인딩
- 개발자가 데이터 파싱 코드를 안 짜도, 프레임워크가 매핑 정의대로 **자동 송수신 바인딩**

이 화면에는 총 6개의 전문이 정의되어 있습니다: `KAA0495841`(고객목록조회), `KAA0495442`(고객번호확인), `KAE0000101`(조회등록), `KAE0000102`(파일등록) 등.

### ② 송신 ― SetTranID() + Tran.ASend() ([ZPT00000901.scn:562-587](Solution/ZP/Screen/ZPT00000901.scn#L562-L587))

```javascript
// [조회] 버튼 클릭
function Button3_OnClick(){
    TabClear();
    if( inquryDstic1.Data != "3" ) {
        GRID1.Trantype = 0;          // 그리드 조회모드
        nextKey.Clear();             // 페이지키 초기화
        inquryDstic.Data = inquryDstic1.Data;

        SetTranID("KAA0495841");     // 사용할 전문ID 지정 (MapInfo의 TranID)
        Tran.ASend();                // 비동기 송신 ― INPUT 매핑대로 자동 조립
    }
}

// 그리드 페이징 ― nextKey 기반 연속조회
function GRID1_OnPageChange(Arg1, Arg2){
    nextKey.Data = GRID1.NextKey(); // 이전 응답의 nextKey를 다시 송신
    SetTranID("KAA0495841");
    Tran.ASend();
}
```

등록 처리에서는 대량 데이터를 **10건 단위로 분할 송신**하는 패턴도 사용됩니다 ([ZPT00000901.scn:816-843](Solution/ZP/Screen/ZPT00000901.scn#L816-L843)):

```javascript
for( var i=1; rowCount>=i ; i++ ) {

```

### ③ 수신 ― OnEndTran() 콜백 ([ZPT00000901.scn:638-697](Solution/ZP/Screen/ZPT00000901.scn#L638-L697))

응답이 도착하면 프레임워크가 OUTPUT 매핑대로 컨트롤/그리드에 데이터를 채운 뒤 `OnEndTran()`을 호출합니다:

```javascript
function OnEndTran(){
    if( Tran.ID == "KAE0000101" || Tran.ID == "KAE0000102" ) {  // 어떤 전문의 응답인지 구분
        if( tran.bError == 0 ) {                                 // 거래 성공 여부
            var rowCount = GRID3.RowCount;
            if( processCnt.Value == rowCount ) {
                Alert("일괄등록을 완료하였습니다.","처리결과");
                GroupBox2.Clear();
                tchsYmd.Data = User.tranBaseYmd;   // 화면 초기화
            }
        }
        else {
            Alert("일괄등록이 실패하였습니다.","처리결과");
        }
    }
}
```

## 전체 흐름 요약

```
[사용자] 조회버튼 클릭
    │
    ▼
Button3_OnClick()
    ├─ 입력값 검증 (SetCheckInput)
    ├─ SetTranID("KAA0495841")        ← 전문 선택
    └─ Tran.ASend()                   ← 비동기 송신
            │
            ▼  프레임워크가 <INPUT> 매핑대로 전문 조립
       [MCI 서버]  ── 업무처리 ──▶ 응답 전문
            │
            ▼  프레임워크가 <OUTPUT> 매핑대로 GRID1/컨트롤에 자동 바인딩
OnEndTran()
    ├─ Tran.ID 로 응답 전문 판별
    ├─ Tran.bError 로 성공/실패 분기
    └─ 후처리 (Alert, 그리드 페이징용 nextKey 저장 등)
```

핵심 특징은 **선언적 매핑**입니다 ― 스크립트는 "언제 어떤 전문을 보낼지"와 "응답 후 무엇을 할지"만 기술하고, 실제 데이터의 전문 조립/파싱/바인딩은 `MapInfo` 정의에 따라 프레임워크가 처리합니다. 더 복잡한 예시(대형 화면 [ZPK00000201.scn](Solution/ZP/Screen/ZPK00000201.scn), 624KB)나 특정 화면의 분석이 필요하시면 말씀해 주세요.
