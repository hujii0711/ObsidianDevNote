플랜 모드가 해제되었고 조사도 완료됐습니다. `IztScript/` 디렉터리 분석 결과를 정리합니다.

# IztScript/ 디렉터리 분석 ― 파일별 역할과 연관관계

## 0. 한 줄 요약

`iWorks\IztScript.dll`을 빌드하는 **MFC 기반 COM 오토메이션 DLL 프로젝트**로, ① DLL 골격 ② COM 계약(IDL) ③ 내장함수 구현 ④ 스크립트 전역객체 5종 ⑤ 이미지/OCR ⑥ 엑셀 연동의 6개 그룹으로 구성됩니다. 단, **핵심 헤더 다수가 형제 프로젝트 참조라서 이 디렉터리 단독으로는 빌드 불가**합니다.

## 1. 파일별 역할

### ① DLL 골격 (MFC 보일러플레이트)
| 파일                                                                              | 역할                                                                                                                                                                                                                                             |
| ------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [IztScript.h](IztScript/IztScript.h) / [IztScript.cpp](IztScript/IztScript.cpp) | `CScriptApp : CWinApp` ― DLL 진입점. `DllRegisterServer` 등 COM 자기등록 4종, 타입라이브러리 GUID(`{70E9D726-...}`) 등록. 특이점: [_purecall 핸들러](IztScript/IztScript.cpp#L47)를 재정의해 **순수가상 호출 장애 시 호스트 메인윈도우에 `WM_APPEXITINSTANCE`를 보내 단말을 안전 종료**시키는 금융단말다운 방어 코드 |
| [IztScript.def](IztScript/IztScript.def)                                        | DLL 익스포트 목록 (COM 표준 4함수)                                                                                                                                                                                                                       |
| [stdafx.h](IztScript/stdafx.h)                                                  | MFC 전체 헤더 + **`#import "IztScript.tlb"`** ― 자기 자신의 타입라이브러리를 임포트해 `LIBID_IztScript`, `DIID_IGlobalData` 등을 사용. `_IZT_EXT_CLASS`(dllexport) 매크로 정의                                                                                               |
| Resource.h / Script.rc / res/Script.rc2                                         | 리소스·버전 정보                                                                                                                                                                                                                                      |
| [version.ver](IztScript/version.ver)                                            | 버전 **2.175.2020.0217**                                                                                                                                                                                                                         |

### ② COM 계약 ― [IztScript.idl](IztScript/IztScript.idl) (이 프로젝트의 "정본 명세")
`library IztScript` 안에 **7개 dispinterface + 6개 coclass** 정의:
- `IScriptFunction` ― 속성 9개(`System`/`User`/`Global`/`Link`/`Tran`/`Scanner`/`Image`/`Device`/`Local`) + **메서드 347개** (id 10 `Alert`부터 id 315 상수까지)
- `IScriptVar`, `ISystemInfo`, `IUserInfo`, `IGlobalData`, `ILinkData`, `ILocalData`, `IImage`
- MIDL 컴파일 → `IztScript.tlb`(+`IztScript_i.c`) 생성 → stdafx.h가 임포트하는 순환 구조

### ③ 핵심 구현 ― [ScriptFunction.cpp](IztScript/ScriptFunction.cpp) (8,778줄) / [ScriptFunction.h](IztScript/ScriptFunction.h)
- `CScriptFunction : CCmdTarget` ― **내장함수 290개(DISP_FUNCTION 338 매핑)의 실제 구현체**. [DISPATCH_MAP(107행~)](IztScript/ScriptFunction.cpp#L107)이 "스크립트 함수명 → dispid → C++ 멤버함수"를 바인딩
- `SCRIPT_GLOBAL_FUNCTION = "_ScriptFunction"` 이름으로 JScript 엔진에 전역 주입됨
- **구현 패턴** (Alert·ScreenOpen에서 확인): `CStaticLog` 로깅 → `AFX_MANAGE_STATE` → 인자/옵션 파싱(예: ScreenOpen의 `AUTOSEND|DATALINK|NEW|CLOSEANDOPEN` 플래그) → **호스트 엔진 인터페이스로 위임**
- 위임 대상 (호스트가 `SetAPI()`/`SetPlatform()`으로 주입):
  - `IIztScreenAPI* m_pScreenAPI` ― **190회 호출** (화면 제어)
  - `IIztPlatformAPI* m_pPlatformAPI` ― **282회 호출** (플랫폼 기능)
  - `IDispatch* m_pTran` ― 거래(전문) 객체 (IztTran.dll 쪽)

### ④ 스크립트 전역 데이터 객체 5종 (완전히 동일한 패턴)
| 파일               | 스크립트 이름  | 역할                                    |
| ---------------- | -------- | ------------------------------------- |
| SystemInfo.h/cpp | `System` | 시스템 정보                                |
| UserInfo.h/cpp   | `User`   | 사용자(텔러) 정보                            |
| GlobalData.h/cpp | `Global` | 전역 데이터 (유일하게 `_IZT_EXT_CLASS` export) |
| LinkData.h/cpp   | `Link`   | 화면 간 데이터 전달                           |
| LocalData.h/cpp  | `Local`  | 화면 로컬 데이터                             |

5개 모두 `class CXxx : public CScriptVar, public CCmdTarget` 다중상속이고 **DISPATCH_MAP이 비어 있음** ― 즉 `Global.아무이름 = 값` 같은 **동적 프로퍼티(expando) 기능은 전부 부모 `CScriptVar`(외부 파일)가 IDispatch 레벨에서 처리**하고, 이 파일들은 "이름(`"Global"` 등)과 DIID만 바꿔 끼운 껍데기"입니다.

### ⑤ 이미지/OCR ― [Image.h](IztScript/Image.h) / [Image.cpp](IztScript/Image.cpp)
- `CImage : CCmdTarget` ― `Rotate/Deskew/Cut/Merge/Add/Splite/OCR/ICR` 8개 메서드 (스크립트의 `Image.*`)
- [siImgProc_vc.h](IztScript/siImgProc_vc.h)+`siImgProc.lib`(이미지 처리), [siFormRecog_vc.h](IztScript/siFormRecog_vc.h)+`siFormRecog.lib`(OCR/필기인식) ― 3rd-party 정적 라이브러리
- ※ **주의**: 현재 소스에서 `siImageRotate()` 등 실제 si* 호출부가 **전부 주석 처리**되어 있어, 이 버전의 Image 기능은 사실상 무력화 상태(또는 다른 경로로 대체)로 보입니다

### ⑥ 엑셀 연동 ― [IztExcell.h](IztScript/IztExcell.h) / [IztExcell.c](IztScript/IztExcell.c)
- MIDL 자동생성물 ― **외부 VB6 COM 컴포넌트 `IztExcelClass`의 CLSID/IID 정의**만 담음. `ScriptFunction.cpp`의 `ExcelReport*` 계열이 이 CLSID로 VB6 DLL을 호출(그리드→엑셀 붙여넣기), Office 오토메이션(`excel8.h`)과 병행

### ⑦ 스크립트 엔진 래퍼 ― [ScriptControl.h](IztScript/ScriptControl.h)
- **MS Script Control(msscript.ocx, `CLSID_ScriptControl`)** 의 `COleDispatchDriver` 래퍼 (`Eval`, `ScriptRun`, Procedures 열거)
- 이 프로젝트 내 cpp에서는 사용처가 없음 → **호스트(IztScreen/PowerWorks 쪽)가 쓰는 공용 헤더**가 들어온 것. JScript 실행은 호스트가 담당하고, 이 DLL은 "엔진에 꽂히는 객체"만 제공한다는 구조적 증거

### ⑧ 빌드 시스템
- [IztScript.sln](IztScript/IztScript.sln) / [IztScript.vcxproj](IztScript/IztScript.vcxproj)(2025-01 갱신) / IztScript.vcproj(VS2005 구버전) / .filters
- **OutDir이 `..\Inzent\iWorks\`(Release), `..\Inzent\iWorksD\`(Debug)** ― 빌드하면 곧바로 배포 폴더에 `IztScript.dll`이 떨어지는 구조. `C:\MYSTAR+\dev\iWorks\` 경로도 존재(개발 PC 표준 경로)

## 2. 파일 간 연관관계

```
[빌드 타임]
IztScript.idl ──MIDL──▶ IztScript.tlb + IztScript_i.c(중간폴더)
                              │ #import (stdafx.h)
                              ▼  LIBID/DIID 상수 공급
     ┌────────────────────────┴───────────────────────┐
     │              모든 .cpp가 stdafx.h 사용            │
     └────────────────────────────────────────────────┘

[런타임 객체 그래프]
호스트(nGiantWorks2.exe + IztScreen.dll)
  │ 생성 + SetAPI(IIztScreenAPI, Tran) / SetPlatform(IIztPlatformAPI)
  ▼
CScriptFunction ("_ScriptFunction"로 JScript 전역 주입)  [ScriptFunction.cpp]
  ├─ 속성 System → CSystemInfo ┐
  ├─ 속성 User   → CUserInfo   │  모두 CScriptVar(외부) 상속
  ├─ 속성 Global → CGlobalData │  = 동적 K-V 저장소 (파일은 껍데기)
  ├─ 속성 Link   → CLinkData   │
  ├─ 속성 Local  → CLocalData  ┘
  ├─ 속성 Image  → CImage ──▶ siImgProc.lib / siFormRecog.lib (호출부는 주석화)
  ├─ 속성 Tran   → 외부 IztTran.dll의 IDispatch (주입받음)
  ├─ 속성 Device → 외부 장치 객체 (주입받음, 구현은 Device.h=외부)
  ├─ 화면 제어 190회 ──▶ IIztScreenAPI   (호스트 구현)
  ├─ 플랫폼 기능 282회 ─▶ IIztPlatformAPI (호스트 구현)
  └─ 엑셀 출력 ──▶ IztExcelClass(VB6 COM, IztExcell.h/c의 CLSID) + excel8.h

[호출 경로 예시]  .scn 스크립트 Alert("메시지","제목")
  → JScript 엔진 → IDispatch::Invoke(dispid 10)
  → DISPATCH_MAP 매핑 → CScriptFunction::Alert()
  → CStaticLog 기록 → 커스텀 메시지박스 표시
```

## 3. 중요한 발견 ― 외부 의존성 (이 디렉터리에 **없는** 파일들)

소스가 참조하지만 미포함이라 **단독 빌드가 불가능**합니다:

| 누락 파일                                                      | 제공해야 할 것                                   | 추정 출처                                 |
| ---------------------------------------------------------- | ------------------------------------------ | ------------------------------------- |
| `ScriptVar.h` (`CScriptVar`)                               | Global/Local 등 5개 객체의 **expando 저장 핵심 구현** | 공용 include (`../include_` 또는 IztUtil) |
| `platformAPI.h` (`IIztPlatformAPI`, `IIztScreenAPI`)       | 호스트 엔진과의 **계약 인터페이스** (472회 호출 대상)         | 엔진 공용 헤더                              |
| `Device.h`, `IztControls.h`, `IztTrans.h`, `eventdef.h`    | 장치·컨트롤·거래 연동                               | 형제 프로젝트                               |
| `../IztUtil/` (Utility, StaticLog, json, DrawUtil, DirMgr) | 로깅·유틸리티                                    | **IztUtil 프로젝트** (미확보)                |
| `../../IztControl/excel8.h`                                | Office 오토메이션                               | **IztControl 프로젝트** (미확보)             |

경로 패턴(`..\..\IztUtil\`, `..\Inzent\iWorks\`)으로 볼 때 원래 소스 트리는 `<루트>\IztScript`, `<루트>\IztUtil`, `<루트>\IztControl`, `<루트>\Inzent\iWorks`(배포)가 나란히 있는 **멀티 프로젝트 솔루션의 한 조각**만 넘어온 것입니다.

## 4. 유지보수 이력 단서

- `ScriptFunction.cpp/h`, `IztScript.idl` 수정일 **2025-06-09** (최근까지 활발히 유지보수)
- 주석 서명: `[SMJ] 2023~2024`(단말화면 개선 TFT, POS프린터), `zino 2009`, `yani 2009`, `leen 2007` ― 약 18년에 걸친 증분 개발

---

**JS 변환 플랜과의 연결**: 변환 시 정본 시그니처는 `IztScript.idl`, 동작은 `ScriptFunction.cpp`에서 확인하면 되지만, **동작의 절반 이상(472회 호출)은 이 DLL이 아니라 호스트의 `IIztScreenAPI`/`IIztPlatformAPI` 구현에 있으므로**, 그 인터페이스 정의(`platformAPI.h`)를 추가 확보하면 분석 정확도가 크게 올라갑니다.

이 분석을 `/export-last`로 저장하시거나, 특정 파일(예: `ScriptFunction.cpp`의 특정 함수군)을 더 깊이 파볼 수 있습니다.
