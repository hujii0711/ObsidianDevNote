조사를 마쳤습니다. iWorks **엔진 내장함수**(`SetTranID`, `Alert`, `Tran.*` 등)는 공통함수(XML 스크립트)와 달리 **MFC/C++ COM Automation(IDispatch) 기반으로 구현되어 DLL로 배포**되는 구조입니다.

## 전체 아키텍처

```
[IztScript/ 소스 프로젝트 (MFC Regular DLL + COM)]
    │
    ├─ ScriptFunction.h/.cpp ── 내장함수 본체 (CScriptFunction, 347개 메서드)
    ├─ IztScript.idl ────────── COM 타입 라이브러리 정의 (정본 카탈로그)
    ├─ SystemInfo / UserInfo / GlobalData / LinkData / LocalData / Image
    │                └───────── 하위 객체들 (System.*, User.*, Global.* …)
    └─ ScriptControl.h ──────── MS Script Control(msscript.ocx) 호스팅 래퍼
    │
    ▼ 빌드 (MIDL → Script.tlb, 링크 → DLL)
iWorks/IztScript.dll  (버전 2.175.2020.0217 ― version.ver)
    │
    ▼ 런타임: CScriptControl.AddObject("_ScriptFunction", pDisp, AddMembers=TRUE)
.scn 화면 스크립트(JScript) 전역 네임스페이스에 주입
    → 화면에서 SetTranID("..."), Alert(...), User.empid 등 접두어 없이 호출
```

## ② 계층형 객체 모델 ― 전역함수 + 하위 객체

`CScriptFunction`은 **파사드(Facade)** 역할이며, 도메인별 기능은 별도 dispatch 클래스로 분리되어 **속성(property)으로 노출**됩니다:

```cpp
BEGIN_DISPATCH_MAP(CScriptFunction, CCmdTarget)
    DISP_PROPERTY_EX_ID(CScriptFunction, "System", dispidSystem, GetSystem, ..., VT_DISPATCH)
    DISP_PROPERTY_EX_ID(CScriptFunction, "User",   dispidUser,   ...)  // → UserInfo.cpp
    DISP_PROPERTY_EX_ID(CScriptFunction, "Global", dispidGlobal, ...)  // → GlobalData.cpp
    DISP_PROPERTY_EX_ID(CScriptFunction, "Link",   dispidLink,   ...)  // → LinkData.cpp
    DISP_PROPERTY_EX_ID(CScriptFunction, "Tran",   dispidTran,   ...)  // → IztTran.dll (외부)
    DISP_PROPERTY_EX_ID(CScriptFunction, "Image",  dispidImage,  ...)  // → Image.cpp (OCR/ICR)
    DISP_PROPERTY_EX_ID(CScriptFunction, "Local",  dispidLocal,  ...)  // → LocalData.cpp
    // 상수도 읽기전용 속성으로 노출 (SetNotSupported)
    DISP_PROPERTY_EX_ID(CScriptFunction, "CONST_SB_PAGEUP", ..., GetConstantScrollBarPageUp, SetNotSupported, VT_I4)
```

화면 스크립트에서 `User.empid`, `Tran.ASend()`, `Link.brncd`로 쓰이는 것이 바로 이 구조입니다. 앞서 본 `ZPT00000901.scn`의 `User.userBzwkBrncd`, `Tran.bError`가 모두 여기서 나옵니다.

## ③ 스크립트 노출 ― MS Script Control 호스팅 + 전역 주입

[ScriptControl.h](IztScript/ScriptControl.h)는 `msscript.ocx`(MS Script Control)의 `COleDispatchDriver` 래퍼입니다:

```cpp
#import "msscript.ocx" no_namespace
class CScriptControl : public COleDispatchDriver {
    void AddObject(LPCTSTR Name, LPDISPATCH Object, BOOL AddMembers);  // 객체 주입
    void AddCode(LPCTSTR Code);      // .scn <SCRIPT> + 공통함수 소스 로딩
    VARIANT Run(ProcedureName, ...); // 이벤트 함수 실행 (Button3_OnClick 등)
    VARIANT Eval(Expression);
};
```

핵심은 `AddObject("_ScriptFunction", ..., **AddMembers=TRUE**)`입니다 ([ScriptFunction.h:13](IztScript/ScriptFunction.h#L13)의 `SCRIPT_GLOBAL_FUNCTION`) ― AddMembers=TRUE면 객체의 **멤버들이 스크립트 전역 이름**이 되므로, 화면에서 `_ScriptFunction.SetTranID()`가 아니라 그냥 `SetTranID()`로 호출할 수 있습니다.

## ④ 모듈 간 위임 ― 내장함수는 "게이트웨이"

`CScriptFunction`은 실제 로직을 직접 갖지 않고 인터페이스로 **다른 엔진 모듈에 위임**합니다:

```cpp
private:
    IIztScreenAPI   *m_pScreenAPI;    // → IztScreen.dll (화면/컨트롤, 벤더 바이너리)
    IIztPlatformAPI *m_pPlatformAPI;  // → 플랫폼 모듈
    IDispatch       *m_pTran;         // → IztTran.dll (전문 통신)
public:
    void SetAPI(IIztScreenAPI *pApi, LPDISPATCH pTran);  // CScreenDoc(friend)가 화면 생성 시 주입
```

즉 **스크립트 ↔ C++ 엔진 사이의 어댑터 계층**이며, 화면별로 `CScreenDoc`이 자기 화면의 API 포인터를 꽂아주는 인스턴스 단위 바인딩입니다.

## ⑤ 관리 체계

| 관리 항목 | 방식 |
|-----------|------|
| **ID 채번** | DISPID enum에 **역순 append-only** (최신이 맨 위, 344까지). 삭제/재사용 없이 작성자·날짜 주석으로 이력 관리 (`// KJM 2026.06.08 ...`) |
| **정본 목록** | [IztScript.idl](IztScript/IztScript.idl) (347개 메서드) ― `helpstring`이 공식 설명 |
| **에디터 카탈로그** | [Config/Function.xml](Config/Function.xml) ― 화면 에디터 자동완성/도움말용 (49개만 등록, 실제의 일부) |
| **버전** | [version.ver](IztScript/version.ver) (`2.175.2020.0217`) ― 리소스에 반영 |
| **배포** | 빌드 → [iWorks/IztScript.dll](iWorks/) 교체. [IztScript.def](IztScript/IztScript.def)로 COM 표준 진입점(`DllRegisterServer` 등)만 export ― **개별 함수는 export하지 않고 전부 IDispatch로만 노출** |

## 공통함수(XML)와의 대비

| | 내장함수 | 공통함수 |
|---|---|---|
| 구현 언어 | C++ (MFC/COM) | JScript |
| 저장 위치 | `IztScript/` 소스 → DLL | `Config/CommonFunction*.xml` |
| 추가 절차 | 4곳 선언 + DLL 빌드/배포 | XML에 `<node>` 추가 (무배포 반영) |
| 호출 메커니즘 | IDispatch (COM 늦은 바인딩) | 같은 스크립트 컨텍스트에 소스 주입 |
| 용도 | 화면/전문/장치 등 엔진 기능 접근 | 업무 로직 재사용 |

정리하면, **"IDL+DISPID+디스패치맵 3중 선언으로 계약을 고정하고, MS Script Control에 전역 객체로 주입해 스크립트에서 접두어 없이 쓰게 하는 COM Automation 아키텍처"**입니다. 특정 내장함수의 구현 코드나 하위 객체(Tran, Image 등)를 더 깊이 보시겠으면 말씀해 주세요.
