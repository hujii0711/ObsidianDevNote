## iWorks 관련 디렉터리 정리 및 연관성

`c:\Inzent`는 사실상 전체가 iWorks 단말 시스템의 설치 루트이며, 각 디렉터리는 다음과 같이 연결됩니다.

### 연관성 흐름

1. **설치/업데이트**: `Bin\`의 에이전트(`IZTnGiantAgent2.exe`, `SMUpdate2.exe`)가 [IztnGiant.xml](IztnGiant.xml) 매니페스트를 읽어 KB 서버(`fadapd.kbstar.com`)에서 파일을 받아 `iWorks\` 등에 배포합니다. 매니페스트에 `PATH="iWorks/inzent/"`, `INFO="Bin/,$$\Bin\"` 형태로 **소스경로→설치경로 매핑**이 명시돼 있습니다.

2. **실행**: `iWorks\PowerWorks.exe`(또는 `nGiantWorks2.exe`)가 기동하면서
   - `iWorks\IztScript.dll` 로드 → JScript 엔진에 **내장함수** 노출 (이 DLL의 소스가 `IztScript\`)
   - `Config\Solution.xml` 로드 → 메뉴/화면 트리 구성
   - `Config\CommonFunction*.xml` 로드 → 업무 공통 JS 함수 등록

3. **화면 표시**: 사용자가 메뉴 선택 → `Solution\<업무>\Screen\*.scn` 파일을 읽어 컨트롤 배치 + `<SCRIPT>` CDATA의 JScript 실행 → 스크립트가 내장함수(`Alert` 등)와 공통함수를 호출

4. **주변 자원**: 스크립트/모듈이 실행 중에 `Code\`(코드테이블), `Image\`·`Sound\`(리소스), `Device\DLL\`(핀패드·스캐너 드라이버), `IztDevice\`(전표/인쇄 스풀), `UserData\`·`Data\`(데이터), `Log\`(로그)를 사용합니다.

### 운영 vs 개발/테스트 짝 구조

| 운영              | 개발/테스트             | 내용       |
| --------------- | ------------------ | -------- |
| `iWorks\`       | `iWorksD\`         | 런타임 바이너리 |
| `Solution\`     | `SolutionT\`       | 화면(.scn) |
| `IztnGiant.xml` | `IztnGiantDev.xml` | 배포 매니페스트 |

또한 **바이너리 ↔ 소스 짝**이 하나 생겼습니다: `iWorks\IztScript.dll`(배포 바이너리) ↔ `IztScript\`(MFC/C++ 소스).

즉, **내장함수 변환 작업의 관점**에서 직접 관련된 곳은 `IztScript\`(구현 소스 ★정본), `iWorks\IztScript.dll`(빌드 산출물), `Config\Function.xml`(명세 카탈로그·일부만 등록), `Solution*/*.scn` + `Config\CommonFunction*.xml`(호출부) 다섯 곳이고, 나머지는 설치·데이터·장치 등 주변 인프라입니다.
