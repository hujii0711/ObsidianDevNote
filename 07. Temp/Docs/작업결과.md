구현을 마쳤습니다. 브랜치 `feat/shorts-agent`에 커밋 12개가 있고, 마지막으로 돌린 전체 테스트는 78개 통과(네트워크 테스트 1개 제외)입니다.

## 결과
- **실행 방법:** `./model_run.sh`로 LLM 서버를 띄운 뒤 `uv run python -m shorts_agent "AI 뉴스"`를 실행합니다.
  - 그래프 구조를 보려면 `--show-graph`를 붙입니다.
  - 중간에 끊긴 실행은 `--resume <thread_id>`로 이어 갑니다.
- **실제 모델로 끝까지 실행해 봤습니다.**
  - 결과 영상 [outputs/smoke-full/final.mp4](outputs/smoke-full/final.mp4)는 1080×1920, 57초이고, 장면 8개에 음성과 자막이 들어 있습니다. 전체 실행에 약 6분이 걸렸습니다.
  - mflux가 설치되어 있지 않아서 이미지는 단색 배경의 플레이스홀더로 나왔습니다.
- **최종 리뷰:** 별도 리뷰어의 판정은 "수정 후 병합 가능"이었고, Critical 항목은 없었습니다. 아래 4건을 각각 실패하는 테스트로 재현한 뒤 고쳤습니다.
  - 검수자가 불합격을 주면서 피드백을 비워 두면 작가와 검수자가 무한히 반복하던 문제
  - 리서치 에이전트가 결과를 제출하지 못하면 주제 선택 전에 실행이 죽던 문제
  - 에이전트가 틀린 이미지 경로를 보고하면 생성된 이미지를 플레이스홀더로 덮어쓰던 문제
  - `.pyc` 파일이 커밋에 들어가 테스트할 때마다 작업 트리가 더러워지던 문제

## 제가 내린 결정 (틀렸을 때의 영향)
1. **git worktree를 만들지 않고 현재 폴더에서 새 브랜치로 작업했습니다.** worktree를 만들면 `.venv`를 새로 설치해야 하기 때문입니다. 대신 `ch*/`의 커밋되지 않은 수정 사항이 브랜치를 바꿀 때 함께 따라다닙니다. 그 파일들은 커밋하지 않았습니다.
2. **moviepy 때문에 Pillow가 13에서 11.3으로 내려갔습니다.** 기존 `ch*` 예제 중 Pillow 13 기능을 쓰는 것이 있다면 깨질 수 있습니다.
3. **로컬 Qwen이 도구 호출 대신 텍스트로 답할 때 대비하는 2단계 변환을 넣었습니다.** 실측으로는 이 변환 없이 0/3, 넣은 뒤 4/4 성공했습니다. 대가로 호출이 한 번 늘고, 변환 과정에서 내용이 조금 바뀔 수 있습니다.
4. **mflux는 전역 설치하지 않고 플래그만 확인했습니다.** 실제 이미지를 쓰려면 직접 설치하셔야 합니다.
5. **이미지 도구가 이미 만든 파일은 에이전트가 실패하더라도 그대로 씁니다.**
6. **기획 단계 테스트는 `interrupt_after=["storyboarder"]`로 그 지점에서 멈추게 했습니다.**
7. **`#Shorts`가 이미 있으면 그 위치를 유지합니다.** 그래서 `#shorts`가 항상 맨 앞에 오지는 않습니다.
8. **리뷰어가 Minor로 본 2건(이미지 경로, `.pyc`)을 Important로 올려 고쳤습니다.**
9. **`--resume` 분기에 대한 CLI 자동 테스트는 넣지 않았습니다.** 실제 실행과 리뷰어의 검증 스크립트로는 확인했습니다. 다만 나중에 `__main__.py`를 고치다 이어 가기 기능이 깨져도 테스트로 잡히지 않습니다.

## 미룬 사소한 항목
- `--resume`에 존재하지 않는 ID를 넣어도 "이미 완료된 실행입니다"라고 나옵니다.
- 오류가 나거나 프롬프트에서 Ctrl-D를 누르면 이어 가기 안내 없이 traceback만 출력됩니다.
- `IMAGE_SOURCE` 값을 검증하지 않습니다. `pexels`로 설정해도 `mflux`와 똑같이 동작합니다.
- 띄어쓰기가 들어간 해시태그("인공 지능")를 붙여 주지 않고, 빈 제목도 그대로 통과합니다.
- 주제를 직접 입력해 다시 리서치하면 `research.json`을 덮어써서 처음 탐색한 후보가 사라집니다.
- 숫자로만 된 주제("1984")는 직접 입력할 수 없습니다.
