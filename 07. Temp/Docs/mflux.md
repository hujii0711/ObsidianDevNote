**mflux**는 Black Forest Labs의 이미지 생성 모델 **FLUX**를 Apple의 머신러닝 프레임워크 **MLX**로 옮긴 오픈소스 프로젝트입니다(GitHub: `filipstrand/mflux`). Apple Silicon Mac에서 텍스트 프롬프트로 이미지를 로컬에서 만듭니다. 이 프로젝트에서 쓰는 로컬 Qwen 모델(`mlx-community/...`)도 같은 MLX 기반입니다.

## 특징
- **Mac 전용 로컬 실행:** 클라우드 API나 비용 없이 M 시리즈 칩의 GPU와 통합 메모리를 씁니다.
- **CLI로 바로 사용:** Python 코드를 짜지 않아도 명령어 하나로 이미지가 나옵니다.
- **양자화 지원:** `-q 4`나 `-q 8`로 4bit/8bit 양자화를 하면 메모리 사용량과 속도 부담이 줄어듭니다.
- **주요 모델:**
  - `schnell`: 2~4 step이면 충분할 만큼 빠르고, 라이선스는 Apache 2.0입니다.
  - `dev`: 품질은 더 좋지만 느리고, 비상업 라이선스이며 Hugging Face에서 접근 승인을 받아야 합니다.

## 사용 예
```bash
uv tool install mflux          # 별도 CLI 도구로 설치

mflux-generate \
  --model schnell \
  --prompt "a cat sitting on a desk, cinematic lighting" \
  --steps 4 -q 4 \
  --width 576 --height 1024 \
  --output out.png
```
처음 실행하면 Hugging Face에서 모델 가중치를 받는데, 수십 GB라서 시간이 걸립니다.

## 이 프로젝트에서의 역할
[Docs/superpowers/plans/2026-11-06-ai-shorts-agent.md](Docs/superpowers/plans/2026-11-06-ai-shorts-agent.md)를 보면, mflux는 쇼츠 파이프라인의 **⑤ 비주얼 담당**이 장면 이미지를 만들 때 쓰는 기본 도구입니다.
- **설정:** FLUX.1-schnell을 4bit, 4 step, 576×1024로 생성한 뒤 1080×1920으로 맞춥니다.
- **Pexels를 쓰지 않는 이유:** 현재 Pexels 무료 API 키 발급이 중단되어 mflux가 기본 이미지 소스입니다.
- **메모리:** Qwen 모델이 약 20GB를 쓰기 때문에, mflux는 락을 걸어 한 번에 하나씩만 실행합니다.
- **실패 시:** placeholder 이미지(단색 배경 + 장면 설명 텍스트)로 대신합니다.

참고로 스펙 문서 기준으로 mflux는 아직 설치되어 있지 않습니다.

| 구분 | 내용 | 크기 (대략) |
|---|---|---|
| **mflux 프로그램** | `uv tool install mflux`로 설치하는 CLI(`mflux-generate` 등) | 작음 |
| **FLUX.1-schnell 가중치** | 처음 실행할 때 Hugging Face에서 자동으로 내려받음 | 원본 약 30GB 이상 |

  - `mflux-save`로 양자화된 모델을 따로 저장합니다(약 10GB 안팎).
  - 커뮤니티가 미리 양자화해 올린 모델을 받습니다.

## Qwen(LLM)과 비교
| | Qwen3.6-35B (지금 쓰는 것) | mflux + FLUX |
|---|---|---|
| 종류 | 언어 모델(LLM) | 이미지 생성 모델(디퓨전) |
| 입력 → 출력 | 텍스트 → 텍스트 | 텍스트 프롬프트 → 이미지 |
| 실행 방식 | `model_run.sh`로 **서버를 띄워 두고** 8080 포트로 호출 | 이미지를 만들 때마다 **CLI를 한 번 실행하고 종료** |
| 기반 | MLX | MLX (같은 프레임워크) |

## 실제로 신경 쓸 점
- **메모리:** Qwen 서버(약 20GB)가 떠 있는 상태에서 FLUX(4bit 기준 수 GB에서 10GB 안팎)가 같은 통합 메모리를 나눠 씁니다. 그래서 설계에서 mflux를 한 번에 하나씩만 실행하도록 락을 걸었습니다.
- **속도:** CLI를 실행할 때마다 모델을 새로 불러오므로, 장면마다 로딩 시간이 몇 초에서 수십 초씩 더 걸립니다.
- **디스크:** 첫 다운로드에 수십 GB가 필요하니 여유 공간을 먼저 확인하세요.

## 설계에서 둘을 함께 쓰는 이유
처음 설계는 **"먼저 검색해 보고, 맞는 사진이 없으면 생성한다"**는 흐름이었습니다.

1. Pexels에서 장면 키워드로 검색합니다. 실제 사진이라 자연스럽고 빠릅니다.
2. 비주얼 에이전트가 alt 텍스트를 보고 장면과 맞는지 판단합니다.
3. 맞는 사진이 없으면 mflux로 생성합니다.
4. 생성도 실패하면 placeholder 이미지를 씁니다.

지금은 Pexels 키를 받을 수 없어서 1~2단계를 건너뛰고 **mflux 생성이 기본**이 된 상태입니다. 앞서 말씀드린 Pixabay나 Unsplash도 Pexels처럼 **검색** 서비스라서, 넣는다면 이 1~2단계 자리에 들어갑니다.

## 검색 방식의 한계
- **흔한 장면에 강함:** 고양이, 도시 야경, 커피처럼 흔한 소재는 잘 찾습니다.
- **구체적인 장면은 어려움:** "1920년대 서울 거리"나 "화성에 착륙하는 로봇"처럼 구체적이거나 상상 속 장면은 맞는 사진이 없는 경우가 많습니다. 이럴 때 생성 모델(mflux)이 필요합니다.
- **사진을 직접 보지 않음:** 에이전트는 사진 자체가 아니라 alt 텍스트나 태그로만 판단합니다. 그래서 설명은 맞는데 실제 사진은 장면과 어긋날 수 있습니다.
