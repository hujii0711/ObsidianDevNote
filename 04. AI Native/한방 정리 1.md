
## ✍️ claude.md에 넣어야 할 내용

- **절대 규칙** — 위반하면 안 되는 금지 사항 (맨 위에 배치)
- **아키텍처** — 폴더 구조, 기술 스택
- **빌드/테스트** — 개발 서버, 테스트, 배포 명령어
- **도메인 컨텍스트** — 비즈니스 용어, 데이터 흐름
- **코딩 컨벤션** — 네이밍, 커밋, 패턴 규칙

- ❌ 나쁜 예 — 모든 내용을 [CLAUDE.md](http://CLAUDE.md)에 직접 작성
```markdown
# CLAUDE.md (나쁜 예)
## API 엔드포인트
- POST /api/auth/login - 로그인...
- POST /api/auth/register - 회원가입...
- GET /api/users/:id - 유저 조회...
- ... (50개 더)
```
 
- ✅ 좋은 예 — 한 줄짜리 참조만 남기기
```markdown
# CLAUDE.md (좋은 예)
## 프로젝트 문서
- API 스펙: @docs/api-spec.md
- DB 스키마: @docs/db-schema.md
- 인증 설계: @docs/auth.md
- 코딩 컨벤션: @docs/conventions.md
```

## Cloud.md 작성 원칙

- **Non-obvious 패턴 명시**: AI가 실패할 때마다 cloud.md에 한 줄 추가하여 같은 실수 방지 
- 루트 cloud.md는 100~200줄 이하로 유지: 매 세션마다 컨텍스트에 포함되므로 간결해야 함  
- **인덱스 역할**: 백과사전이 아닌 나침반처럼, 정보의 위치만 안내  
- **자동 갱신 필수**: 썩어가는 컨텍스트는 없는 것보다 나쁨  
    - 세션 종료 시 또는 주기적으로 훅을 통해 자동 갱신
## TDD 기반 스마트 코딩

**핵심 루프**: 작은 변경 → 테스트 → 린트 → 커밋 → 반복

1. 기능 하나 추가
2. 테스트 돌려서 확인
3. 린트/포맷 체크
4. 문제 없으면 커밋
5. 다음 기능으로 넘어가기

## Sub-Agent

**핵심 장점 4가지**
• 병렬 처리 — 여러 작업을 동시에 실행해 전체 소요 시간 단축 
• 컨텍스트 보호 — 메인 에이전트의 컨텍스트를 오염시키지 않음 
• 전문화 — 각 Sub-Agent에 전문 역할 부여 
• 재사용 — 한 번 만든 에이전트를 여러 워크플로우에서 활용

**Do's & Don'ts**
✅ 독립적인 작업을 병렬로 분배 
✅ 명확한 역할과 범위 지정 
✅ 결과를 메인에서 통합 처리 
❌ 의존성 있는 작업을 무리하게 병렬화 
❌ 하나의 Sub-Agent에 너무 많은 역할 
❌ Sub-Agent 간 직접 통신 시도 (불가)

## Hook이란?

Claude Code의 **자동화 엔진**입니다. 이벤트가 발생하면 matcher가 조건을 검사하고, 조건이 맞으면 지정된 액션이 자동으로 실행됩니다.

**이벤트 → Hook 감지 → 액션 실행** 파일 저장, 도구 호출, 알림 수신 등의 이벤트 발생 → matcher가 조건 검사 (와일드카드 * 또는 특정 패턴) → lint 실행, format 적용, 알림 전송 등 자동 실행

## Hook JSON 구조

```json
{
  "hooks": {
    "Notification": [
      {
        "matcher": "*",
        "hooks": [
          {
            "type": "command",
            "command": "terminal-notifier -title 'Claude Code' -message '알림이 있습니다' && afplay /System/Library/Sounds/Ping.aiff &"
          }
        ]
      }
    ]
  }
}
```

**JSON 구조 분해:**

- **이벤트 타입** (`Notification`) — 언제 실행할지
- **matcher** (`*`) — 어떤 상황에 매칭할지 (와일드카드 = 전부)
- **hooks 배열** — 실행할 Hook 목록 (여러 개 가능)
- **command** — 실제 실행할 셸 명령어

|이벤트|타이밍|설명|
|---|---|---|
|**PreToolUse**|도구 호출 직전|입력값 검증, 승인/차단/수정 가능|

## Git Worktree로 병렬 작업

하나의 Git 저장소에서 **여러 개의 작업 디렉토리**를 만드는 기능입니다. 커밋 히스토리는 공유하면서 파일 시스템은 완전히 분리됩니다.  
![Pasted image 20260419160909.png](app://03604033b2088abd3ba230fb8ec627b4d41a/Users/fujii0711/Documents/Obsidian/DevNote/06.%20Link%20Images/Pasted%20image%2020260419160909.png?1776582549487)

```bash
# 수동 worktree
git worktree add ../project-feature-auth feature/auth

# Claude Code 네이티브 지원 (추천)
claude --worktree feature-auth
claude -w feature-auth

# Sub-Agent에서 격리
isolation: worktree  # 에이전트 설정에 추가
```

💡 `claude -w` 한 줄이면 워크트리 생성 → 브랜치 체크아웃 → 세션 시작까지 자동. 변경 없으면 세션 종료 시 자동 정리됩니다.

## 하네스 엔지니어링의 4가지 기둥

1. **기계가 읽는 컨텍스트 파일** — `CLAUDE.md`, `AGENTS.md` 등 에이전트가 자동 로드하는 규칙/지침
2. **결정론적 CI/CD 게이트** — 린터, Hook, 자동 교정 루프로 AI 출력을 기계가 검증·교정
3. **명시적 도구 경계** — 최소 권한 원칙(least privilege)으로 에이전트가 만질 수 있는 범위를 제한
4. **지속적 피드백 루프** — 가비지 컬렉션 방식의 컨텍스트 정리, 실패를 시스템에 환류
