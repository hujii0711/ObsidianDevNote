# 6. 리뷰 단계 상세 가이드

Claude Code를 활용한 앱 개발 — 리뷰 단계에서 해야 할 작업을 파트별로 정리합니다.

---

## 파트 1. 리뷰 단계 개요

### 리뷰의 목적

리뷰는 단순히 코드 오류를 찾는 작업이 아닙니다. 아래 네 가지를 동시에 달성해야 합니다.

```
1. 품질 보증   → 버그, 보안 취약점, 성능 이슈 사전 차단
2. 지식 공유   → 팀원 간 코드 이해도 향상
3. 일관성 유지 → CLAUDE.md 컨벤션 준수 확인
4. 리스크 감소 → 배포 전 마지막 안전망
```

### 리뷰 흐름

```
코드 완성
   ↓
자동 리뷰 (Claude Code 에이전트)
   ↓
셀프 리뷰 (개발자 본인)
   ↓
피어 리뷰 (팀원)
   ↓
머지 및 배포 승인
```

---

## 파트 2. 자동 리뷰 (Claude Code 에이전트)

사람이 리뷰하기 전에 Claude Code로 1차 자동 리뷰를 실행합니다. 반복적이고 기계적인 검사를 자동화해서 사람은 더 중요한 판단에 집중할 수 있습니다.

### PR 전체 코드 리뷰

```bash
# 변경된 파일 전체 리뷰
git diff main...HEAD | claude -p "
역할: 시니어 테크 리드
작업: 아래 diff를 리뷰해줘

확인 항목:
- CLAUDE.md 컨벤션 위반
- 버그 가능성이 있는 로직
- 보안 취약점
- 성능 이슈 (N+1 쿼리, 불필요한 루프 등)
- 중복 코드 및 리팩터링 필요 지점
- 누락된 에러 처리
- 타입 안전성 위반

출력 형식:
파일명 : 라인번호
심각도 : critical / warning / suggestion
문제   : 구체적인 설명
수정안 : 코드 예시 포함
"
```

### 항목별 전문 리뷰 에이전트

```bash
# 보안 리뷰 에이전트
claude -p "
역할: 보안 전문가
작업: 전체 코드베이스 보안 취약점 검사

검사 항목:
- SQL 인젝션 취약점
- XSS / CSRF 취약점
- 인증·인가 누락 엔드포인트
- 민감 정보 하드코딩 (API 키, 비밀번호)
- 민감 정보 로그 출력
- 안전하지 않은 의존성 패키지
- JWT 검증 로직 오류

발견 시 파일명, 라인, 심각도, 수정 방법 포함해서 보고해줘
" > logs/security-review.md

# 성능 리뷰 에이전트
claude -p "
역할: 성능 최적화 전문가
작업: 성능 이슈 탐지

검사 항목:
- N+1 쿼리 패턴
- 인덱스 누락 가능성
- 불필요한 전체 데이터 조회
- 캐싱 적용 가능 지점
- 불필요한 리렌더링 (React)
- 메모리 누수 가능성
- 무거운 연산의 비동기 처리 누락

발견 시 파일명, 라인, 예상 영향, 개선 방법 포함해서 보고해줘
" > logs/performance-review.md

# 컨벤션 리뷰 에이전트
claude -p "
역할: 코드 품질 담당자
작업: CLAUDE.md 컨벤션 준수 여부 전수 검사

검사 항목:
- 네이밍 규칙 위반
- 파일 위치 규칙 위반
- 금지된 패턴 사용
- 누락된 타입 정의
- 주석 규칙 위반
- 임포트 순서 규칙

위반 항목은 파일명, 라인, 규칙 내용, 올바른 예시 포함해서 보고해줘
" > logs/convention-review.md
```

### 리뷰 결과 통합 리포트

```bash
claude -p "
logs/security-review.md
logs/performance-review.md
logs/convention-review.md
를 읽고 전체 리뷰 결과를 통합해서 docs/review-report.md로 작성해줘.

포함 항목:
- 심각도별 이슈 요약 (critical / warning / suggestion)
- 반드시 수정해야 할 항목 목록
- 권장 수정 항목 목록
- 전체 코드 품질 평가
"
```

## 파트 3. 셀프 리뷰

자동 리뷰 결과를 바탕으로 개발자 본인이 직접 확인합니다.

### 셀프 리뷰 체크리스트

PR을 올리기 전에 본인 코드를 직접 점검합니다.

```
코드 품질
- [ ] 함수 하나가 하나의 역할만 하는가
- [ ] 변수·함수명이 의도를 명확히 표현하는가
- [ ] 불필요한 주석이나 디버그 코드가 없는가
- [ ] 중복 코드를 공통 함수로 분리했는가

안정성
- [ ] 모든 에러 케이스를 처리했는가
- [ ] null / undefined 처리를 빠뜨리지 않았는가
- [ ] 외부 API 실패 시 fallback이 있는가
- [ ] 트랜잭션이 필요한 곳에 적용했는가

보안
- [ ] 입력값 유효성 검사를 서버에서도 하는가
- [ ] 인증이 필요한 엔드포인트에 미들웨어가 있는가
- [ ] 민감 정보를 로그에 출력하지 않는가

테스트
- [ ] 새로 추가한 로직에 테스트가 있는가
- [ ] 테스트가 실제 동작을 검증하는가 (형식적 테스트 아닌지)
```

### PR 설명 작성

```bash
# Claude Code로 PR 설명 자동 생성
git diff main...HEAD | claude -p "
이 변경사항을 기반으로 GitHub PR 설명을 작성해줘.

포함 항목:
- 변경 이유와 배경
- 구현 내용 요약
- 테스트 방법
- 스크린샷 또는 API 응답 예시 (해당 시)
- 리뷰어가 집중해서 봐야 할 부분
- 관련 이슈 번호

형식: GitHub Markdown
"
```

## 파트 4. 피어 리뷰

팀원이 코드를 검토하는 단계입니다. Claude Code는 리뷰어와 작성자 모두를 보조합니다.

### 리뷰어를 위한 Claude Code 활용

```bash
# 특정 파일의 맥락 파악
claude -p "
src/modules/auth/auth.service.ts 파일을 읽고
이 파일이 전체 시스템에서 어떤 역할을 하는지,
주요 메서드가 무엇을 하는지 설명해줘.
리뷰하기 전에 빠르게 맥락을 파악하고 싶어
"

# 복잡한 로직 설명 요청
claude -p "
다음 코드 블록이 무엇을 하는지 설명해줘.
잠재적인 문제가 있으면 함께 알려줘.
[코드 붙여넣기]
"

# 더 나은 구현 방법 제안
claude -p "
이 구현 방식의 장단점을 알려주고
더 나은 대안이 있으면 코드 예시와 함께 제안해줘.
[코드 붙여넣기]
"
```

### 리뷰 코멘트 작성 기준

팀 내 리뷰 코멘트를 일관되게 작성하기 위한 기준을 정의합니다.

|레이블|의미|머지 차단 여부|
|---|---|---|
|`[critical]`|버그·보안 이슈, 반드시 수정|차단|
|`[warning]`|잠재적 문제, 수정 강력 권장|차단|
|`[suggestion]`|더 나은 방법 제안, 선택 사항|비차단|
|`[question]`|의도 파악을 위한 질문|비차단|
|`[nit]`|사소한 스타일 지적|비차단|

```bash
# 리뷰 코멘트 초안 작성
claude -p "
다음 코드에 대한 리뷰 코멘트를 작성해줘.
건설적이고 구체적으로, 문제점과 개선 방법을 함께 제시해줘.
레이블: [critical / warning / suggestion] 중 적절한 것 선택

[코드 붙여넣기]
"
```

### 리뷰 피드백 반영

```bash
# 리뷰 코멘트 일괄 반영
claude -p "
다음 리뷰 코멘트들을 확인하고 수정이 필요한 항목을 모두 반영해줘.
수정 후 각 코멘트에 대해 어떻게 처리했는지 요약해줘.

[리뷰 코멘트 목록 붙여넣기]
"

# 리뷰 반영 후 재검토
git diff HEAD~1 | claude -p "
이전 리뷰 피드백을 반영한 변경사항이야.
리뷰 코멘트가 올바르게 반영되었는지 확인해줘.

원래 리뷰 코멘트:
[코멘트 붙여넣기]
"
```

## 파트 5. 아키텍처 리뷰

기능 단위 코드 리뷰와 별도로, 전체 구조가 설계 의도대로 구현되었는지 검토합니다.

### 설계 일치 검토 `권장`

```bash
claude -p "
docs/architecture.md (설계 문서)와
현재 구현된 코드를 비교해서

1. 설계와 다르게 구현된 부분
2. 설계에는 있지만 구현이 누락된 부분
3. 구현은 되었지만 설계 문서에 없는 부분

을 각각 정리해줘
"
```

### 의존성 방향 검토 `권장`

```bash
claude -p "
현재 코드베이스의 모듈 간 의존성을 분석해줘.

확인 항목:
- 순환 의존성이 있는가
- 레이어 간 의존성 방향이 올바른가
  (Controller → Service → Repository 방향)
- 도메인 레이어가 인프라에 의존하고 있는가

문제가 있으면 구체적인 위치와 개선 방법을 알려줘
"
```

## 파트 6. 문서 리뷰

코드 변경에 따라 문서도 함께 업데이트되었는지 확인합니다.

### 문서 업데이트 확인 `필수`

```bash
claude -p "
이번 PR의 변경사항을 기반으로
업데이트가 필요한 문서 목록을 알려줘.

대상 문서:
- docs/api-spec.md (API 명세)
- README.md
- CLAUDE.md
- docs/architecture.md

변경된 내용과 문서의 차이를 구체적으로 알려줘
"
```

### API 문서 자동 업데이트

```bash
claude -p "
변경된 API 엔드포인트를 기반으로
docs/api-spec.md를 최신 상태로 업데이트해줘.

추가·수정·삭제된 엔드포인트를 모두 반영하고
요청/응답 예시도 실제 코드와 일치하도록 수정해줘
"
```

## 파트 7. 머지 승인 기준

모든 리뷰가 완료된 후 머지를 승인하는 기준을 명확히 정의합니다.

### 머지 필수 조건

```
- [ ] critical, warning 레이블 이슈 전부 해결
- [ ] CI 파이프라인 전체 통과 (린트, 테스트, 빌드)
- [ ] 최소 1명 이상 팀원 Approve
- [ ] 관련 문서 업데이트 완료
- [ ] 충돌(Conflict) 해결 완료
```

### 머지 전 최종 확인

```bash
# 머지 전 최종 자동 검사
claude -p "
머지 전 최종 체크리스트를 실행해줘.

1. 전체 테스트 실행 및 결과 확인
2. 린트 오류 없음 확인
3. 빌드 성공 확인
4. 환경변수 누락 없음 확인
5. CLAUDE.md 컨벤션 최종 확인

이상이 없으면 '머지 준비 완료', 있으면 항목별로 보고해줘
"
```

## 리뷰 단계 완료 체크리스트

배포 단계로 넘어가기 전에 아래 항목을 모두 완료해야 합니다.

- [ ] Claude Code 자동 리뷰 완료 및 critical 이슈 해결
- [ ] 보안 리뷰 완료
- [ ] 성능 리뷰 완료
- [ ] 셀프 리뷰 체크리스트 통과
- [ ] PR 설명 작성 완료
- [ ] 피어 리뷰 1인 이상 Approve
- [ ] 모든 리뷰 코멘트 처리 완료
- [ ] 관련 문서 업데이트 완료
- [ ] CI 파이프라인 전체 통과
- [ ] 머지 완료

---

> **핵심 포인트**: 리뷰 단계에서 Claude Code의 역할은 **반복적인 검사를 자동화**해서 사람이 더 중요한 판단, 즉 설계 의도 파악, 비즈니스 로직 검증, 팀 지식 공유에 집중할 수 있게 만드는 것입니다. 자동 리뷰가 `critical` 이슈를 잡아주더라도 최종 판단은 반드시 사람이 해야 합니다.
