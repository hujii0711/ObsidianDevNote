# 4. 개발 단계 상세 가이드

Claude Code를 활용한 앱 개발 — 개발 단계 작업과 서브에이전트 활용법을 함께 정리합니다.

---

## 파트 1. 개발 단계 작업 흐름

### 기능 개발 순서 원칙 `필수`

무작정 코딩을 시작하지 않고 아래 순서를 지킵니다.

```
DB 마이그레이션 → 모델/스키마 → 서비스 로직 → API 엔드포인트 → 프론트엔드 → 테스트
```

이 순서를 지켜야 의존성 충돌 없이 기능을 완성할 수 있습니다.

### 브랜치 단위 개발 `필수`

기능 하나 = 브랜치 하나 = PR 하나 원칙을 지킵니다.

```bash
# 기능 브랜치 생성
git checkout -b feature/user-auth

# 개발 완료 후 커밋
git add .
git commit -m "feat: 유저 로그인 API 구현"

# PR 생성 (MCP 연결 시 Claude Code로 직접 생성 가능)
claude -p "지금 변경사항으로 PR 작성해줘"
```

### 반복 개발 사이클 `필수`

각 기능마다 아래 사이클을 반복합니다.

```
기능 명세 확인 → Claude Code로 구현 → 로컬 테스트 → 코드 리뷰 → 머지
```

## 파트 2. 역할별 개발 작업

### 백엔드 작업

```bash
# DB 마이그레이션 생성
claude -p "users 테이블 마이그레이션 파일 작성해줘"

# API 엔드포인트 구현
claude -p "POST /auth/login 엔드포인트 구현해줘. JWT 사용, CLAUDE.md 컨벤션 따를 것"

# 서비스 레이어 구현
''
claude -p "UserService 클래스 구현해줘. 의존성 주입 패턴 사용"

# 유닛 테스트 작성
claude -p "UserService 단위 테스트 작성해줘. 커버리지 80% 이상"
```

### 프론트엔드 작업

```bash
# 컴포넌트 생성
claude -p "LoginForm 컴포넌트 작성해줘. React Hook Form 사용, 유효성 검사 포함"

# API 연동
claude -p "로그인 API 호출하는 useAuth 훅 작성해줘"

# 상태관리
claude -p "유저 인증 상태를 관리하는 Zustand 스토어 작성해줘"
```

### 공통 작업

```bash
# 타입 정의
claude -p "API 명세 기반으로 TypeScript 타입 정의 파일 작성해줘"

# 에러 핸들링
claude -p "API 에러를 일관되게 처리하는 미들웨어 작성해줘"

# 환경별 설정
claude -p "개발/스테이징/프로덕션 환경 설정 분리해줘"
```

## 파트 3. 서브에이전트란?

### 개념

Claude Code에서 서브에이전트(Subagent)는 메인 Claude Code 세션이 별도의 독립된 Claude Code 인스턴스를 생성해서 특정 작업을 위임하는 방식입니다.

각 서브에이전트는 다음과 같은 특성을 가집니다.

- 독립된 컨텍스트 윈도우를 가집니다
- 메인 에이전트와 병렬로 실행될 수 있습니다
- 특정 역할과 도구만 부여받아 집중해서 작업합니다
- 결과를 메인 에이전트에게 반환합니다

### 서브에이전트가 필요한 시점

아래 상황에서 서브에이전트 분담이 효과적입니다.

```
- 백엔드와 프론트엔드를 동시에 개발해야 할 때
- 테스트 작성을 구현과 병렬로 진행할 때
- 코드 리뷰와 문서화를 개발과 동시에 할 때
- 대규모 리팩터링을 여러 모듈에 걸쳐 진행할 때
```

## 파트 4. 서브에이전트 실행 방법

### 방법 1. `/agents` 명령으로 서브에이전트 구성

Claude Code 세션 내에서 `/agents` 명령을 사용해 서브에이전트를 정의하고 실행합니다.

```bash
# Claude Code 세션 시작
claude

# 세션 내에서 서브에이전트 실행 지시
> /agents

# 에이전트 역할 정의 후 실행 지시 예시
> 다음 3개의 서브에이전트를 병렬로 실행해줘:
  1. backend-agent: POST /auth/login API 구현
  2. frontend-agent: LoginForm 컴포넌트 구현
  3. test-agent: 위 두 작업의 테스트 코드 작성
```

### 방법 2. `-p` 플래그로 병렬 서브에이전트 실행

터미널에서 여러 Claude Code 프로세스를 동시에 실행합니다.

```bash
# 터미널 3개를 열고 각각 실행

# 터미널 1: 백엔드 에이전트
claude -p "
역할: 백엔드 개발자
작업: 유저 인증 API 구현 (POST /auth/login, POST /auth/logout, GET /auth/me)
규칙: CLAUDE.md 컨벤션 준수, JWT 사용, 에러 처리 포함
완료 기준: 각 엔드포인트 구현 + 단위 테스트 작성
"

# 터미널 2: 프론트엔드 에이전트
claude -p "
역할: 프론트엔드 개발자
작업: 유저 인증 UI 구현 (LoginPage, LoginForm, useAuth 훅)
규칙: CLAUDE.md 컨벤션 준수, React Hook Form 사용
완료 기준: 컴포넌트 구현 + API 연동 + 로딩/에러 상태 처리
"

# 터미널 3: QA 에이전트
claude -p "
역할: QA 엔지니어
작업: 인증 기능 E2E 테스트 작성 (Playwright 사용)
규칙: 로그인 성공/실패/엣지케이스 모두 커버
완료 기준: E2E 테스트 파일 작성 + 실행 확인
"
```

### 방법 3. 셸 스크립트로 서브에이전트 자동화

반복적인 서브에이전트 실행을 스크립트로 관리합니다.

```bash
# scripts/dev-agents.sh
#!/bin/bash

FEATURE=$1  # 예: "user-auth"

echo "=== 서브에이전트 병렬 실행 시작: $FEATURE ==="

# 백엔드 에이전트 백그라운드 실행
claude -p "
역할: 백엔드 개발자
기능: $FEATURE
CLAUDE.md 컨벤션 준수하여 API 구현 후 결과를 backend-result.md에 저장
" > logs/backend-agent.log 2>&1 &

BACKEND_PID=$!

# 프론트엔드 에이전트 백그라운드 실행
claude -p "
역할: 프론트엔드 개발자
기능: $FEATURE
CLAUDE.md 컨벤션 준수하여 UI 구현 후 결과를 frontend-result.md에 저장
" > logs/frontend-agent.log 2>&1 &

FRONTEND_PID=$!

# 두 에이전트 완료 대기
wait $BACKEND_PID
wait $FRONTEND_PID

echo "=== 모든 서브에이전트 완료 ==="

# 결과 통합 에이전트 실행
claude -p "
backend-result.md와 frontend-result.md를 읽고
충돌하는 부분(타입 불일치, API 경로 오류 등)을 찾아서 수정해줘
"
```

```bash
# 실행
chmod +x scripts/dev-agents.sh
./scripts/dev-agents.sh "user-auth"
```

### 방법 4. Git Worktree로 완전히 격리된 서브에이전트 실행

각 에이전트가 독립된 워킹 디렉터리에서 작업하게 해서 파일 충돌을 방지합니다.

```bash
# 워크트리 생성 (각 에이전트가 독립된 브랜치에서 작업)
git worktree add ../my-app-backend feature/backend-auth
git worktree add ../my-app-frontend feature/frontend-auth

# 백엔드 에이전트: 별도 디렉터리에서 실행
cd ../my-app-backend
claude -p "유저 인증 백엔드 API 구현해줘" &

# 프론트엔드 에이전트: 별도 디렉터리에서 실행
cd ../my-app-frontend
claude -p "유저 인증 프론트엔드 UI 구현해줘" &

# 완료 후 각 브랜치를 develop에 머지
```

## 파트 5. 역할별 서브에이전트 프롬프트 템플릿

효과적인 서브에이전트 실행을 위해 역할을 명확히 정의한 프롬프트를 사용합니다.

### 백엔드 에이전트 템플릿

```
역할: 시니어 백엔드 개발자
기술 스택: [NestJS / PostgreSQL / Prisma / JWT]
참고 문서: CLAUDE.md, docs/api-spec.md

작업 범위:
- [구현할 API 목록]

완료 기준:
- 모든 엔드포인트 구현 완료
- 단위 테스트 커버리지 80% 이상
- API 명세와 응답 형식 일치

금지 사항:
- CLAUDE.md에 없는 라이브러리 추가 금지
- 하드코딩된 시크릿 값 사용 금지
```

### 프론트엔드 에이전트 템플릿

```
역할: 시니어 프론트엔드 개발자
기술 스택: [Next.js / TypeScript / Tailwind / Zustand]
참고 문서: CLAUDE.md, docs/design-system.md

작업 범위:
- [구현할 컴포넌트/페이지 목록]

완료 기준:
- 컴포넌트 구현 및 백엔드 API 연동 완료
- 로딩 상태, 에러 상태 처리 포함
- 반응형 레이아웃 적용

금지 사항:
- inline style 사용 금지
- any 타입 사용 금지
```

### 테스트 에이전트 템플릿

```
역할: QA 엔지니어
기술 스택: [Jest / Playwright]
참고 문서: CLAUDE.md, 구현된 코드 전체

작업 범위:
- 백엔드 단위 테스트
- 프론트엔드 컴포넌트 테스트
- 주요 사용자 시나리오 E2E 테스트

완료 기준:
- 전체 커버리지 80% 이상
- 성공/실패/엣지케이스 모두 커버
- 모든 테스트 통과 확인
```

### 리뷰 에이전트 템플릿

```
역할: 테크 리드
작업: 구현된 코드 전체 리뷰

확인 항목:
- CLAUDE.md 컨벤션 준수 여부
- 보안 취약점 (SQL 인젝션, XSS, 인증 누락 등)
- 성능 이슈 (N+1 쿼리, 불필요한 렌더링 등)
- 타입 안전성
- 에러 처리 누락

출력 형식:
- 파일명과 라인 번호 포함
- 심각도 표시 (critical / warning / suggestion)
- 수정 방법 제안
```

## 파트 6. 서브에이전트 협업 시 주의사항

### 충돌 방지 규칙

```
1. 같은 파일을 동시에 수정하지 않도록 작업 범위를 명확히 분리합니다
2. 공유 타입 파일(types.ts)은 먼저 확정한 후 에이전트를 실행합니다
3. API 명세를 먼저 확정해야 백엔드/프론트엔드 에이전트가 동시에 작업 가능합니다
4. Git Worktree를 사용하면 파일 충돌을 구조적으로 방지할 수 있습니다
```

### 결과 통합 순서

```
1. 각 에이전트 작업 완료 확인
2. 타입 불일치, API 경로 오류 등 충돌 검사
3. 통합 에이전트로 충돌 수정
4. 전체 테스트 실행으로 통합 검증
5. 코드 리뷰 에이전트로 최종 점검
```

### 컨텍스트 유지 팁

서브에이전트는 독립된 컨텍스트를 가지므로 필요한 정보를 명시적으로 전달해야 합니다.

```bash
# 좋은 예: 필요한 컨텍스트를 명시적으로 제공
claude -p "
CLAUDE.md를 읽고,
docs/api-spec.md의 /auth 섹션을 참고해서,
src/modules/auth/ 디렉터리에 인증 모듈을 구현해줘
"

# 나쁜 예: 컨텍스트 없이 실행
claude -p "인증 모듈 만들어줘"
```

## 개발 단계 완료 체크리스트

테스트 단계로 넘어가기 전에 아래 항목을 모두 완료해야 합니다.

- [ ] 모든 MVP 기능 구현 완료
- [ ] 각 기능별 단위 테스트 작성 완료
- [ ] 린트·타입 오류 없음 확인
- [ ] 환경변수 누락 없음 확인
- [ ] API 명세와 실제 구현 일치 확인
- [ ] 코드 리뷰 에이전트 점검 완료
- [ ] 로컬 환경에서 전체 기능 동작 확인

---

> **핵심 포인트**: 서브에이전트의 효과를 극대화하려면 **작업 범위 분리**와 **명시적 컨텍스트 전달** 두 가지가 핵심입니다. 에이전트에게 "잘 해줘"가 아니라 "무엇을, 어디에, 어떤 규칙으로, 어떤 기준까지"를 구체적으로 지정할수록 결과물의 품질이 올라갑니다.
