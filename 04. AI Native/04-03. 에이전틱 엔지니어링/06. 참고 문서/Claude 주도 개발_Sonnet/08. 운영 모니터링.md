# 8. 운영 · 모니터링 단계 상세 가이드

Claude Code를 활용한 앱 개발 — 운영 단계에서 해야 할 작업을 파트별로 정리합니다.

---

## 파트 1. 모니터링 체계 구축

### 모니터링 3계층 `필수`

운영 모니터링은 세 계층으로 나눠서 구성합니다.

```
인프라 계층    → 서버 CPU, 메모리, 디스크, 네트워크
애플리케이션 계층 → API 응답 시간, 에러율, 처리량
비즈니스 계층   → 가입자 수, 결제 성공률, 핵심 기능 사용량
```

세 계층 모두 모니터링해야 장애 원인을 빠르게 특정할 수 있습니다.

### 핵심 지표(SLI) 및 목표(SLO) 정의 `필수`

서비스 수준을 수치로 정의합니다.

|지표|측정 항목|목표(SLO)|
|---|---|---|
|가용성|정상 응답 비율|99.9% 이상|
|응답 시간|API p95 응답 시간|500ms 이하|
|에러율|5xx 응답 비율|0.1% 이하|
|처리량|분당 요청 수(RPS)|목표치 대비 80% 이상|

```bash
claude -p "
우리 서비스에 맞는 SLI/SLO를 정의하고
CloudWatch 또는 Datadog에서 이를 측정하는 대시보드 설정 방법을 알려줘
"
```

### 모니터링 도구 설정 `필수`

```bash
claude -p "
다음 모니터링 스택을 설정하는 방법을 알려줘.

인프라: CloudWatch (AWS)
APM: Datadog 또는 New Relic
에러 추적: Sentry
로그 집계: CloudWatch Logs 또는 ELK Stack
업타임: UptimeRobot 또는 Pingdom

각 도구의 설치·설정 방법과 핵심 대시보드 구성 방법 포함
"
```

## 파트 2. 로그 관리

### 로그 수준 및 구조 정의 `필수`

```bash
claude -p "
프로덕션 환경에 적합한 로그 전략을 설계해줘.

포함 내용:
- 로그 수준별 기준 (ERROR / WARN / INFO / DEBUG)
- 구조화된 JSON 로그 포맷 정의
- 민감 정보 마스킹 처리 방법 (비밀번호, 토큰, 개인정보)
- 요청 추적을 위한 Correlation ID 적용 방법
- NestJS 기준으로 작성해줘
"
```

로그 수준 기준은 다음과 같습니다.

```
ERROR  → 즉시 대응 필요한 오류 (서비스 영향 있음)
WARN   → 잠재적 문제, 모니터링 필요 (서비스 영향 없음)
INFO   → 주요 비즈니스 이벤트 (요청 처리, 결제 완료 등)
DEBUG  → 개발 디버깅용 (프로덕션에서는 비활성화)
```

### 로그 분석 자동화

```bash
# 에러 로그 분석
cat /var/log/app/error.log | claude -p "
이 에러 로그를 분석해줘.

포함 내용:
- 가장 빈번한 에러 패턴 TOP 5

- 각 에러의 예상 원인과 대응 방법
"

# 주간 로그 리포트 자동 생성
claude -p "

```

## 파트 3. 알림 및 온콜 체계

### 알림 규칙 설정 `필수`

알림이 너무 많으면 피로도가 높아져 정작 중요한 알림을 놓칩니다. 알림은 반드시 대응이 필요한 상황에만 발생하도록 설정합니다.

```bash
claude -p "
다음 기준으로 CloudWatch 알람 설정 방법을 알려줘.

즉시 알림 (PagerDuty + Slack):
- 서비스 다운 (헬스체크 실패 2회 연속)
- 에러율 1% 초과 (5분 기준)
- API 응답 시간 p95 1초 초과
- DB 연결 실패

경고 알림 (Slack만):
- CPU 사용률 80% 초과 (10분 지속)
- 메모리 사용률 85% 초과
- 디스크 사용률 80% 초과
- 에러율 0.5% 초과

각 알림의 임계값 조정 방법과 알림 피로도 줄이는 방법도 포함해줘
"
```

### 온콜 로테이션 설정 `권장`

```bash
claude -p "
소규모 팀(3명)을 위한 온콜 로테이션 정책을 설계해줘.

포함 내용:
- 주간 온콜 담당자 로테이션 방식
- 야간/주말 알림 에스컬레이션 기준
- 대응 시간 SLA (P1: 15분, P2: 1시간, P3: 4시간)
- PagerDuty 설정 방법
- 온콜 핸드오프 체크리스트
"
```

### 장애 대응 런북 작성 `필수`

반복적으로 발생하는 장애 유형마다 대응 절차를 문서화합니다.

```bash
claude -p "
다음 장애 유형별 대응 런북을 작성해줘.

장애 유형:
1. 서비스 전체 다운
2. DB 연결 실패
3. 메모리 부족으로 인한 OOM
4. 외부 API 연동 실패 (결제, 이메일)
5. 급격한 트래픽 증가

각 런북 형식:
- 장애 감지 방법
- 즉시 확인 사항 (1분 이내)
- 단계별 대응 절차
- 에스컬레이션 기준
- 재발 방지 조치
"
```

## 파트 4. 장애 대응 프로세스

### 장애 심각도 분류 `필수`

```
P1 (Critical) → 서비스 전체 중단, 전체 사용자 영향
               즉시 대응, 15분 이내 상황 공유
               예: 로그인 불가, 결제 전체 실패

P2 (High)     → 핵심 기능 장애, 일부 사용자 영향
               1시간 이내 대응
               예: 특정 기능 오류, 성능 심각한 저하

P3 (Medium)   → 부분적 기능 저하, 소수 사용자 영향
               4시간 이내 대응
               예: 특정 조건에서만 발생하는 버그

P4 (Low)      → 사용성 불편, 서비스 영향 미미
               다음 스프린트에 처리
               예: UI 깨짐, 비핵심 기능 오류
```

### 장애 대응 흐름

```
장애 감지 (알림 또는 사용자 제보)
      ↓
심각도 분류 (P1~P4)
      ↓
담당자 지정 및 상황 공유 채널 개설
      ↓
원인 파악 (로그, 메트릭 분석)
      ↓
임시 조치 (롤백, 기능 차단 등)
      ↓
근본 원인 수정
      ↓
정상화 확인
      ↓
장애 보고서(Post-mortem) 작성
```

### Claude Code로 장애 원인 분석

```bash
# 에러 로그 기반 원인 분석
claude -p "
다음 에러 로그와 스택 트레이스를 분석해줘.

에러 발생 시각: 2024-03-15 14:23:00
영향 범위: 로그인 API 전체 실패

[로그 내용 붙여넣기]

분석 내용:
- 에러 원인 추정
- 즉시 취할 수 있는 임시 조치
- 근본 원인 수정 방법
- 재발 방지 방안
"

# 메트릭 이상 분석
claude -p "
배포 후 다음 메트릭 변화가 감지됐어.

배포 전: 평균 응답 시간 120ms, 에러율 0.05%
배포 후: 평균 응답 시간 850ms, 에러율 2.3%

가능한 원인과 확인 순서를 알려줘.
롤백 여부 판단 기준도 함께 알려줘
"
```

### 장애 보고서(Post-mortem) 작성 `필수`

P1, P2 장애는 반드시 Post-mortem을 작성합니다. 비난 없이 시스템과 프로세스 개선에 집중합니다.

```bash
claude -p "
다음 장애에 대한 Post-mortem 문서를 작성해줘.

장애 개요:
- 발생 시각 및 복구 시각
- 영향 범위 및 사용자 수
- 주요 타임라인

형식:
1. 요약 (경영진용 3줄 요약)
2. 영향 범위
3. 타임라인 (감지→대응→복구 전 과정)
4. 근본 원인 분석
5. 재발 방지 Action Item (담당자, 기한 포함)

비난 없는(Blameless) 문화로 작성해줘
"
```

## 파트 9. 회고 및 개선

### 스프린트 회고 `필수`

운영에서 얻은 인사이트를 다음 기획 사이클에 반영합니다.

```bash
claude -p "
이번 스프린트 운영 데이터를 바탕으로 회고 문서를 작성해줘.

데이터:
- 발생한 장애: [목록]
- SLO 달성 여부: [현황]
- 사용자 피드백: [주요 내용]
- 기술 부채: [목록]

형식:
- 잘된 점 (Keep)
- 개선할 점 (Problem)
- 다음에 시도할 것 (Try)
- 다음 스프린트 Action Item (담당자, 기한 포함)
"
```

### 기술 부채 관리

```bash
claude -p "
현재 코드베이스의 기술 부채를 분석해줘.

확인 항목:
- 오래된 의존성 패키지
- 테스트 커버리지가 낮은 모듈
```
