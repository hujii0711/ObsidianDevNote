# 3. 환경 세팅 단계 상세 가이드

Claude Code를 활용한 앱 개발 — 환경 세팅 단계에서 해야 할 작업을 네 파트로 정리합니다.

---

## 파트 1. Claude Code 초기 설정

### Claude Code 설치 및 인증 `필수`

```bash
# 설치 (권장 방식)
curl -fsSL https://claude.ai/install.sh | bash

# 또는 Homebrew (macOS)
brew install --cask claude-code

# 로그인
claude auth login
```

### CLAUDE.md 완성 `필수`

설계 단계에서 작성한 초안을 실제 프로젝트 루트에 배치하고 내용을 완성합니다. Claude Code는 세션 시작 시 이 파일을 자동으로 읽어 프로젝트 맥락을 파악합니다.

CLAUDE.md에 반드시 포함해야 할 항목은 다음과 같습니다.

```markdown
# 프로젝트명

## 개요
- 서비스 목적 한 줄 요약
- 기술 스택 목록

## 디렉터리 구조
src/
├── components/
├── services/
└── utils/

## 코딩 컨벤션
- 네이밍 규칙
- 파일 구조 규칙
- 주석 작성 규칙

## API 규칙
- 엔드포인트 형식
- 에러 응답 형식
- 인증 방식

## 주의사항
- 절대 하면 안 되는 것
- 반드시 지켜야 할 것
```

```bash
claude -p "설계 문서 기반으로 CLAUDE.md 최종 완성해줘"
```

### 커스텀 슬래시 커맨드 설정 `권장`

반복적으로 사용하는 프롬프트를 슬래시 커맨드로 등록해두면 개발 속도가 올라갑니다.

```bash
# 프로젝트 전용 커맨드 디렉터리 생성
mkdir -p .claude/commands

# 예시: 코드 리뷰 커맨드
echo "변경된 코드를 리뷰하고 버그, 보안 이슈, 컨벤션 위반을 알려줘" \
  > .claude/commands/review.md

# 예시: 테스트 작성 커맨드
echo "이 파일에 대한 단위 테스트를 작성해줘. Jest 사용, 커버리지 80% 이상" \
  > .claude/commands/test.md

# 세션 내에서 /review, /test 로 바로 사용 가능
```

## 파트 2. 프로젝트 초기화

### 저장소 생성 및 브랜치 전략 설정 `필수`

```bash
# Git 저장소 초기화
git init
git remote add origin <repo-url>

# 브랜치 전략 확정 (예: GitHub Flow)
# main → 프로덕션
# develop → 통합 개발
# feature/xxx → 기능 개발
# hotfix/xxx → 긴급 수정

claude -p "이 프로젝트에 맞는 브랜치 전략 추천하고 보호 규칙 설정법 알려줘"
```

### 프로젝트 스캐폴딩 `필수`

기술 스택에 맞는 초기 프로젝트 구조를 생성합니다.

```bash
# 예시: Next.js
npx create-next-app@latest my-app --typescript --tailwind --eslint

# 예시: NestJS
npx @nestjs/cli new my-api

# Claude Code로 디렉터리 구조 정리
claude -p "CLAUDE.md의 디렉터리 구조대로 폴더와 기본 파일 생성해줘"
```

### 의존성 설치 `필수`

설계 단계에서 확정한 라이브러리를 설치합니다. 버전을 명시해서 팀 전체가 동일한 환경을 사용하도록 합니다.

```bash
# 예시
npm install

# Claude Code로 필요한 패키지 파악
claude -p "PRD와 기술 스택 기반으로 필요한 npm 패키지 목록 뽑아줘"
```

## 파트 3. 개발 환경 표준화

팀원 모두가 동일한 환경에서 개발하도록 표준화하는 단계입니다.

### 환경변수 설정 `필수`

`.env.example` 파일을 만들어 필요한 환경변수를 문서화합니다. 실제 값이 담긴 `.env`는 반드시 `.gitignore`에 추가합니다.

```bash
# .env.example
DATABASE_URL=postgresql://user:password@localhost:5432/mydb
JWT_SECRET=your-secret-key
API_BASE_URL=http://localhost:3000

claude -p "이 프로젝트에 필요한 환경변수 목록 정리해줘"
```

### 린트 및 포맷터 설정 `필수`

코드 스타일을 자동으로 강제하는 도구를 설정합니다.

```bash
# ESLint + Prettier 설정 생성
claude -p "이 프로젝트 컨벤션에 맞는 .eslintrc와 .prettierrc 작성해줘"

# pre-commit 훅으로 자동 검사 (husky)
npx husky init
echo "npx lint-staged" > .husky/pre-commit
```

### Node/Python 버전 고정 `권장`

팀원 간 런타임 버전 차이로 인한 문제를 방지합니다.

```bash
# Node.js 버전 고정
node --version > .nvmrc        # nvm 사용 시
echo "20.x" > .node-version    # 일반

# Python 버전 고정
echo "3.11.0" > .python-version   # pyenv 사용 시
```

### Docker 개발 환경 구성 `권장`

DB, 캐시, 메시지 큐 등 외부 서비스를 로컬에서 일관되게 실행합니다.

```bash
# docker-compose.yml 생성
claude -p "PostgreSQL, Redis 포함한 개발용 docker-compose.yml 작성해줘"

docker-compose up -d
```

## 파트 4. MCP 서버 연결

Claude Code가 외부 도구와 직접 연동할 수 있도록 MCP를 설정합니다.

### 프로젝트에 유용한 MCP 서버 `권장`

|MCP 서버|용도|
|---|---|
|`@modelcontextprotocol/server-postgres`|DB 직접 조회·수정|
|`@modelcontextprotocol/server-github`|PR 생성, 이슈 관리|
|`@modelcontextprotocol/server-filesystem`|파일 시스템 접근|
|`@modelcontextprotocol/server-fetch`|외부 API 호출|

### MCP 서버 등록 방법

```bash
# 프로젝트 레벨로 등록
claude mcp add postgres \
  -e DATABASE_URL=$DATABASE_URL \
  -- npx @modelcontextprotocol/server-postgres

claude mcp add github \
  -e GITHUB_TOKEN=$GITHUB_TOKEN \
  -- npx @modelcontextprotocol/server-github

# 등록된 MCP 확인
claude mcp list
```

## 파트 5. CI/CD 파이프라인 기초 설정

배포 파이프라인을 초반에 잡아두면 개발 중 지속적으로 품질을 확인할 수 있습니다.

### GitHub Actions 기본 워크플로우 설정 `권장`

```bash
mkdir -p .github/workflows

claude -p "PR 생성 시 린트·테스트 자동 실행하는 GitHub Actions 워크플로우 작성해줘"
```

기본적으로 포함할 스텝은 다음과 같습니다.

```
PR 생성 → 린트 검사 → 단위 테스트 → 빌드 확인
```
