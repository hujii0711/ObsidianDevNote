
### 1. Skills란? → AI에게 주는 업무 매뉴얼
![[Pasted image 20260419140714.png]]
![[Pasted image 20260419140802.png]]

반복되는 프롬프트를 `SKILL.md` 파일에 정의하여 AI에게 **업무 매뉴얼**처럼 전달하는 기능입니다.
한 번 만들면 자동 트리거 또는 `/skill-name`으로 호출하여 매번 같은 품질의 결과를 얻을 수 있습니다.

### 2. 프롬프트 vs Skills 비교
• 프롬프트: 매번 입력, 결과 들쭉날쭉, 공유 어려움, 일회성 작업에 좋음  
• Skills: 한 번 만들면 자동 호출, 품질 일관, 팀 공유 가능
▶︎ 프롬프트가 "한 번의 지시"라면, Skills는 **"재사용 가능한 업무 시스템"**입니다.

| 항목     | 프롬프트      | Skills     |
| ------ | --------- | ---------- |
| 재사용성   | 매번 재입력    | 파일로 영구 보존  |
| 일관성    | 매번 다를수 있음 | 항상 동일한 품질  |
| 팀 공유   | 공유 어려움    | Git으로 공유   |
| 트리거 방식 | 수동 입력     | 자동 감지 & 실행 |

### 3. Skills를 쓰는 3가지 이유
- **반복 자동화** — 같은 프롬프트를 매번 입력하지 않아도 됨. `/ppt`만 치면 끝
- **품질 일관성** — 순서, 형식, 체크리스트가 정해져 있어 누가 실행하든 같은 기준
- **팀 공유** — Git에 올려서 팀원과 공유하면 팀 전체가 같은 자동화 사용

### 4. 스킬 구조와 로딩 방식
스킬의 경우 평소에는 한줄 설명만 올라가고 전체 내용은 쓸 때만 불러온다.  
같은 기능이라면 MCP 보다 스킬이 훨씬 가볍다.  
그래서 간단한 작업이라면 MCP 대신 로컬 스크립트를 스킬로 감싸주는 것을 추천한다.
```
.claude/skills/
└── ppt-generator/            ← 스킬 폴더
    ├── SKILL.md               ← 핵심 파일 (필수)
    ├── template.md            ← Claude가 채울 템플릿 (선택)
    ├── examples/              ← 예제 출력 (선택)
	    ├── sample.md
    └── scripts/               ← 실행 가능한 스크립트 (선택)
	    ├── generator.py
```

> 핵심 포인트
- SKILL.md의 description이 스킬 매칭의 핵심이다.
- 사용자의 입력과 description을 비교해서 자동으로 스킬을 선택한다.

#### (1) 2단계 로딩 방식
1단계: 스킬 이름과 description만 로드 (항상, ~50-100바이트)
2단계: 실제 호출 시 SKILL.md 본문 + 참고 파일 전체 로드

→ 평소에는 가볍게, 쓸 때만 전체를 불러오는 구조입니다.
자동 정리(컴팩션) 시 전체 내용은 정리되고 설명만 남습니다.

![[Pasted image 20260520175630.png]]

아무리 좋은 규칙을 만들어도 이 컨텍스트 윈도우가 꽉 차버리면 AI가 앞에서 뭘했는지 잊어버리고 나쁜 품질의 코드를 작성해준다. 스킬은 이 문제를 깔끔하게 해결해준다. 필요할 때만 불러오고 쓰고 나면 알아서 치워준다.

#### (2) CLAUDE.md 🆚 Skills

| 항목    | CLAUDE.md                     | Skills                      |
| ----- | ----------------------------- | --------------------------- |
| 로딩시점  | 항상 세션 시작시 자동 로딩               | 필요시 호출될 때만 로딩               |
| 용도    | 프로젝트 규칙으로 코딩 컨벤션, 금지사항, 지침    | 작업 워크플로우로 반복 작업의 자동화 레시피    |
| 크기 제한 | 작게 유지 권장<br>매번 로딩 -> 토큰 절약 필수 | 본문 500줄 이하 권장, 별도 파일 분리 가능  |
| 트리거   | 자동으로 세션마다 무조건 적용              | 명령어(슬래시 명령) / 자동(조건 매칭)<br> |

#### (3) CLAUDE.md vs Skills vs MCP vs Sub-Agent 비교

| 비교 항목          | CLAUDE.md | Skills         | MCP 도구    | Sub-Agent  |
| -------------- | --------- | -------------- | --------- | ---------- |
| **평소 차지하는 공간** | 전체 내용 매번  | 설명만 (~50-100B) | 전체 설명 매번  | 에이전트 설명 매번 |
| 대화할 때마다?       | 전부 포함     | 설명만            | 전부 포함     | 설명이 포함됨    |
| **안 쓸 때 부담**   | 항상 있음     | **거의 없음**      | 항상 있음     | 항상 있음      |
| **언제 쓰면 좋은가**  | 핵심 규칙     | 반복 작업          | 외부 서비스 연동 | 대량 탐색/분석   |
→ 정리)
- 알 쓸때 가장 가벼운건: Skiils(설명만 올라가니까)
- 설명 중 가장 효율적인 건: Sub-Agent(별도 공간에서 돌아가니까)
- 둘 다 잡고 싶으면 Skiils + context: fork(평소엔 가볍고, 실행은 별도 공간에서)
- '뭐가 제일 좋아?' 가 아니라, 언제 공간을 아끼고 싶은지에 따라 선택이 달라진다.  
각각 쓰임새가 다르니까. 상황에 맞에 섞어 쓰는 것이 핵심이다.

### 5. SKILL.md 작성법
```ㅡ
---
name: ppt-generator
description: "PPT 발표자료 자동 생성. 'PPT 만들어줘',
  '발표자료 작성', '슬라이드 제작' 요청 시 트리거."
---

## 목적
주제와 핵심 내용을 입력하면 PPT 발표자료를 자동 생성합니다.

## 절차
1. 발표 주제, 대상 청중, 발표 시간 확인
2. 목차 및 슬라이드 구성 설계
3. 각 슬라이드별 내용 작성
4. .pptx 파일로 출력

## 자체 검증 체크리스트
- [ ] 슬라이드 수가 적절한가?
- [ ] 핵심 메시지가 있는가?
- [ ] 시각 자료 지시사항이 포함되었는가?
```

💡**description 작성 팁** 
✅ 좋은 예: "PPT 발표자료 자동 생성. 'PPT 만들어줘', '발표자료 작성' 요청 시 트리거." 
❌ 나쁜 예: "문서를 생성하는 스킬" (너무 추상적)

핵심 기능이 첫 문장에, 사용자가 쓸 법한 표현 3개 이상 포함할 것.

### 6. 스킬 만들기
![[Pasted image 20260419142951.png]]

- **방법 1 — 수동:** `mkdir -p ~/.claude/skills/ppt-generator` → [SKILL.md](http://skill.md/) 작성
- **방법 2 — skill-creator 플러그인 (추천):** `/install-plugin skill-creator` 설치 후 "스킬 만들어줘"라고 말하면 자동 트리거

💡skill-creator는 description 최적화, frontmatter 설정, 지원 파일 구성까지 **스킬 작성 모범 사례를 자동 적용**해서 [SKILL.md](http://skill.md/)를 만들어줍니다.

### 7. 스킬 저장 위치
![[Pasted image 20260419150840.png]]

| 위치             | 경로                                 | 적용 대상               |
| -------------- | ---------------------------------- | ------------------- |
| **Enterprise** | 관리 설정                              | 조직의 모든 사용자          |
| **Personal**   | `~/.claude/skills/<name>/SKILL.md` | 내 모든 프로젝트           |
| **Project**    | `.claude/skills/<name>/SKILL.md`   | 이 프로젝트만 (Git 공유 가능) |
| **Plugin**     | `<plugin>/skills/<name>/SKILL.md`  | 플러그인 활성화된 곳         |

💡**우선순위:** Enterprise > Personal > Project. Plugin 스킬은 `plugin-name:skill-name`으로 네임스페이스가 분리되어 충돌이 없습니다. 팀 공유: `.claude/skills/`를 Git에 커밋하면 팀원이 pull 받는 순간 바로 사용 가능합니다.

### 에이전트 스킬

에이전트 스킬을 이용하면 에이전트에 특정한 전문 스킬을 부여할 수 있다.
예를 들어, 파워포인트나 엑셀 파일 같은 문서 생성, 데이터로부터의 금융 또는 비즈니스 분석, 또는 특정 Git 작업이나 작업 자동화 등  다양한 능력을 부여할 수 있다.

- 에이전트 스킬 도입 이유
원하는 기능을 간단하고 명확하게 지시하면 컨텍스트 관리가 더 효율적이고 에이전트의 성능도 향상될 수 있다.
에이전트 스킬을 활용하면 LLM에 구체적인 절차, 스크립트, 참조 파일 등을 제공할 수 있어 프롬프트나 훅만으로는 어려웠던 특정 작업의 재현성과 일관성을 보장할 수 있다.
사용자의 요청과 스킬이 존재하면 클로드가 그 스키을 우선적으로 활용한다. 또한 사용자가 스킬을 지정해 직접 호출할 수도 있다.

- 스킬 설정 파일
스킬 설정 파일은 특정 프롬프트와 프로그램 스크립트로 이뤄져 있다. 쉽게 말해, 에이전트가 따라야 할 절차를 안내하는 메뉴얼과 이 때 실행할 프로그램을 함께 제공하는 것이다.

```
my-skill
	SKILL.md(필수)
	reference.md(옵션: 컨텍스트에 포함하고 싶은 문서)
	example.md(옵션: 구페적인 예시)
	scripts/
		helper.py(옵션: 실행할 스크립트)
	templates/
		template.txt(옵션: 출력 템플릿 등)
```

- 에이전트에게 스킬 생성 요청 지시
```
새로운 스킬을 작성하세요.
클로드 코드 에이전트가 파일 편집을 완료한 후, 편집된 파일에 대해 린터를 실행하는 스킬이다.
```
이렇게 하면 예를 들어 ~/.claude/skiils/lint-checker라는 디렉터링 다음과 같은 SKILL.md가 출력된다.

- 스킬의 구체적인 사용법
구체적인 절차나 명령을 지정하고, 스크립트의 결과를 클로드가 컨텍스트로 포함하기 때문에 완료된 시점에 예상되는 출력이나 오류 발생 시에 지정하는 것도 가능하다.
예를 들어, git diff에서 추출한 파일로 특정 형식의 커밋 메시지를 만들거나, 품질 관리 기준에 따라 코드 리뷰를 진행하거나, 코드를 작성할 때 특정 예시에 기반한 테스트 파일을 반드시 작성하도록 하는 등 여러 상황에 적용할 수 있다.
이는 LLM의 높은 유연성과 처리 능력에 스크립트 실행 기능이 더해져 매우 강력하게 활용할 수 있다.
