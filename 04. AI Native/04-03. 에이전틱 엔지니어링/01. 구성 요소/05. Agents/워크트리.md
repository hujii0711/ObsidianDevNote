
```bash

```


### 7-3. 머지 후 워크트리 정리(방법3)
```bash

# 원격 브랜치 삭제 (PR 머지 후)

```

**Git 워크트리(`git worktree`)는 철저하게 로컬(Local) 시스템에서만 동작하는 기능**입니다.

워크트리를 생성한다고 해서 GitHub 저장소에 새로운 설정이 생기거나 구조가 변하지 않습니다. 이에 대한 핵심적인 특징을 정리해 드립니다.

### 1. 로컬 환경에서의 동작 원리

`git worktree`는 하나의 `.git` 데이터(저장소의 역사와 객체들)를 공유하면서, **서로 다른 브랜치를 별도의 물리적인 폴더에 동시에 체크아웃**해주는 기능입니다.

- **GitHub 입장:** 사용자가 어떤 폴더에서 작업하는지 알 수 없습니다. 오직 `git push`를 통해 커밋이 전송될 때만 변화를 감지합니다.

- **로컬 입장:** `main` 브랜치는 A 폴더에서, `feature` 브랜치는 B 폴더에서 동시에 열어두고 작업할 수 있습니다. 브랜치를 전환(`git switch`)하느라 작업 중인 파일을 `stash`하거나 커밋할 필요가 없어집니다.

### 2. 원격(GitHub)과의 관계

워크트리를 생성하는 과정에서 원격 저장소에 영향을 주는 유일한 경우는 "원격에만 있는 브랜치를 가져와서 워크트리를 만들 때"입니다.

```
# 원격의 feature 브랜치를 가져와서 별도 폴더(my-feature-dir)에 워크트리 생성
git worktree add ../my-feature-dir origin/feature
```

이때도 원격 저장소의 상태가 바뀌는 것이 아니라, 로컬에 해당 브랜치의 복사본(워킹 디렉토리)이 하나 더 생기는 것뿐입니다.

### 3. 워크트리 사용 시 주의할 점 (로컬 관리)

워크트리는 로컬의 폴더와 연결되어 있기 때문에 관리에 주의가 필요합니다.

- **폴더 삭제:** 워크트리로 만든 폴더를 그냥 `rm -rf`로 지우면 Git은 여전히 해당 워크트리가 존재한다고 믿습니다. 반드시 아래 명령어로 정리해야 합니다.

```
# 연결이 끊긴 워크트리 정리
git worktree prune

# 또는 명시적으로 제거
git worktree remove <워크트리_이름>
```
  
- **브랜치 중복 체크아웃 방지:** Git은 기본적으로 동일한 브랜치를 두 개의 워크트리에 동시에 체크아웃하는 것을 막습니다. (혼란 방지 목적)

### 💡 요약하자면

회사 계정 프로젝트와 개인 계정 프로젝트를 동시에 띄워놓고 비교하거나, 현재 진행 중인 VS Code 익스텐션 개발 중에 급한 버그 수정 요청이 들어왔을 때 **기존 작업을 멈추지 않고 옆 폴더에서 바로 수정**할 수 있게 해주는 "로컬용 멀티태스킹 도구"라고 보시면 됩니다.

GitHub에는 오직 작업이 끝난 뒤 `push`한 결과물만 올라갑니다. 안심하고 사용하셔도 됩니다!

### Claude Code가 자동으로 하는 것

```bash
claude --worktree feature-auth
```

내부적으로 아래 순서로 동작합니다.

1. `.claude/worktrees/feature-auth/` 디렉터리 생성
2. `worktree-feature-auth` 브랜치 생성
3. 해당 워크트리에서 Claude 세션 시작

### 수동으로 동일하게 구성

```bash
# 1. worktrees 디렉터리 생성
mkdir -p .claude/worktrees

# 2. 워크트리 + 브랜치 생성
git worktree add .claude/worktrees/feature-auth -b worktree-feature-auth

# 3. 해당 디렉터리로 이동
cd .claude/worktrees/feature-auth

# 4. 의존성 초기화 (필요한 경우)
npm install

# 5. 해당 디렉터리에서 Claude 세션 시작
claude
```

### 작업 완료 후 정리

```bash
# 메인 저장소로 복귀
cd /path/to/main-repo

# 워크트리 제거
git worktree remove .claude/worktrees/feature-auth

# 브랜치 제거 (머지 완료 후)
git branch -d worktree-feature-auth
```

### 비교

||`claude --worktree`|수동|
|---|---|---|
|디렉터리 위치|`.claude/worktrees/자동`|직접 지정|
|브랜치명|`worktree-feature-auth` 자동|직접 지정|
|변경 없으면 정리|자동|수동|
|의존성 초기화|수동|수동|

### 1. Git Worktree로 병렬 작업

하나의 Git 저장소에서 **여러 개의 작업 디렉토리**를 만드는 기능입니다.
커밋 히스토리는 공유하면서 파일 시스템은 완전히 분리됩니다.  
![[Pasted image 20260419160909.png]]

```bash
# 수동 worktree
git worktree add ../project-feature-auth feature/auth

# Claude Code 네이티브 지원 (추천)
claude --worktree feature-auth
claude -w feature-auth

# Sub-Agent에서 격리
isolation: worktree  # 에이전트 설정에 추가
```

💡 `claude -w` 한 줄이면 워크트리 생성 → 브랜치 체크아웃 → 세션 시작까지 자동. 변경 없으면 세션 종료 시 자동 정리됩니다.

### 2. 병렬처리와 서브 에이전트
##### (1) 깃 워크트리를 활용한 병렬 처리
깃 워크트리는 동일한 깃 레포지터리의 다른 브랜치를 별도 디렉터리에 체크아웃할 수 있는 기능이다.
이를 통해 원래 작업 중인 브랜치의 코드에 영향을 주지 않으면서 병렬로 작업할 수 있다.
앤트로픽 공식 문서에서도 깃 워크트리를 이용한 병렬 처리를 권장한다.
git worktree를 사용하면 추가 복제 없이 하나의 .git 디렉터리를 공유하며 여러 작업 환경을 만들 수 있다.

```
git worktree add -b feature-x ./feature-x
git worktree remove feature-x
```

| 부분                 | 설명                          |
| ------------------ | --------------------------- |
| `git worktree add` | 새로운 worktree를 추가하는 명령       |
| `-b feature-x`     | `feature-x`라는 **새 브랜치를 생성** |
| `./feature-x`      | worktree가 체크아웃될 **디렉토리 경로** |

실행 결과)
```
your-repo/          ← 메인 worktree (현재 브랜치)
your-repo/feature-x ← 새로 생성된 worktree (feature-x 브랜치)
```
두 디렉토리가 **같은 `.git`을 공유**하면서 서로 다른 브랜치를 독립적으로 체크아웃한 상태가 됩니다.

##### (2) 병렬 처리 팁
다른 세션의 클로드는 별개의 인격과 같으므로 서로의 작업이 겹치지 않도록 하는 것이 기본적인 팁이다.
따라서 프런트엔드, 벡엔드, 테스트, 인프라 등 각각 담당할 작업을 나누는 것이 좋다.
##### (3)  서브 에이전트 활용
서브 에이전트는 서로 컨텍스트를 공유하지 않기 때문에, 사용자가 매번 컨텍스트를 전환할 필요없이 서브 에이전트가 각 전문 영역의 작업에 집중하도록 할 수 있다.
서브 에이전트는 호출될 때 마다 초기화된 상태로 시작된다. 따라서 작업을 수행하는 데 필요한 정보를 다시 수집하는 데 시간이 걸려서 처리가 느려질 수 있다.

- 서브 에이전트 작성법(대화모드)
서브 에이전트는 설정 파일을 통해서도 만들수 있고, 대화모드에서 바로 생성할 수 도 있다. 대화 모드에서 바로 생성하는 것이 더 쉽고 편리하므로 이를 권장한다.
```
/agents
--> Create new agent
1. Project(.claude/agents): 이번 프로젝트에 참여하는 모든 멤버가 서브에이전트를 함께 사용 가능
2. Personal(~/.claude/agents): 다른 멤버 공유 없이 개인만 사용할 수 있는 서브에이전트 생성
--> Creation method
3. Generate with Claude: 클로드에게 요청하면 좀 더 세밀하게 서브에이전트가 정의
프롬프트: 숙련된 프런트엔드 엔지니어
--> Select tools
서브에이전트 권한 설정
--> Individual tools
세부 권한 개별적 설정
--> Select Model
모델 설정
--> Choose backgroun color
서브에이전트 색상 구분
```
이 내용은 ~/.claude/agents/frontend-expert-engineer.md에 저장된다.
마크다운 파일의 이름은 에이전트의 특성에 따라 클로가 자동으로 지어준다.

- 서브 에이전트 작성법(마크다운 파일 만들어 생성)
사용자 루트나 프로젝트 루트에 .claude/agents 폴더 만들고 원하는 마크다운 파일을 새로 작성하면 된다.
일반적으로는 클로드와의 대화 과정을 통해 에이전트를 만들고, 필요한 부분만 수정하는 방법이 더 편리하다.

- 서브 에이전트 호출법
```
1. <서브에이전트 역할(.md)> XXX를 구현하세요.
2. 백엔드 서브에이전트에서 XXX를 구현하세요.
3. XXX에 가장 적합한 서브에이전트를 구현하세요.
```
##### (4) 언제 서브 에이전트를 사용하나
- 특정 언어나 프레임워크에 특화된 서브에이전트로서 코드를 작성하게 한다.
- 아키텍트 역할로 설계를 맡기고 코드를 리뷰를 진행하게 한다.
- 보안 검토자 역할로 보안에 허점이 없는지 확인하게 한다.
- 테스트 코드에 정통한 테스트 엔지니어로서 테스트를 작성하게 한다.
- 인프라 엔지니어로서 인프라 구축 및 점검 체계를 수립하게 한다.
