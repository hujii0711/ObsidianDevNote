
Claude Code에서 "세션"과 "컨텍스트"는 밀접하지만 다른 개념이에요. 정리하면 이렇습니다.

## 세션 = 컨텍스트를 담는 그릇

**세션**은 터미널을 열고 Claude Code와 나누는 하나의 대화 단위입니다. **컨텍스트(윈도우)**는 그 세션 안에서 모델이 한 번에 "볼 수 있는" 정보의 총량(토큰 기준 최대 용량)이에요.

세션이 진행될수록 컨텍스트는 계속 쌓입니다. 클로드가 사용자의 메시지, 세션의 모든 이전 메시지, 클로드가 읽은 모든 파일, 모든 bash 명령어 출력, 모든 도구 결과를 처리한다고 보면 됩니다. 즉:

```
세션 시작 → 대화 1턴 → 대화 2턴 → 파일 읽기 → 명령 실행 → ...
                    (컨텍스트가 계속 누적됨)
```

## 컨텍스트가 꽉 차면 생기는 문제

컨텍스트가 한계에 가까워지면 모델이 관련 있는 부분을 표면화하는 데 더 어려움을 겪고, 신호 대 잡음 비율이 떨어집니다. 실제로 이런 증상들이 나타나요:

- 이전에 함께 내린 결정과 모순되는 답변을 함
- 특정 프레임워크나 라이브러리, 제약조건을 사용 중이라는 걸 "잊어버림"

## 세션 안에서 컨텍스트를 관리하는 명령어

같은 세션을 유지하면서 컨텍스트만 정리하는 방법들이 있어요.

**`/compact`** — 모델에게 지금까지의 대화를 요약하도록 요청한 뒤, 대화 기록을 그 요약으로 대체합니다. 정보 손실은 있지만 직접 요약을 작성할 필요가 없다는 장점이 있습니다.

**`/clear`** — 대화 기록을 완전히 지우지만, 코드 변경사항은 보존합니다. 즉 "기억"만 리셋하고 실제 작업 결과물은 남아요.

**자동 압축(auto-compact)** — 컨텍스트 윈도우의 약 83.5% 사용량에 도달하면 자동으로 트리거됩니다. 다만 자동 압축이 발동할 때쯤이면 모델이 이미 저하된 상태로 동작하고 있고, 요약 자체도 제약된 조건에서 이뤄지기 때문에 전문가들은 80~95%까지 기다리기보다 60% 정도에서 수동으로 `/compact`를 실행하는 걸 권장합니다.

## 요약하면

|개념|역할|
|---|---|
|세션|하나의 연속된 작업 단위 (터미널 창 하나)|
|컨텍스트 윈도우|그 세션 안에서 모델이 기억할 수 있는 최대 용량 (Claude Code는 1M 토큰)|
|`/compact`|세션은 유지, 컨텍스트만 요약해서 공간 확보|
|`/clear`|세션은 유지, 컨텍스트를 통째로 리셋 (코드는 보존)|
|새 세션 시작|컨텍스트도 완전히 새로 시작|

실전 팁으로는, 관련 없는 새 작업을 시작할 땐 `/clear`, 같은 작업/코드베이스를 이어갈 땐 `/compact`를 쓰는 게 일반적인 패턴입니다.
