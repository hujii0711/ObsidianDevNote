**개발 및 프롬프트 이터레이션(Iteration) 단계**는 개발자가 직접 키보드로 코드를 타이핑하는 대신, 클로드 코드(Claude Code)라는 강력한 AI 조수에게 명령을 내리고 결과를 검토하며 코드를 완성해 나가는 '실전 개발 레이스'입니다.

클로드 코드는 단순히 코드를 추천해 주는 것을 넘어, 프로젝트의 파일을 읽고 쓰고, 터미널 명령어를 실행할 수 있는 '에이전트'이므로 개발자의 역할은 '지휘관 및 감리관'으로 바뀝니다. 이 단계에서 수행해야 할 구체적인 작업 5가지를 정리해 드립니다.

---

## 개발 및 프롬프트 이터레이션의 5가지 구체적 작업

### 1. 기능을 원자 단위(Atomic Task)로 쪼개어 지시하기

기획 단계에서 만든 `prd.md` 전체를 던지며 "이대로 만들어줘"라고 하면 AI는 컨텍스트의 한계나 복잡성 때문에 엉성한 코드를 만듭니다. 기능을 잘게 쪼개어 하나씩 순차적으로 완료해야 합니다.

- **구체적 작업:** 예를 들어 '게시판 기능'을 개발한다면 아래와 같이 쪼개어 한 번에 하나씩만 클로드에게 명령합니다.
    
    1. "1단계: `prd.md`를 참고해서 게시글의 TypeScript `interface` 타입을 `types/post.ts`에 정의해줘."
        
    2. "2단계: 방금 만든 타입을 기반으로, 게시글 목록을 불러오는 Mock API 함수를 `services/post.ts`에 작성해줘."
        
    3. "3단계: Mock 데이터를 화면에 카드 형태로 보여주는 UI 컴포넌트를 `components/PostList.tsx`에 구현해줘."
        

### 2. 명확한 컨텍스트(Reference) 지정 및 첫 프롬프트 던지기

클로드 코드에게 명령을 내릴 때, 어떤 파일들을 참고해야 하는지 명확히 짚어주면 할루시네이션(환각 현상)이 극적으로 줄어듭니다.

- **구체적 작업:** 파일 경로를 명시하여 명령을 시작합니다.
    
    - _좋은 프롬프트 예시:_ `"/prd.md 문서의 '3-1 회원가입' 요구사항과 /src/types/user.ts의 유저 타입을 참고해서, /src/components/SignupForm.tsx 컴포넌트를 구현해줘. 스타일링은 Tailwind CSS를 사용해야 해."`
        
- **효과:** 클로드가 프로젝트 내의 엉뚱한 파일을 뒤지느라 토큰(비용)을 낭비하는 것을 막고, 정확한 코드를 짜냅니다.
    

### 3. AI의 실행 과정 모니터링 및 실시간 개입 (Human-in-the-Loop)

클로드 코드는 명령을 받으면 스스로 `공구(Tool)`를 사용합니다. 파일 목록을 조회(`ls`), 파일 내용 확인(`cat`), 파일 수정(`write`), 터미널 명령어 실행 등을 수행하는데, 이 과정을 실시간으로 지켜보아야 합니다.

- **구체적 작업:** 클로드가 엉뚱한 방향으로 코드를 수정하고 있거나, 쓰지 않기로 한 라이브러리를 갑자기 설치(예: `npm i axios`)하려고 하면, 터미널에서 즉시 실행을 중단(`Ctrl + C`) 시키고 피드백을 주어야 합니다.
    
    - _개입 예시:_ "스톱, 외부 라이브러리 쓰지 말고 내장 `fetch` API를 사용해서 다시 짜줘."
        

### 4. 빌드/린트 에러 피드백 및 자가 치유 루프 (Error Iteration)

클로드가 코드를 다 작성했다고 선언하면, 실제로 컴파일이 잘 되는지, 코드 규칙(Lint)에 맞는지 검증하고 에러를 수정하는 이터레이션을 돕니다.

- **구체적 작업:** 클로드 코드에게 직접 빌드 명령을 내리도록 지시합니다.
    
    - _명령 예시:_ `"이제 터미널에서` npm run build`(또는`npm run lint`)를 실행해서 에러가 없는지 확인해줘. 만약 타입 에러나 컴파일 에러가 발생하면 에러 로그를 보고 코드를 스스로 수정해줘."`
        
- **효과:** 개발자가 에러 로그를 복사해서 붙여넣을 필요 없이, 클로드가 터미널에 찍힌 스택 트레이스(Stack Trace)를 읽고 버그를 알아서 잡아냅니다. 이 과정이 완료될 때까지 프롬프트 대화를 반복(Iteration)합니다.
    

### 5. 점진적 깃(Git) 커밋 및 세이브포인트 구축

AI 개발의 속도는 사람이 코딩할 때보다 5~10배 빠릅니다. 그만큼 코드가 망가지는 속도도 빠릅니다. 하나의 원자적 기능이 성공적으로 빌드되면 반드시 깃 커밋을 남겨야 합니다.

- **구체적 작업:** 기능 하나가 완벽히 동작하고 테스트와 빌드를 통과하면, 클로드에게 커밋까지 시키거나 개발자가 직접 커밋을 남깁니다.
    
    - _명령 예시:_ `"지금까지 작성한 컴포넌트와 서비스 로직의 변경 사항을 확인하고, Conventional Commits 가이드라인에 맞춰서 Git 커밋을 남겨줘."`
        
- **효과:** 다음 기능을 개발하다가 클로드가 코드를 크게 꼬아놓았을 때, 언제든 안전한 상태(`git reset --hard`)로 되돌릴 수 있는 '세이브포인트'가 됩니다.

## 💡 이 단계의 핵심 마인드셋: "말 잘 듣는 신입을 다루는 팀장"

개발 및 프롬프트 이터레이션 단계에서 개발자는 코더가 아니라 '코드 리뷰어이자 팀장'입니다.

클로드가 짠 코드가 마음에 들지 않거나 버그가 있다면 감정적으로 대응하기보다, "어느 파일의 몇 번째 줄 근처 로직이 왜 잘못되었는지, 어떻게 수정하길 원치 않는지"를 구체적인 개발 용어로 지적해 주는 것이 이터레이션 횟수를 줄이고 고품질의 어플리케이션을 빠르게 완성하는 지름길입니다.
