
## 핵심 차이 한 줄 요약

```
내부 피드백 (Hooks + 멀티에이전트)
→ Claude가 작업하는 "도중" 실시간 검증

외부 피드백 (GitHub Actions)
→ 코드가 "제출된 후" 검증
```

---

## 내부 피드백이 유리한 상황

### 1. 즉각적인 자기교정이 필요할 때

작업 중간에 방향이 틀어지는 것을 막아야 할 때

```
Claude가 파일 수정
    ↓ PostToolUse Hook 즉시 실행
테스트 실패 감지
    ↓ 같은 세션 안에서
Claude가 즉시 수정 → 재시도
```

GitHub Actions였다면:
```
커밋 → 푸시 → Actions 실행 (2~5분)
→ 실패 알림 → 개발자가 다시 수정
→ 커밋 → 푸시 → 반복...
```

**장점:** 커밋/푸시 없이 세션 내에서 즉시 교정

---

### 2. 컨텍스트를 유지한 채 검증해야 할 때

Claude가 작업 중인 **의도와 맥락**을 알고 있는 상태에서 검증

```
Claude: "인증 모듈 리팩토링 중"
    ↓
PreToolUse Hook: "보안 관련 파일 수정 감지"
    ↓
같은 컨텍스트로 → "이 변경이 안전한가?" 즉시 판단
```

GitHub Actions는 컨텍스트 없이 코드 결과물만 봄

---

### 3. 멀티에이전트 생성-평가 루프

생성 에이전트와 평가 에이전트를 분리해서 품질을 높일 때

```
생성 에이전트 → 코드 작성
    ↓
평가 에이전트 → 코드 리뷰 (다른 컨텍스트로 객관적 평가)
    ↓
기준 미달 → 생성 에이전트에게 피드백
    ↓
재생성 → 재평가 → 반복
```

**장점:** 자기 작업을 스스로 칭찬하는 편향 제거, 품질 기준 강제

---

### 4. 위험한 명령어 사전 차단

실행 전에 막아야 할 때 (사후 조치가 너무 늦은 경우)

```
PreToolUse Hook (exit code 2)
    ↓
rm -rf / → 즉시 차단 (실행 자체가 안 됨)
프로덕션 DB 직접 수정 → 차단
민감 파일 접근 → 차단
```

GitHub Actions는 실행 후 결과를 보는 구조라 사전 차단 불가

---

### 5. 장기 세션에서 품질 기준 유지

수백 번의 툴 호출이 이어지는 긴 작업에서 일관성 유지

```
세션 시작
  → 툴 호출 1회 → Hook 검증
  → 툴 호출 2회 → Hook 검증
  ...
  → 툴 호출 500회 → Hook 검증 (일관되게 유지)
```

---

## 외부 피드백(GitHub Actions)이 유리한 상황

### 1. 여러 개발자의 코드를 통합 검증할 때

혼자가 아닌 팀 단위 코드가 합쳐질 때

```
개발자 A의 코드 + 개발자 B의 코드 + Claude의 코드
    ↓ PR
GitHub Actions → 통합된 상태로 테스트
```

내부 훅은 각자의 세션만 볼 수 있어서 통합 검증 불가

---

### 2. 표준화된 품질 게이트가 필요할 때

모든 PR에 동일한 기준을 강제해야 할 때

```
어떤 코드든 PR 올리면
→ 무조건 동일한 테스트 실행
→ 커버리지 80% 미달 시 머지 불가
→ 보안 스캔 통과 필수
```

팀 전체에 일관된 기준 적용 → 훅은 개인 세션에만 적용됨

---

### 3. 외부 환경 의존 테스트

실제 인프라, 외부 API, DB가 필요한 테스트

```
GitHub Actions
→ 실제 테스트 DB 연결
→ AWS 환경 연동
→ 외부 API 실제 호출
→ Docker 컨테이너 띄워서 E2E 테스트
```

Claude 세션 내부 훅은 이런 외부 환경 접근이 제한적

---

### 4. 감사 추적(Audit Trail)이 필요할 때

누가 언제 어떤 코드를 배포했는지 기록이 필요한 경우

```
GitHub Actions 로그
→ PR #123, 홍길동, 2026-05-14 10:30
→ 테스트 통과 여부
→ 배포 승인자
→ 배포 시각
모두 영구 기록
```

내부 훅은 세션 종료 후 사라짐

---

### 5. 배포 자동화 자체

코드 검증 이후 실제 서버에 배포하는 작업

```
테스트 통과
    ↓
Docker 이미지 빌드
    ↓
레지스트리 푸시
    ↓
서버 배포
    ↓
헬스체크
```

이건 GitHub Actions의 고유 영역, 내부 훅으로 대체 불가

---

## 함께 쓸 때 가장 강력한 시나리오

```
[Claude 작업 중 - 내부 피드백]
PreToolUse Hook
  → 위험 명령어 사전 차단
  → 보안 파일 접근 제어

PostToolUse Hook
  → 수정 즉시 유닛 테스트
  → 실패 시 같은 세션에서 즉시 재시도

멀티에이전트
  → 생성 에이전트가 코드 작성
  → 평가 에이전트가 품질 채점
  → 기준 미달 시 재생성

        ↓ 내부 검증 통과 후 커밋/푸시

[코드 제출 후 - 외부 피드백]
GitHub Actions
  → 팀 전체 통합 테스트
  → 실제 인프라 E2E 테스트
  → 커버리지 게이트
  → 프로덕션 배포
  → 감사 로그 기록
```

## 한 줄 정리

```
내부 피드백 → "Claude가 실수하지 않도록" 작업 중 교정
외부 피드백 → "팀 전체 기준을 통과했는지" 제출 후 검증

내부는 속도와 컨텍스트,
외부는 신뢰성과 표준화가 장점입니다.
```
