
### 1. 워크트리 생성
```bash
git worktree add ./feature-a -b feature-a

# 기존 브랜치가 있는 경우
git worktree add ./feature-a feature-a
```


### 2. 워크트리 조회
```bash
git worktree list 
```

### 3. 워크트리 삭제
```bash
git worktree remove ./feature-a
```


### 4. 브랜치 확인
```bash
git branch | grep feature-a 
```


### 5. 브랜치 삭제
```bash
git branch -D feature-a
```


### 6. 기타 명령어
```bash
# 변경사항이 있어도 강제 삭제
git worktree remove --force ../project-feature-a

# 이미 삭제된 워크트리 참조 정리
git worktree prune
```


### 7-1. 메인 워크트리에서 직접 머지(방법1)
```bash
# 메인 저장소로 이동
cd /path/to/main-repo

# 워크트리 브랜치를 현재 브랜치에 머지
git merge feature-a

# 또는 rebase
git rebase feature-a
```


### 7-2.  GitHub PR을 통한 머지(방법2)
```bash
# 워크트리 디렉터리에서 push
cd ./worktree/next-js-app
git push origin feature-a

# PR 생성
gh pr create --title "feat: feature-a 구현" --body "Closes #이슈번호"
```


### 7-3. 머지 후 워크트리 정리(방법3)
```bash
# 메인 저장소에서
git worktree remove ./worktree/next-js-app

# 브랜치도 함께 삭제
git branch -d feature-a

# 원격 브랜치 삭제 (PR 머지 후)
git push origin --delete feature-a
```

**Git 워크트리(`git worktree`)는 철저하게 로컬(Local) 시스템에서만 동작하는 기능**입니다.

워크트리를 생성한다고 해서 GitHub 저장소에 새로운 설정이 생기거나 구조가 변하지 않습니다. 이에 대한 핵심적인 특징을 정리해 드립니다.

### 1. 로컬 환경에서의 동작 원리

`git worktree`는 하나의 `.git` 데이터(저장소의 역사와 객체들)를 공유하면서, **서로 다른 브랜치를 별도의 물리적인 폴더에 동시에 체크아웃**해주는 기능입니다.

- **GitHub 입장:** 사용자가 어떤 폴더에서 작업하는지 알 수 없습니다. 오직 `git push`를 통해 커밋이 전송될 때만 변화를 감지합니다.

- **로컬 입장:** `main` 브랜치는 A 폴더에서, `feature` 브랜치는 B 폴더에서 동시에 열어두고 작업할 수 있습니다. 브랜치를 전환(`git switch`)하느라 작업 중인 파일을 `stash`하거나 커밋할 필요가 없어집니다.

### 2. 원격(GitHub)과의 관계

워크트리를 생성하는 과정에서 원격 저장소에 영향을 주는 유일한 경우는 "원격에만 있는 브랜치를 가져와서 워크트리를 만들 때"입니다.

```
# 원격의 feature 브랜치를 가져와서 별도 폴더(my-feature-dir)에 워크트리 생성
git worktree add ../my-feature-dir origin/feature
```

이때도 원격 저장소의 상태가 바뀌는 것이 아니라, 로컬에 해당 브랜치의 복사본(워킹 디렉토리)이 하나 더 생기는 것뿐입니다.

### 3. 워크트리 사용 시 주의할 점 (로컬 관리)

워크트리는 로컬의 폴더와 연결되어 있기 때문에 관리에 주의가 필요합니다.

- **폴더 삭제:** 워크트리로 만든 폴더를 그냥 `rm -rf`로 지우면 Git은 여전히 해당 워크트리가 존재한다고 믿습니다. 반드시 아래 명령어로 정리해야 합니다.

```
# 연결이 끊긴 워크트리 정리
git worktree prune

# 또는 명시적으로 제거
git worktree remove <워크트리_이름>
```
  
- **브랜치 중복 체크아웃 방지:** Git은 기본적으로 동일한 브랜치를 두 개의 워크트리에 동시에 체크아웃하는 것을 막습니다. (혼란 방지 목적)

### 💡 요약하자면

회사 계정 프로젝트와 개인 계정 프로젝트를 동시에 띄워놓고 비교하거나, 현재 진행 중인 VS Code 익스텐션 개발 중에 급한 버그 수정 요청이 들어왔을 때 **기존 작업을 멈추지 않고 옆 폴더에서 바로 수정**할 수 있게 해주는 "로컬용 멀티태스킹 도구"라고 보시면 됩니다.

GitHub에는 오직 작업이 끝난 뒤 `push`한 결과물만 올라갑니다. 안심하고 사용하셔도 됩니다!

`claude --worktree feature-auth`가 내부적으로 하는 작업을 수동으로 풀면 다음과 같습니다.

### Claude Code가 자동으로 하는 것

```bash
claude --worktree feature-auth
```

내부적으로 아래 순서로 동작합니다.

1. `.claude/worktrees/feature-auth/` 디렉터리 생성
2. `worktree-feature-auth` 브랜치 생성
3. 해당 워크트리에서 Claude 세션 시작

### 수동으로 동일하게 구성

```bash
# 1. worktrees 디렉터리 생성
mkdir -p .claude/worktrees

# 2. 워크트리 + 브랜치 생성
git worktree add .claude/worktrees/feature-auth -b worktree-feature-auth

# 3. 해당 디렉터리로 이동
cd .claude/worktrees/feature-auth

# 4. 의존성 초기화 (필요한 경우)
npm install

# 5. 해당 디렉터리에서 Claude 세션 시작
claude
```

### 작업 완료 후 정리

```bash
# 메인 저장소로 복귀
cd /path/to/main-repo

# 워크트리 제거
git worktree remove .claude/worktrees/feature-auth

# 브랜치 제거 (머지 완료 후)
git branch -d worktree-feature-auth
```

### 비교

||`claude --worktree`|수동|
|---|---|---|
|디렉터리 위치|`.claude/worktrees/자동`|직접 지정|
|브랜치명|`worktree-feature-auth` 자동|직접 지정|
|변경 없으면 정리|자동|수동|
|의존성 초기화|수동|수동|
