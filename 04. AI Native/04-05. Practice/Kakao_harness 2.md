**`TeamCreate(...)`는 이 하네스에서 실제로 존재하는 도구(tool)가 아닙니다.** 스킬 작성자가 "에이전트 팀"이라는 개념을 표현하려고 만든 **가상의 표기**입니다. 의도와 실제를 나눠서 설명드리겠습니다.

## 1. 작성자가 의도한 역할

[SKILL.md:61-70](vscode-webview://1tk9858l3ui9jtn3vjirul74fd8dgc9m16qdd5g81kkqb2q1j78g/KakaoHarness2/.claude/skills/shop-orchestrator/SKILL.md#L61-L70)의 Phase 3 맥락을 보면, `TeamCreate("shop-impl", members=[...])`로 의도한 것은:

- **"shop-impl"이라는 이름의 지속적인 에이전트 팀을 생성**
- 멤버: backend / frontend / integration 엔지니어 3명
- 이 팀원들이 **병렬로 일하면서 서로 통신**(SendMessage)하고, **태스크를 분배·의존성 관리**(TaskCreate)한다

즉, "상태를 유지하며 서로 대화하는 팀원들"이라는 멀티에이전트 협업 모델을 그린 것입니다.

## 2. 실제 하네스에는 그런 도구가 없음

이 환경에서 제가 가진 도구 목록에는 **`TeamCreate`, `TaskCreate`, `SendMessage`(팀원 간 통신용) 같은 도구가 없습니다.** 따라서 이 줄을 그대로 실행할 수 없습니다. 작성자가 그린 모델과 실제 메커니즘 사이엔 차이가 있습니다:

|작성자 의도|실제 동작 방식|
|---|---|
|지속적인 "팀" 생성 후 멤버 상주|❌ 팀 개념 없음. 서브에이전트는 **일회성(stateless)** — 호출 → 작업 → 최종 결과 반환 후 종료|
|팀원 간 실시간 SendMessage 통신|⚠️ 서브에이전트끼리 작업 중 대화 불가. (SendMessage는 _내가_ 특정 에이전트를 이어서 호출할 때만 쓰는 개념)|
|TaskCreate로 의존성 있는 태스크 분배|❌ 그런 도구 없음. 의존성은 제가 호출 순서로 직접 통제|

## 3. 같은 목적을 실제로 구현하는 방법

작성자가 원한 "병렬 + 통신 + 의존성"을 이 하네스에서 구현하려면 두 가지 실제 수단이 있습니다:

1. **Agent 도구 (`run_in_background: true`)**
    - 여러 서브에이전트를 동시에 띄워 **병렬 실행**은 가능
    - 단, 팀원 간 직접 통신은 안 됨 → 오케스트레이터인 제가 각 결과를 받아 다음 에이전트에게 전달(중계)하는 방식으로 "통신"을 흉내냄
2. **Workflow 도구** (실제로 의도에 가장 가까움)
    - `parallel()` / `pipeline()` 으로 병렬·파이프라인 오케스트레이션
    - 한 단계의 출력을 다음 단계로 흘려보내 의존성 표현 (TaskCreate의 blocks 관계를 대체)
    - 결정론적 fan-out / fan-in 구조

## 4. 정리

- **`TeamCreate(...)`는 공식/지원 문법 아님** → 실행 불가능한 의사코드(개념 표기)입니다.
- 같은 줄의 `Agent(...)` 표기는 **실제 도구와 대응**되지만, `TeamCreate`·`TaskCreate`·팀원 간 `SendMessage`는 **이 하네스에 대응 도구가 없습니다.**
- 실제로 동작하게 하려면: **순차 호출은 Agent 도구**, **병렬·파이프라인 협업은 Workflow 도구**로 다시 설계해야 합니다.
