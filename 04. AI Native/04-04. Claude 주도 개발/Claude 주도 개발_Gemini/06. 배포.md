**배포(Deployment) 단계**는 지금까지 기획, 설계, 개발, 검증을 거쳐 완벽하게 만들어진 어플리케이션을 로컬 컴퓨터(내 PC)라는 안전한 온실에서 벗어나, **실제 유저들이 접속해서 사용할 수 있는 리얼 월드(운영 서버)로 내보내는 과정**입니다.

클로드 코드(Claude Code)는 터미널에서 클라우드 CLI(AWS, Supabase, Vercel 등)나 Git 명령어를 직접 다룰 수 있으므로, 배포 프로세스 자체를 자동화하거나 인프라 설정을 대신 짜주는 강력한 '데브옵스(DevOps) 조수'로 활용할 수 있습니다.

배포 단계에서 수행해야 할 5가지 구체적인 작업과 AI 활용법을 정리해 드립니다.

---

## 배포 단계의 5가지 구체적 작업

### 1. 환경 변수(Environment Variables) 및 운영 환경 세팅

개발(Development) 환경과 운영(Production) 환경은 데이터베이스 주소, API 키, 결제 모듈 ID 등이 완전히 다릅니다. 운영 환경 전용 설정 파일(`.env.production`)을 세팅해야 합니다.

- **구체적 작업:** 클로드에게 운영 환경에서 필요한 환경 변수 목록 체커를 만들게 하거나, 유출되면 안 되는 보안 키들이 잘 격리되었는지 확인합니다.
    
    - _명령 예시:_ `"프로젝트 내에 개발용 API Key나 로컬 DB 주소가 하드코딩된 곳이 없는지 다시 확인해줘. 그리고 프로덕션 배포 시 필수적으로 셋업해야 하는` .env `환경 변수 템플릿(`env.example`)을 만들어줘."`
        
- **주의점:** 중요 비밀키(Secret Key)는 절대로 GitHub 같은 원격 저장소에 올리지 않고, 배포 플랫폼(Vercel, AWS 시스템 관리자 등)의 환경 변수 설정 칸에 직접 입력해야 합니다.
    

### 2. 프로덕션 빌드(Production Build) 검증

코드를 서버에 올리기 전, 내 컴퓨터나 CI 서버에서 '실제 배포용 파일'로 압축하고 컴파일하는 과정을 거쳐야 합니다. 이 과정에서 숨어있던 타입 에러나 번들링 에러가 자주 발생합니다.

- **구체적 작업:** 클로드 코드가 터미널에서 배포 빌드 명령어를 실행하고 에러를 추적하도록 합니다.
    
    - _명령 예시:_ `"터미널에서 프로덕션 빌드 명령어(`npm run build `또는 프레임워크별 배포 빌드 명령어)를 실행해줘. 빌드 도중 워닝(Warning)이나 에러가 발생하면 로그를 보고 즉시 코드를 수정해서 빌드가 성공하도록 조치해줘."`
        

### 3. CI/CD 파이프라인 구축 및 배포 자동화

코드를 GitHub 메인 브랜치에 푸시(Push)하면 자동으로 테스트가 돌아가고 서버에 배포되도록 만드는 가이프라인을 구축합니다. (Vercel, Netlify, GitHub Actions 등 활용)

- **구체적 작업:** 클로드에게 GitHub Actions 워크플로우 파일(`.github/workflows/deploy.yml`) 작성을 요청합니다.
    
    - _명령 예시:_ `"이 프로젝트를 GitHub 메인 브랜치에 푸시할 때마다 자동 빌드 및 테스트를 수행하고, Vercel(또는 AWS, 데이터베이스 마이그레이션 등)로 자동 배포해주는 GitHub Actions 워크플로우 마크다운 코드를 작성하고 해당 경로에 파일을 생성해줘."`
        

### 4. 데이터베이스 마이그레이션(Database Migration) 실행

앱만 새로 배포된다고 끝나는 것이 아니라, 새 기능에 맞춰 변경된 데이터베이스의 테이블 구조(스키마)를 운영 DB에 반영해야 합니다. 배포 단계에서 가장 사고가 많이 나는 구간입니다.

- **구체적 작업:** Prisma, Drizzle 등 ORM의 프로덕션 마이그레이션 스크립트를 안전하게 실행합니다.
    
    - _명령 예시:_ `"운영 환경에 안전하게 DB 스키마를 동기화하기 위한 마이그레이션 명령어(`npx prisma migrate deploy`등)를 확인하고, 배포 스크립트에 이 단계가 포함되도록`package.json`을 수정해줘."`
        

### 5. 스모크 테스트(Smoke Test) 및 롤백(Rollback) 대책 수립

배포가 완료된 직후, 실제 서비스 URL에 접속하여 가장 핵심이 되는 기능(로그인, 메인 화면 진입 등)이 정상 작동하는지 5분 이내로 가볍게 테스트하는 것을 '스모크 테스트'라고 합니다. 만약 치명적인 버그가 발견되면 즉시 이전 버전으로 돌릴 준비가 되어 있어야 합니다.

- **구체적 작업:** 배포된 라이브 서버의 상태 코드를 확인하고, 실패 시 대책을 세웁니다.
    
    - _명령 예시:_ `"배포가 끝난 후 라이브 서버가 정상 응답(HTTP 200)을 주는지 체크하는 curl 스크립트를 짜줘. 만약 서버 오류(HTTP 500대)가 발생했을 때 이전 커밋 버전으로 빠르게 원클릭 롤백하기 위해 어떤 명령어나 플랫폼 설정을 확인해야 하는지 가이드를 정리해줘."`

## 💡 클로드 코드와 함께하는 배포 체크리스트

배포 직전, 클로드 코드에게 아래 체크리스트를 던져 최종 점검을 진행하면 휴먼 에러를 막을 수 있습니다.

Markdown

```
이제 배포를 진행하려고 한다. 배포 전 최종 안전 점검을 위해 다음 사항을 확인해줘.

1. `console.log`나 개발용 디버깅 코드가 남아있는 파일이 있다면 모두 지우거나 주석 처리해줘.
2. 빌드 산출물의 용량을 최적화할 수 있도록 트리 쉐이킹(Tree Shaking)이나 안 쓰는 임포트(`unused imports`)를 정리해줘.
3. 운영 서버용 `next.config.js` 나 `vite.config.ts` 등 빌드 설정 파일에 이상이 없는지 검토해줘.
```

이 단계까지 무사히 완료되면 기획했던 아이디어가 세상에 나와 빛을 보게 됩니다. 배포 이후에는 운영 환경에서 발생하는 에러 로그를 수집하여 다시 클로드 코드와 함께 고쳐나가는 **운영 및 유지보수(Ops)** 루프로 진입하게 됩니다.
