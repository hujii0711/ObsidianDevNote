# 2. 설계 단계 상세 가이드

Claude Code를 활용한 앱 개발 — 설계 단계에서 해야 할 작업을 네 파트로 정리합니다.

---

## 파트 1. 시스템 아키텍처 설계

전체 시스템의 뼈대를 잡는 단계입니다. 여기서 내린 결정이 이후 모든 개발에 영향을 줍니다.

### 기술 스택 선정 `필수`

프론트엔드, 백엔드, 데이터베이스, 인프라를 확정합니다. PRD의 요구사항(규모, 성능, 팀 역량)을 기반으로 선택하고, 트렌드보다 팀이 잘 아는 기술을 우선합니다.

```bash
claude -p "PRD 기반으로 기술 스택 추천해줘"
```

### 시스템 구성도 작성 `필수`

클라이언트 → API → 서버 → DB → 외부 서비스 간의 관계를 도식화합니다. 모놀리식인지 마이크로서비스인지, 서버리스를 쓸지도 이 단계에서 결정합니다.

```bash
claude -p "기술 스택 기반으로 시스템 구성도 텍스트로 그려줘"
```

### 인프라 및 배포 환경 결정 `권장`

클라우드 제공자(AWS, GCP, Azure, Vercel 등)와 배포 방식을 미리 확정합니다. 개발 / 스테이징 / 프로덕션 환경을 어떻게 분리할지도 함께 정의합니다.

```bash
claude -p "이 스택에 맞는 인프라 구성 추천해줘"
```

## 파트 2. 데이터 설계

어떤 데이터를 어떻게 저장하고 다룰지 정의하는 단계입니다.

### ERD (엔티티 관계 다이어그램) 작성 `필수`

데이터베이스의 테이블(엔티티)과 관계를 정의합니다. 유저 스토리를 기반으로 필요한 데이터가 무엇인지 역으로 추출합니다.

```bash
claude -p "유저 스토리 기반으로 ERD 작성해줘"
```

### 데이터 모델 및 스키마 정의 `필수`

각 테이블의 컬럼, 타입, 제약조건(PK, FK, NOT NULL 등)을 확정합니다. 초기 마이그레이션 파일까지 Claude가 생성해줄 수 있습니다.

```bash
claude -p "ERD 기반으로 SQL 스키마 작성해줘"
```

### 데이터 흐름 정의 `권장`

데이터가 생성되고 읽히고 수정되고 삭제되는 흐름(CRUD)을 정리합니다. 캐싱이 필요한 지점, 실시간 처리가 필요한 지점을 이 단계에서 식별합니다.

```bash
claude -p "주요 기능별 데이터 흐름 정리해줘"
```

## 파트 3. API 설계

프론트엔드와 백엔드가 어떻게 통신할지 계약을 정의하는 단계입니다.

### API 방식 결정 `필수`

REST, GraphQL, gRPC 중 프로젝트에 맞는 방식을 선택합니다.

|방식|적합한 경우|
|---|---|
|REST|일반적인 웹/앱 서비스, 팀 친숙도 높음|
|GraphQL|다양한 클라이언트, 유연한 데이터 조회 필요|
|gRPC|서비스 간 내부 통신, 고성능 요구|

```bash
claude -p "우리 프로젝트에 맞는 API 방식 추천해줘"
```

### API 엔드포인트 명세 작성 `필수`

각 엔드포인트의 URL, HTTP 메서드, 요청/응답 형식, 인증 여부를 정의합니다. OpenAPI(Swagger) 스펙으로 작성하면 문서화와 테스트까지 자동화할 수 있습니다.

```bash
claude -p "유저 스토리 기반으로 REST API 명세 작성해줘"
```

### 인증 및 권한 설계 `필수`

JWT, 세션, OAuth 등 인증 방식을 결정하고, 역할(Role) 기반 권한 구조를 정의합니다. 보안 설계는 개발 후에 추가하기 어렵기 때문에 반드시 이 단계에서 확정합니다.

```bash
claude -p "인증·권한 설계 방안 추천해줘"
```

### 에러 처리 규칙 정의 `권장`

API 전체에서 일관된 에러 응답 형식을 정합니다. 에러 코드 체계, HTTP 상태 코드 사용 규칙, 에러 메시지 형식을 문서화합니다.

```bash
claude -p "API 에러 응답 형식 표준화해줘"
```

## 파트 4. 개발 규칙 및 환경 설계

팀 전체가 일관되게 개발할 수 있는 기준을 세우는 단계입니다.

### 디렉터리 구조 설계 `필수`

프로젝트의 폴더 구조를 확정합니다. 이 구조가 `CLAUDE.md`에 들어가면 Claude Code가 파일을 올바른 위치에 생성합니다.

```bash
claude -p "이 기술 스택에 맞는 디렉터리 구조 잡아줘"
```

### 코딩 컨벤션 정의 `필수`

네이밍 규칙, 코드 스타일, 린트/포맷터 설정을 확정합니다. `.eslintrc`, `.prettierrc` 같은 설정 파일을 Claude가 생성해줄 수 있습니다.

```bash
claude -p "코딩 컨벤션 문서와 린트 설정 파일 만들어줘"
```

### CLAUDE.md 초안 작성 `필수`

설계 단계에서 확정된 모든 내용(기술 스택, 디렉터리 구조, 컨벤션, API 규칙)을 `CLAUDE.md`에 정리합니다. 이 파일이 있어야 Claude Code가 프로젝트 맥락을 이해하고 일관된 코드를 생성합니다.

```bash
claude -p "지금까지 설계 내용으로 CLAUDE.md 초안 작성해줘"
```
