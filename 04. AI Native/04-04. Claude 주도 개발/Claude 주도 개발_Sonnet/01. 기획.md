# 1. 기획 단계 상세 가이드

Claude Code를 활용한 앱 개발 — 기획 단계에서 해야 할 작업을 세 파트로 정리합니다.

---

## 파트 1. 문제 정의

무엇을 왜 만드는지 명확히 하는 단계입니다.

### 문제 및 목표 정의 `필수`

해결하려는 문제가 무엇인지, 앱이 존재해야 하는 이유를 한 문장으로 정의합니다. "무엇을 만드는가"보다 "왜 만드는가"를 먼저 확정합니다.

```bash
claude -p "문제 정의 문서 초안 작성해줘"
```

### 타겟 유저 및 페르소나 설정 `필수`

누가 이 앱을 쓰는지 구체적으로 정의합니다. 나이, 직업, 목표, 불편함(pain point)을 담은 페르소나 1~3개를 작성합니다.

```bash
claude -p "페르소나 3개 작성해줘"
```

### 시장 및 경쟁사 분석 `권장`

유사 서비스의 강점·약점을 파악하고, 우리 앱의 차별점(USP)을 도출합니다. 기능을 무조건 추가하는 게 아니라 "이미 있는 것"을 파악하는 단계입니다.

```bash
claude -p "경쟁사 비교표 만들어줘"
```

---

## 파트 2. 요구사항 정리

실제로 무엇을 만들지 구체화하는 핵심 작업입니다.

### 유저 스토리 작성 `필수`

기능을 개발자 관점이 아닌 유저 관점으로 작성합니다.

형식: **"나는 [유저]로서, [목적]을 위해 [기능]을 할 수 있다."**

Claude가 초안을 빠르게 생성해줍니다.

```bash
claude -p "유저 스토리 20개 작성해줘"
```

### 기능 우선순위 결정 (MVP 정의) `필수`

모든 기능을 첫 버전에 넣을 수 없습니다. MoSCoW 방법으로 분류하고, MVP 범위를 명확히 확정합니다.

|분류|설명|
|---|---|
|Must have|반드시 있어야 하는 핵심 기능|
|Should have|있으면 좋지만 없어도 출시 가능|
|Could have|여유가 있으면 추가|
|Won't have (v1)|이번 버전에서는 제외|

```bash
claude -p "기능 목록 MoSCoW 분류해줘"
```

### PRD (제품 요구사항 문서) 작성 `필수`

문제 정의·페르소나·유저 스토리·MVP 범위를 하나의 문서로 통합합니다. 이 문서가 설계·개발 단계의 기준이 되며, `CLAUDE.md`의 핵심 소스가 됩니다.

```bash
claude -p "PRD 문서 템플릿으로 작성해줘"
```

### 화면 흐름(User Flow) 및 와이어프레임 `권장`

유저가 앱 내에서 어떻게 이동하는지 화면 흐름을 그립니다. 개발 시작 전에 UI/UX 문제를 발견할 수 있는 가장 효과적인 방법입니다.

```bash
claude -p "주요 화면 흐름 텍스트로 정리해줘"
```

## 파트 3. 프로젝트 준비

팀과 일정, 리스크를 정리해서 개발 시작을 준비하는 단계입니다.

### 일정 및 마일스톤 계획 `필수`

MVP 출시까지의 일정을 역산해서 마일스톤을 설정합니다. 각 단계별 소요 시간을 추정하고, 버퍼를 반드시 포함합니다.

```bash
claude -p "MVP 일정 역산해서 짜줘"
```

### 리스크 식별 `권장`

기술적 리스크, 일정 리스크, 외부 의존성(API, 서드파티)을 미리 파악합니다. 리스크를 인지한 상태에서 설계에 들어가면 훨씬 안정적입니다.

```bash
claude -p "PRD 보고 리스크 목록 뽑아줘"
```

- [ ] 유저 스토리 작성 완료
- [ ] MVP 기능 범위 확정
- [ ] PRD 문서 작성 완료
- [ ] 주요 화면 흐름 정리
- [ ] 일정·마일스톤 확정

> **핵심 포인트**: 기획 단계의 최종 산출물은 **PRD 문서** 하나입니다. 이 문서가 탄탄하면 이후 단계에서 `claude -p "PRD 읽고 설계해줘"` 한 줄로 다음 단계를 빠르게 시작할 수 있습니다.
