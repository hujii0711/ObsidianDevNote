
- 메타스킬: 스킬과 에이전트를 만드는 스킬이다. 메타스킬의 출력물은 메타스킬이 한바퀴 돌면 그 자리에 새로운 에이전트파일과 새로운 스킬 파일이 남는다. 메타스킬은 자신이 정의한 규칙을 자기가 따른다. 이것이 자기 참조성이다. 하네스 자체도 SKILL.md 형식으로 작성된 스킬이다.

- 하네스를 구성한다는 것은 `도메인 분석 -> 팀 설계 -> 스킬 -> 정의 -> 오케스트레이션 -> 검증`

| Phase                  | 핵심 질문            | 산출물                       |
| ---------------------- | ---------------- | ------------------------- |
| 1. 도메인 분석(질문을 정제하는 단계) | 무엇을 만드는가         | 분석 메모                     |
| 2. 팀 설계                | 어떤 구조로 꾸리는가      | 팀 설계도                     |
| 3. 에이전트 정의             | 누가 일하는가          | .claude/agents/*.md       |
| 4. 스킬 생성               | 어떻게 일하는가         | .claude/skills/*/SKILL.md |
| 5. 오케스트레이션             | 언제, 어떤 순서로 협업하는가 | 오케스트레이터 + CLAUDE.md       |
| 6. 검증                  | 잘 만들어졌는가         | 테스트 리포트                   |
Phase0. 현황 감사로, 이미 하네스가 있을 때 새로 만들지, 기존 것을 확장할지, 아니면 유지보수만 할지를 먼저 판단한다. `.claude/agents/*.md, .claude/skills/*/SKILL.md, CLAUDE.md` 를 먼저 분석하여, 이번 작업이 신규 구축, 기존 확장, 단순 유지보수 중 어디에 해당하는지 판단한다.
Phase7. 진화로, 완성된 하네스에 피드백을 반영해 계속 개선한다. 이 두 단계가 여섯 단계를 감싸면서 한 번 쓰고 끝나는 구조가 아니라 계속 돌아가는 순환 구조가 된다.

- 에이전트 정의 파일은 에이전트가 다음 세션에서도 다시 불릴 수 있게 하는 연결고리이다. 에이전트의 메모리는 컨텍스트이고 디스크는 `.claude/agents/*.md` 파일이다.

- 오케스트레이션
1) 조율: 태스크 기반(TaskCreate/TaskUpdate)
2) 최종 산출물: 파일 기반(`_workspace/{phase}/_{agent}_{artifact}.{ext}`)
3) 실시간 소통: 메시지 기반(SendMessage)
-> 위 셋은 배타적이지 않다. 팀원이 대용량 결과를 파일로 저장하고, 관련 팀원에게 SendMessage로 저장 완료를 알리며, TaskUpdate로 리더에게 진행률을 보고하는 것이 기본 패턴이다.
