`-`PRD(Product Requirements Document): 제품 요구 사항 문서
"이 서비스가 무엇이고, 어떤 기능을 가져야 하고, 어떤 사용자를 대상으로 한다."를 문서로 정리한 것이다.
`>` @PRD.md를 참고해서 만들어줘(수동 첨부)

`-` PRD의 핵심 목적
1) 제품의 목표와 범위를 명확히 정의한다.
2) 구현해야 할 기능과 우선순위를 구조화한다.
3) 팀 간 해석 차이를 줄여 불필요한 커뮤니케이션 비용을 줄인다.

`-` PRD의 구조
1) 목적(Why): 제품의 존재 이유를 정의한다.
2) 타깃 사용자(Who): 문제를 겪고 있는 구체적인 사용자를 정의한다.
3) 사용자 흐름(User Flow): 사용자가 문제를 해결하기까지 전체 과정을 단계별로 정의한다.
4) 기능 요구 사항과 우선순위: 구현할 기능을 나열하고 반드시 우선순위를 지정한다.

`-` PRD.md 만드는 방법
1) 기본 골격(위 PRD의 구조)을 가진 문서를 기반으로 (클로드, 제미나이, 지피티에게 같은 질문) PRD를 작성하라고 지시한다.
2) 3개의 LLM이 응답 준 내용을 취합하여 PRD를 확정한다.
	이후 클로드 코드로 생성후 지시한 결과물을 다시 수정한다.

`-` CLAUDE.md: 세션이 끝날때까지 컨텍스트에 넣어두고 해당 파일을 함께 들고 간다.
1) 이 프로젝트가 무엇인가
2) 어떤 기술을 사용하는가
3) 어떤 규칙을 따르는가

`-` OMC
클로드 코드에 여러 에이전트를 지휘하는 기능을 더해주는 오픈 소스 도구이다.
(일을 잘게 나누어 각 에이전트에 알맞게 맡기고, 그 결과들이 순서대로 잘 흘러가도록 전체를 조율한다는 의미이다.)

`-`OMC 기능
1) 작업을 분석하여 설계, 구현, 검수 등 역할을 에이전트에 자동으로 분배한다.
2) 작업 난이도에 따라 적절한 모델 티어를 선택하여 비용과 성능을 최적화한다.
3) 실행 과정에서 발생하는 중간 결과를 별도 영역에 기록하여 메인 컨텍스트 오염을 방지한다.
4) 작업 단계에 따라 실행 모드를 자동으로 전환한다.
5) 실행 이력을 파일로 저장하여 중단된 작업을 이어서 진행할 수 있다.

`-`OMC 특징
1) 역할 기반 에이전트 architect, researcher, planner, executor, qa-tester등이 있다.
2) 스킬 시스템 orchestrate, ralph, ultrawork, learner 등 실행 능력을 확장하는 스킬이 있다.
3) HUD 상태 표시로 현재 실행 단계와 에이전트 상채를 실시간으로 시각화한다.
4) 파일 기반 메모리 구조 세션 기록, 실행 상태, 학습된 패턴을 분리 저장하여 긴 작업에서도 맥락을 유지한다.

`-`OMC 아키텍처
보장 레이어: ralph
증강 레이어: ultrawork, git-master, frontend-ui-ux
실행 레이어: default, orchestrate, planner
```
스킬
- default: 기본 실행, 코드 생성, 수정 등 일반적인 작업을 수행한다.
- ultrawork: 여러 파일을 동시에 수정한다. 한 파일씩이 아니라 프로젝트 전체를 병렬로 처리한다.
- git-master: 변경된 파일을 자동으로 커밋하거나 버전 관리를 정리한다.
- ralph: 결과가 기준을 만족할 때까지 테스트 -> 수정 -> 재시도를 반복한다.
  ralph 모드의 경우 할일이 명확(PLAN.md, PRD.md가 있을때)하고 반복 실행으로 완성도를 끌어올릴 수 있는 작업일 때 사용하면 적합
  즉, OMC가 이 조합을 기반으로 다름 실행 흐름을 구성한다.
```
ex) ultrawork: refactor API 호출 -> ultrawork + default + git-master 조합 실행
OMC는 기본 동작 위에 스킬을 레이어처럼 얹는 구조이다. 핵심은 필요한 능력만 골라서 조합한다.

`-` OMC의 상태 관리
OMC는 긴 작업을 안정적으로 수행하기 위해 상태를 파일 기반으로 관리한다. 이를 통해 실행 과정에서 생성된 계획, 결과, 의사 결정 정보를 분리 저장하고, 필요한 정보만 선택적으로 재사용할 수 있다.
.omc/state 디렉터리에서 관리한다.

`-`OMC의 실행 모드
OMC는 작업 성격에 따라 골라 쓸 수 있는 실행 모드를 제공한다.
일반적: /autopilot
복잡한 작업: /team
반드시 성공해야 하는 작업: /ralph
대량 수정: /ultrawork
```
실행 방법
> /autopilot "작업 내용"
```

`-` OMC 플랜 모드로 실행
플랜 모드는 코드에 어떤 변경도 가하지 않은 채, 읽기 전용 상태로 전체 구조를 탐색한다. 그 과정에서 요구 사항을 정리하고 목표를 명확히 정의한 뒤 구현을 위한 계획을 먼저 제시한다.
`>` /omc-plan: 이미 PRD.md가 있을때 적합
`>` /oh-my-claudecode:plan @PRD.md 기반으로 프로젝트 계획을 만들어 보자
-> plan.md파일이 생성된다.
이후 ralph모드로 plan.md와 PRD.md를 기반으로 클로드 코드를 실행해보자.
