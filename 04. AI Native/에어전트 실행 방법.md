CLAUDE.md 외에 에이전트를 효율적으로 실행하는 방법을 4가지 레이어로 정리하면 이렇습니다.

---

## 전체 구조

CLAUDE.md가 계속 커져 절차 문서화 용도로 변질되면 매 세션 토큰을 낭비합니다. 채팅에 붙여넣은 임시 지시는 재사용이 불가능하고, 스킬로 처리해야 할 것을 서브에이전트로 돌리면 불필요한 컨텍스트 격리가 발생합니다. [Product Talk](https://www.producttalk.org/how-to-use-claude-code-features/) 각 도구의 역할이 다릅니다.

---

## 방법 1: 서브에이전트 (`.claude/agents/`)

서브에이전트는 메인 세션이 범위 제한 태스크를 처리하기 위해 생성하는 전문화된 AI 워커입니다. 자체 컨텍스트 창, 프롬프트, 툴 접근 권한, 권한을 갖고 실행됩니다. [GitHub](https://github.com/quemsah/awesome-claude-plugins)

파일 하나로 정의합니다:

```yaml
# .claude/agents/code-reviewer.md
---
name: code-reviewer
description: 코드 변경 후 자동 리뷰. 버그/보안/스타일 체크.
tools: Read, Grep, Glob, Bash   # Write 권한 없음
model: sonnet
skills:
  - api-conventions
---
You are a senior code reviewer...
```

서브에이전트는 부모 스킬을 상속하지 않으므로 필요한 스킬을 명시적으로 프리로드해야 합니다. 스킬 전체 내용이 시작 시 주입됩니다. [Youngleaders](https://www.youngleaders.tech/p/claude-skills-commands-subagents-plugins) 호출은 자연어로 가능합니다: `@"code-reviewer" 인증 모듈 변경사항 확인해줘`

## 방법 2: Hooks (`.claude/settings.json`)

프롬프트가 아닌 **결정론적 코드**로 규칙을 강제합니다.

주요 훅 이벤트는 PreToolUse(도구 실행 전 차단 가능), PostToolUse(완료 후 린터 실행), SessionStart/SessionEnd(세션 수명주기), SubagentStart(서브에이전트 생성 추적), Stop(Claude가 응답을 마칠 때 강제 계속 가능)입니다. [Youngleaders](https://www.youngleaders.tech/p/claude-skills-commands-subagents-plugins)

```json
// .claude/settings.json
{
  "hooks": {
    "PreToolUse": [{
      "matcher": "Bash",
      "hooks": [{ "type": "command", "command": "./scripts/block-dangerous.sh" }]
    }],
    "PostToolUse": [{
      "matcher": "Write",
      "hooks": [{ "type": "command", "command": "npm test -- --findRelatedTests" }]
    }]
  }
}
```

훅 없이는 모든 안전장치가 모델의 지시 이해에 의존합니다. 훅을 사용하면 시스템 레벨에서 규칙을 강제합니다. `rm -rf`를 실행 전에 차단하고, 프로젝트 컨텍스트를 자동 주입하고, 모든 툴 호출을 감사 로깅합니다. [Claude](https://code.claude.com/docs/en/skills)

## 방법 3: Skills (`.claude/skills/`)

스킬만의 핵심 기능: `!command` 문법으로 스킬 내용이 Claude에 전달되기 전에 셸 커맨드를 실행해 출력을 인라인으로 주입합니다. 예를 들어 `!git diff HEAD`를 스킬 안에 넣으면 실행 시점의 실제 diff가 자동으로 컨텍스트에 들어옵니다. [Product Talk](https://www.producttalk.org/how-to-use-claude-code-features/)

```yaml
# .claude/skills/pre-commit-check.md
---
name: pre-commit-check
description: 커밋 전 자동 실행
disable-model-invocation: false
---
## 현재 변경사항
!`git diff HEAD`

## 현재 테스트 상태
!`npm test 2>&1 | tail -20`

위 내용을 보고 위험한 변경사항이 있으면 커밋 전에 알려줘.
```

## 방법 4: Scheduled Tasks (`/schedule`)

클라우드 기반 크론 잡으로 Claude Code를 Anthropic 인프라에서 실행합니다. 스케줄과 프롬프트를 정의하면 크론 인터벌에 맞춰 전체 프로젝트 접근 권한으로 실행됩니다. [GitHub](https://github.com/jeremylongshore/claude-code-plugins-plus-skills)

```bash
claude trigger create --schedule "0 9 * * 1" \
  --prompt "열린 PR 목록 확인 후 주간 요약 작성"
```

## 언제 무엇을 쓸까

| 상황 | 도구 |
|------|------|
| 반복 전문 작업 (리뷰, 테스트) | **서브에이전트** |
| 절대 규칙 강제 (rm 차단, 린트) | **Hooks** |
| 재사용 워크플로우 + 동적 컨텍스트 | **Skills** |
| 주기적 자동 실행 (야간 감사) | **Scheduled Tasks** |
| 전체 프로젝트 맥락 | CLAUDE.md |

스킬부터 시작하세요 — 가장 만들기 쉽고 즉시 가치를 냅니다. 결정론적 강제가 필요할 때 훅을 추가하세요. 병렬 작업이나 컨텍스트 격리가 필요할 때 서브에이전트를 사용하세요. [Claude](https://code.claude.com/docs/en/skills)
