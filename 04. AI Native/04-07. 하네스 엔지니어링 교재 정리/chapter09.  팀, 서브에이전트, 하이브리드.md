
- 팬아웃 구현 방법
1) 에이전트 도구로 서브에이전트를 병렬 호출(서브에이전트 모드)
	- 서브에이전트 모드는 오케스트레이터가 여러 에이전트를 병렬로 호출해놓고 필수 결과만 수집
	- 서브에이전트 모드는 가볍고 빠르지만 에이전트 사이의 상충을 감지하지 못함
	- 오케스트레이터와만 대화하고 팀원끼리는 통신이 이루어지지 않음, 병렬 실행 가능
	- 오케스트레이터는 결과 수집가(단순히 산출물 취합하는 역할)이다.(`_workspace/`)
	- 세션에 제한 없음 
	- 반환값 기반(결과 수집) + 파일 기반(대용량 산출물) 조합을 권장
	
2) TeamCreate로 에이전트 팀 생성(팀 모드)
	-  팀 모드는 멤버끼리 SendMessage로 직접 대화하고 공유 작업 목록으로 자체 조율
	- 팀 모드는 상호 검증과 발경 공유로 품질을 끌어올리지만 오버헤드가 높다.
	- 멤버 사이에 양방향 통신이 이루어짐(SendMessage)
	- 세션당 한 팀만 활성화됨
	- 태스크 기반(조율) + 파일 기반(산출물) + 메시지 기반(실시간 소통) 조합을 권장

- 에이전트 팀이 최우선 기본값이다. 2개 이상의 에이전트가 협업할 때는 반드시 에이전트 팀을 먼저 검토한다. 팀원 간 직접 통신(SendMessage)과 공유 작업 목록(TaskCreate)으로 자체 조율하며, 발견. 공유. 상충 토론. 누락 보완이 결과 품질을 높인다.

- 세 가지 실행모드

| 모드         | 언제 사용                             | 도구 조합                                          | 통신          | 오버헤드 |
| ---------- | --------------------------------- | ---------------------------------------------- | ----------- | ---- |
| 에이전트 팀(기본) | 두명 이상 협업<br>실시간 조율. 피드백 <br>교환 필요 | TeamCrete +<br>TaskCreate +<br>SendMessage     | 양방향 N-way   | 높음   |
| 서브에이전트(대안) | 단일 작업, 결과만 메인에 <br>반환             | 에이전트 직접 호출<br>run_in_background: <br>true 로 병렬 | 일방향(결과 반환만) | 낮음   |
| 하이브리드      | Phase마다 특성이 다름                    | Phase 단위로 팀. <br>서브 혼용                         | Phase별 전환   | 가변   |

- 실행 모드에 따른 데이터 전달 프로토콜

| 전략                  | 적용 모드         | 적합한 경우          |
| ------------------- | ------------- | --------------- |
| 메시지 기반(SendMessage) | 팀 전용          | 실시간 조율, 피드백 교환  |
| 태스크 기반(TaskCreate)  | 팀 전용          | 진행 상황 추적, 의존 관계 |
| 파일 기반(_workspace)   | 팀 + 서브에이전트 공통 | 대용량 산출물, 감사 추적  |
| 반환값 기반              | 서브에이전트 전용     | 서브 결과를 메인이 수집   |

- 에이전트 팀 vs 서브에이전트 선택 기준으로 "동시에 소통해야 하느냐"를 여부로 판단한다.
-> 실시간 소통 필요: 에이전트 팀

- 서브 에이전트 팀 선택 기준
1) 에이전트 사이 산출물이 완전히 독립이다.
2) 에이전트 사이 상충 가능성이 없다.
3) 작업이 단발성 수행이다.
4) 팀 초기화 오버헤드가 작업 자체보다 크다.

- 오케스트레이터는 팀 전체를 조율하는 상위 스킬이다. 실행 모드별 세 가지 템플릿을 제공한다.
	1) 템플릿 A. 에이전트 팀 모드(기본): 2인 이상 협업 시 최우선
	2) 팀플릿 B. 서브에이전트 모드(대안): 팀 통신이 불필요한 경우
	3) 템플릿 C. 하이브리드 모드: Phase 마다 모드를 섞어 구성

- 하이브리드 모드에서는 각 Phase의 실행 모드가 오케스트레이터에 명시되었는지, Phase 경계에서 데이터 전달이 끊기지 않는지 확인(팀 -> 서브 전환시 팀의 산출물이 서브의 입력으로 연결되는지), Phase 경계에서 산출물 경로를 파일 기반으로 남기는 것이 중요하다.
