
- 하네스는 누가(에이전트), 어떻게(스킬), 언제 누구와(오케스트레이터)라는 세 가지 요소로 나뉘며, 이들은 독립적으로 설계되고 실행 시점에만 맞물린다.

- 오케스트레이터는 '이 작업을 언제, 누구와 하는가'에 답한다. 팀 구성, 작업 의존성, 단계 전환이 오케스트레이터의 영역이다. 오케스트레션은 주로 실행 흐름을 담고 있다. 사용자 요청이 들어오면 세션 안의 메인 루프 팀을 구성하고, 단계를 전환하고, 팀을 해체한다. 오케스트레이션 규칙 자체는 스킬 본문이나 CLAUDE.md에 기록될 수 있지만, 그 실행자는 런타임의 메인 루프이다.

- TaskCreate 같은 기본 도구는 오케스트레이터가 'A에게 이걸 시켜라. 그 다음에 실행해라'를 기록하는 수단이다. 기록하는 주체는 오케스트레이터이고, 기록하는 내용도 결국 '언제 누구와'라는 오케스트레이터의 관심사이다. 

- '커밋 메시지는 이렇게 만든다' 같은 절차적 지식은 스킬에 정의하고, '다른 에이전트 3명과 병렬로 실행한다.' 같은 조율 규칙은 오케스트레이터에 넣어야 한다.

- 오케스트레이터는 누가(members), 언제(TaskCreate), 누구와(SendMessage)를 결정한다. 하지만 각 팀원이 어떻게 판단할지는 각자의 에이전트 파일에 어떤 절차를 따를지는 각자의 스킬에 맡겨 둔다. 오케스트레이터는 팀원에게 일일이 지시하지 않고, 누가 언제 누구와 함께 움직일지만 조율한다. 오케스트레이터는 에이전트나 스킬을 지배하는 것이 아니다. 오케스트레이터가 하는 일은 '누가 언제 무엇을 하는가'를 시간 순서로 정하는 것이고, 실제 판단과 절차는 여전히 에이전트와 스킬의 몫이다. 

- Fork는 부모 세션의 컨텍스트를 이어받아 별도의 자식 에이전트로 분기 실행하는 패턴이다.

| 구분          | 에이전트(누가)           | 스킬(어떻게)                | 오케스트레이터(언제. 누구와)       |
| ----------- | ------------------ | ---------------------- | ---------------------- |
| 개념          | 누가 이 작업을 맡는가       | 이 작업을 어떤 절차로 하는가       | 누가 언제 누구와 무엇을 하는가      |
| 정의하는 것      | 역할 설정, 판단 기준 협업 규칙 | 워크플로, 트리거, 절차적 지식      | 팀 구성, 작업 의존성, Phase 전환 |
| 파일 위치       |                    |                        | 세션 런타임 + CLAUDE.md 포인터 |
| 영속 단위       | 역할(세션 간 재사용)       | 절차(세션 간 재사용)           | 실행 흐름(세션마다 새로 구성)      |
| 트리거         | 에이전트 도구로 명시 호출     | description 매칭으로 자동 로드 | 사용자 요청, 단계 전환          |
| 부재 시 생기는 문제 | 역할 표류, 매 세션 재정의    | 매번 절차 재발명, 결과 편차       | 리더 병목, 순차 퇴행           |

- 메타스킬은 오케스트레이션 자체를 목적으로 만든 스킬이다. harness처럼 Phase 0 ~ Phase 7을 선언하고 팀을 구성, 해체하는 스킬은 본문 안에 조율 로직을 담는 것이 정석이다.

- 오케스트레이터는 설계자 역할만 한다. 시작 전에 팀을 구성하고 작업을 나눠주고, 실행 중에는 팀원들이 SendMessage로 직접 소통하게 두고, 끝나면 결과를 통합하고 팀을 해제한다. 팀원이 작업 결과를 파일로 저장하고, 관련 팀원에게 직접 알리고, 공유 작업 목록에 진행 상황을 직접 기록하는 것이 올바른 구조이다. 리더는 중개하지 않는다.

- 스킬은 '어떻게 하는가'를 담는 그릇이자 절차적 지식을 정리하는 자산이다. 공통 지식을 스킬로 분리할 수 있다. `.claude/skills/common/SKILL.md`처럼 독립된 파일로 빼두면, 여러 에이전트가 같은 기준으로 움직이게 된다.
