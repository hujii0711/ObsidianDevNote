
> Context Engineering: 에이전트에게 줄 정보를 전략적으로 설계한다.

클로드 코드에서 프로젝트의 컨텍스트, 코딩 컨벤션, 명령어 규칙 등을 정의해두는 설정 파일로, Claude가 프로젝트를 이해하고 일관된 방식으로 코드를 작성하도록 안내하는 '프로젝트 지침서' 역할을 한다.
CLAUDE.md는 매 대화 시작시 자동으로 컨텍스트에 로드되기 때문에, 반복적으로 프로젝트 규칙이나 선호 사항을 설명할 필요 없이 제한된 컨텍스트 윈도우를 효율적으로 활용할 수 있게 해준다. 즉 토큰 낭비를 줄이면서도 Claude가 항상 프로젝트 맥락을 파악한 상태에서 작업을 시작하도록 보장하는 핵심 컨텍스트 관리 도구이다.

### 1. claude.md에 넣어야 할 내용
- **절대 규칙** — 위반하면 안 되는 금지 사항 (맨 위에 배치)
- **아키텍처** — 폴더 구조, 기술 스택
- **빌드/테스트** — 개발 서버, 테스트, 배포 명령어
- **도메인 컨텍스트** — 비즈니스 용어, 데이터 흐름
- **코딩 컨벤션** — 네이밍, 커밋, 패턴 규칙

### 2. Lazy Loading - CLAUDE.md 참조 구조

- ❌ 나쁜 예 — 모든 내용을 CLAUDE.md 에 직접 작성
```markdown
# CLAUDE.md (나쁜 예)
## API 엔드포인트
- POST /api/auth/login - 로그인...
- POST /api/auth/register - 회원가입...
- GET /api/users/:id - 유저 조회...
- ... (50개 더)
```
 
- ✅ 좋은 예 — 한 줄짜리 참조만 남기기
- 핵심 원칙: CLAUDE.md에는 규칙과 참조만, 상세 내용은 별도 파일로 분리
```markdown
# CLAUDE.md (좋은 예)
## 프로젝트 문서
- API 스펙: @docs/api-spec.md
- DB 스키마: @docs/db-schema.md
- 인증 설계: @docs/auth.md
- 코딩 컨벤션: @docs/conventions.md
```
Claude는 필요할 때만 해당 파일을 읽습니다. 이게 바로 **Lazy Loading**입니다.

💡 **폴더별 [CLAUDE.md](http://CLAUDE.md)**: `src/auth/CLAUDE.md`, `src/payments/CLAUDE.md`처럼 폴더별로 분리하면 Claude가 해당 폴더 작업 시에만 해당 [CLAUDE.md](http://CLAUDE.md)를 읽어 컨텍스트 bloat을 방지합니다.

### 3. CLAUDE.md 작성 원칙
- **Non-obvious 패턴 명시**: AI가 실패할 때마다 CLAUDE.md에 한 줄 추가하여 같은 실수 방지 
- 루트 cloud.md는 100~200줄 이하로 유지: 매 세션마다 컨텍스트에 포함되므로 간결해야 함  
- **인덱스 역할**: 백과사전이 아닌 나침반처럼, 정보의 위치만 안내  
- **자동 갱신 필수**: 썩어가는 컨텍스트는 없는 것보다 나쁨  
- 세션 종료 시 또는 주기적으로 훅을 통해 자동 갱신
