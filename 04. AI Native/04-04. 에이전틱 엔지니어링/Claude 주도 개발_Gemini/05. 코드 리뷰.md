**코드 리뷰 및 보안/성능 검증 단계**는 클로드 코드(Claude Code)가 짜놓은 코드가 기능적으로 '돌아가기만 하는 상태'를 넘어, 프로덕션 환경(실제 서비스)에 올려도 안전하고 안정적인 **'고품질의 상태'로 빌드업하는 최종 방어선**입니다.

AI는 코드를 빠르게 짜지만 안전성, 보안, 대규모 데이터 처리 시의 성능 최적화 등 눈에 보이지 않는 영역에서 실수를 할 수 있습니다. 이 단계에서 수행해야 할 5가지 구체적인 작업과 클로드 코드를 활용하는 방법을 알려드립니다.

---

## 코드 리뷰 및 보안/성능 검증의 5가지 구체적 작업

### 1. 요구사항 및 코딩 컨벤션 교차 검증 (Alignment Check)

클로드가 작성한 최종 코드가 기획서(`prd.md`)의 세부 조항을 빼먹지 않았는지, 그리고 설계 단계에서 정한 규칙(`.clauderules`)을 철저히 지켰는지 검증합니다.

- **구체적 작업:** 클로드에게 전체 코드를 다시 한번 감사(Audit)하도록 요청합니다.
    
    - _명령 예시:_ `"/prd.md의 요구사항과 비교했을 때 현재 코드에서 누락된 예외 처리나 비즈니스 로직이 있는지 전수 조사해줘. 그리고` .clauderules`에 명시한 Zustand 상태 관리 컨벤션을 깨뜨린 코드가 있다면 찾아서 리포트해줘."`
        
- **효과:** 개발자가 일일이 코드를 대조하지 않아도 AI가 규칙 위반이나 요구사항 누락을 빠르게 잡아냅니다.
    

### 2. AI 기반 보안 취약점 감사 (Security Audit)

웹/앱 어플리케이션에서 흔히 발생하는 보안 허점(OWASP Top 10 등)이나 실수로 포함된 중요 정보가 없는지 정적 분석을 수행합니다.

- **구체적 작업:** 클로드에게 공격자(Hacker)의 관점에서 코드를 리뷰하라고 지시합니다.
    
    - _명령 예시:_ `"보안 전문가 관점에서 현재 코드의 취약점을 분석해줘. 특히 SQL 인젝션, XSS(크로스 사이트 스크립팅), CSRF, 그리고 API Key나 비밀번호가 소스코드에 하드코딩(Hardcoded)된 부분이 없는지 샅샅이 찾아내고, 발견되면 안전한 코드로 리팩토링해줘."`
        
- **효과:** `.env` 파일에 들어가야 할 유출되면 안 되는 토큰이나, 무방비한 데이터베이스 쿼리문 등을 배포 전에 차단할 수 있습니다.
    

### 3. 성능 병목 및 리소스 누수 점검 (Performance & Leak Review)

데이터가 많아지거나 사용자가 몰릴 때 앱이 느려지거나 서버가 터질 수 있는 구간을 찾아 최적화합니다.

- **구체적 작업:** 기술 스택별로 자주 발생하는 성능 저하 요소를 짚어서 클로드에게 조사를 시킵니다.
    
    - _프론트엔드(React/Next.js) 예시:_ `"현재 컴포넌트 구조에서 불필요한 리렌더링(Re-rendering)이 자주 발생할 만한 구간이나 메모리 누수(Memory Leak) 위험이 있는` useEffect `구문이 있는지 확인하고 최적화해줘."`
        
    - _백엔드/DB 예시:_ `"DB 조회 로직 중에 N+1 Query 문제가 발생하여 성능을 저하시키는 구간이 없는지 보고, 인덱스(Index) 처리가 필요한 컬럼을 제안해줘."`
        

### 4. 코드 가독성 및 아키텍처 리팩토링 (Refactoring)

AI가 기능을 급하게 구현하다 보면 중복 코드가 생기거나 함수가 너무 비대해질 수 있습니다. 이를 깔끔하게 정리하는 '청소 작업'을 합니다.

- **구체적 작업:** 코드의 복잡도를 낮추고 가독성을 높이는 작업을 지시합니다.
    
    - _명령 예시:_ `"여러 파일에 중복으로 작성된 유틸리티 로직이 있다면` utils/`폴더로 공통화해줘. 하나의 함수가 너무 많은 책임을 지고 있다면 잘게 쪼개주고, TypeScript에서 무분별하게 사용된`any `타입을 구체적인 인터페이스 타입으로 대체해줘."`
        

### 5. 인간 개발자의 최종 디프(Diff) 검토 및 승인 (Human Sign-off)

아무리 AI가 훌륭하게 리뷰하고 고쳤더라도, **최종 병합(Merge)과 배포 승인은 인간 개발자의 몫**입니다.

- **구체적 작업:** `git diff` 명령어를 통해 클로드 코드가 수정한 내역을 줄 단위(Line-by-Line)로 눈으로 직접 확인합니다. 비즈니스 로직의 흐름이 상식적이고 우아하게 짜였는지 개발자의 직관과 경험으로 최종 판단을 내립니다. 이상이 없다면 메인 브랜치에 코드를 병합합니다.

## 💡 이 단계의 핵심 프롬프트 패턴

코드 리뷰 단계에 진입했을 때, 클로드 코드 터미널에 아래 프롬프트를 복사해서 실행해 보세요. 단계별 검증을 효율적으로 시작할 수 있습니다.

Markdown

```
지금부터 '코드 리뷰 및 보안/성능 검증' 단계를 시작한다. 
내가 작성하라고 했던 기능들이 완성되었으니, 다음 3가지 관점에서 프로젝트 전체 코드를 검사하고 보고서를 작성해줘.

1. 보안: 하드코딩된 Key, 인젝션 취약점, 데이터 검증 누락 여부
2. 성능: 무분별한 루프, 불필요한 비동기 블로킹(Blocking), 메모리 누수 위험
3. 품질: 중복 코드, 매직 넘버 사용, TypeScript 타입 안정성 

이상이 발견된 파일과 라인 번호를 명시하고, 어떻게 고쳐야 하는지 리팩토링 코드 예시를 함께 제안해줘.
```

이렇게 검증 단계를 거치면, 배포 후 프로덕션 환경에서 장애가 발생할 확률을 획기적으로 낮출 수 있으며 기술 부채가 없는 깨끗한 코드베이스를 유지할 수 있게 됩니다.
