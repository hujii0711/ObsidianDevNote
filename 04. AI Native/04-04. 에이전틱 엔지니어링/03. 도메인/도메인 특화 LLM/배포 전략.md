## 1. 서버 사전 준비

서버에 처음 한 번만 수행하는 작업입니다.

```bash
# 앱 서버 (CPU)
sudo apt update && sudo apt install -y docker.io nginx git rsync

# GPU 서버 (모델 서빙용)
sudo apt install -y nvidia-container-toolkit   # NVIDIA GPU 환경
# 또는 llama.cpp 직접 빌드 (CPU fallback 가능)

# 배포 전용 유저 생성
sudo useradd -m -s /bin/bash deployer
sudo usermod -aG docker deployer

# 앱 디렉터리 + 모델 디렉터리 준비
sudo mkdir -p /srv/rag/{backend,frontend,chroma-data,pg-data}
sudo mkdir -p /srv/models/fused
sudo chown -R deployer:deployer /srv/rag /srv/models

# GitHub Actions에서 SSH 접속할 수 있도록 공개키 등록
sudo -u deployer mkdir -p /home/deployer/.ssh
echo "공개키_내용" >> /home/deployer/.ssh/authorized_keys
```

## 2. systemd 서비스 유닛 파일

서버에 `/etc/systemd/system/` 아래에 각각 작성합니다.

### `rag-postgres.service`

```ini
[Unit]
Description=RAG PostgreSQL
After=docker.service
Requires=docker.service

[Service]
User=deployer
Restart=always
RestartSec=5

ExecStartPre=-/usr/bin/docker rm -f rag-postgres
ExecStart=/usr/bin/docker run --rm \
  --name rag-postgres \
  -e POSTGRES_USER=rag \
  -e POSTGRES_PASSWORD_FILE=/run/secrets/pg_password \
  -e POSTGRES_DB=ragdb \
  -v /srv/rag/pg-data:/var/lib/postgresql/data \
  -p 127.0.0.1:5432:5432 \
  postgres:16-alpine

ExecStop=/usr/bin/docker stop rag-postgres

[Install]
WantedBy=multi-user.target
```

### `rag-chroma.service`

```ini
[Unit]
Description=RAG Chroma Vector DB
After=docker.service
Requires=docker.service

[Service]
User=deployer

ExecStartPre=-/usr/bin/docker rm -f rag-chroma
ExecStart=/usr/bin/docker run --rm \

[Install]
```

### `rag-model.service` — GPU 서버용

```ini
[Unit]
Description=RAG Model Serving (vLLM)
After=docker.service
Requires=docker.service

[Service]
User=deployer
Restart=always
RestartSec=10

# 모델 파일은 rsync로 배포됨 (/srv/models/fused/)
ExecStartPre=-/usr/bin/docker rm -f rag-model
ExecStart=/usr/bin/docker run --rm \
  --name rag-model \
  --gpus all \
  -v /srv/models:/srv/models:ro \
  -p 127.0.0.1:8001:8001 \
  vllm/vllm-openai:latest \
  --model /srv/models/fused/llama-3.1-8b-rag-v1 \
  --port 8001 \
  --host 0.0.0.0 \
  --max-model-len 4096

ExecStop=/usr/bin/docker stop rag-model

[Install]
WantedBy=multi-user.target
```

### `rag-backend.service`

```ini
[Unit]
Description=RAG Backend (FastAPI)
After=rag-postgres.service rag-chroma.service rag-model.service
Requires=rag-postgres.service rag-chroma.service

[Service]
User=deployer
Restart=always
RestartSec=5
EnvironmentFile=/srv/rag/.env.prod

# 이미지 태그는 배포 스크립트가 /srv/rag/.image-tag에 기록
ExecStartPre=-/usr/bin/docker rm -f rag-backend
ExecStartPre=/bin/bash -c \
  'IMAGE=$(cat /srv/rag/.image-tag-backend); \
   docker pull $IMAGE'
ExecStart=/bin/bash -c \
  'IMAGE=$(cat /srv/rag/.image-tag-backend); \
   docker run --rm --name rag-backend \
     --env-file /srv/rag/.env.prod \
     --network host \
     -p 127.0.0.1:8000:8000 \
     $IMAGE'

ExecStop=/usr/bin/docker stop rag-backend

[Install]
WantedBy=multi-user.target
```

### `rag-frontend.service`

```ini
[Unit]
Description=RAG Frontend (Next.js)
After=rag-backend.service

[Service]
User=deployer
Restart=always
RestartSec=5

ExecStartPre=-/usr/bin/docker rm -f rag-frontend
ExecStartPre=/bin/bash -c \
  'IMAGE=$(cat /srv/rag/.image-tag-frontend); \
   docker pull $IMAGE'
ExecStart=/bin/bash -c \
  'IMAGE=$(cat /srv/rag/.image-tag-frontend); \
   docker run --rm --name rag-frontend \
     -e NEXT_PUBLIC_API_URL=http://localhost:8000 \
     -p 127.0.0.1:3000:3000 \
     $IMAGE'

ExecStop=/usr/bin/docker stop rag-frontend

[Install]
WantedBy=multi-user.target
```

서비스 등록:

```bash
sudo systemctl daemon-reload
sudo systemctl enable rag-postgres rag-chroma rag-model rag-backend rag-frontend
sudo systemctl start  rag-postgres rag-chroma
# model 서버 준비 후
sudo systemctl start  rag-model rag-backend rag-frontend
```

## 3. Nginx 설정 `/etc/nginx/sites-available/rag`

```nginx
upstream backend  { server 127.0.0.1:8000; }
upstream frontend { server 127.0.0.1:3000; }

server {
    listen 80;
    server_name rag.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    server_name rag.example.com;

    ssl_certificate     /etc/letsencrypt/live/rag.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/rag.example.com/privkey.pem;

    # 파일 업로드 크기 제한 (문서 업로드용)
    client_max_body_size 100M;

    # API는 /api/ 로 라우팅
    location /api/ {
        proxy_pass         http://backend/;
        proxy_set_header   Host $host;
        proxy_set_header   X-Real-IP $remote_addr;
        proxy_read_timeout 120s;  # LLM 응답 대기
    }

    # 나머지는 Next.js
    location / {
        proxy_pass       http://frontend;
        proxy_set_header Host $host;
    }
}
```

## 4. GitHub Actions 배포 워크플로

### `.github/workflows/deploy.yml` — 앱 배포

```yaml
name: Deploy

on:
  push:
    branches: [main]
    paths-ignore:
      - 'finetuning/**'   # 파인튜닝 변경은 별도 워크플로

env:
  REGISTRY: ghcr.io
  IMAGE_BASE: ghcr.io/${{ github.repository_owner }}

jobs:
  ci:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Install uv
        uses: astral-sh/setup-uv@v4

      - name: Backend lint + test
        working-directory: backend
        run: |
          uv sync
          uv run ruff check .
          uv run mypy app/
          uv run pytest --tb=short
        env:
          DATABASE_URL: sqlite+aiosqlite:///./test.db

      - name: Frontend lint + build
        working-directory: frontend
        run: |
          npm ci
          npm run lint
          npm run build

  build-push:
    needs: ci
    runs-on: ubuntu-latest
    permissions:
      contents: read
      packages: write

    steps:
      - uses: actions/checkout@v4

      - name: Log in to GHCR
        uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: Build & push backend
        uses: docker/build-push-action@v5
        with:
          context: ./backend
          push: true
          tags: |
            ${{ env.IMAGE_BASE }}/rag-backend:${{ github.sha }}
            ${{ env.IMAGE_BASE }}/rag-backend:latest

      - name: Build & push frontend
        uses: docker/build-push-action@v5
        with:
          context: ./frontend
          push: true
          tags: |
            ${{ env.IMAGE_BASE }}/rag-frontend:${{ github.sha }}
            ${{ env.IMAGE_BASE }}/rag-frontend:latest

  deploy:
    needs: build-push
    runs-on: ubuntu-latest

    steps:
      - name: Deploy to app server via SSH
        uses: appleboy/ssh-action@v1
        with:
          host:     ${{ secrets.APP_SERVER_HOST }}
          username: deployer
          key:      ${{ secrets.APP_SERVER_SSH_KEY }}
          script: |
            set -e
            SHA=${{ github.sha }}

            # 새 이미지 태그 기록
            echo "ghcr.io/${{ github.repository_owner }}/rag-backend:$SHA" \
              > /srv/rag/.image-tag-backend
            echo "ghcr.io/${{ github.repository_owner }}/rag-frontend:$SHA" \
              > /srv/rag/.image-tag-frontend

            # 순서대로 재기동
            sudo systemctl restart rag-backend
            sleep 5

            # 헬스체크
            curl -sf http://localhost:8000/health || \
              (echo "Backend health check failed"; exit 1)

            sudo systemctl restart rag-frontend
            sleep 3

            sudo systemctl reload nginx
            echo "Deploy $SHA succeeded"
```

### `.github/workflows/deploy-model.yml` — 모델 배포 (별도)

```yaml
name: Deploy Model

on:
  workflow_dispatch:        # 수동 트리거만 (모델은 자동 배포 금지)
    inputs:
      model_version:
        description: 'finetuning/outputs/fused/ 하위 폴더명'
        required: true
        default: 'llama-3.1-8b-rag-v1'

jobs:
  deploy-model:
    runs-on: ubuntu-latest

    steps:
      - uses: actions/checkout@v4

      - name: Upload model to GPU server
        uses: appleboy/ssh-action@v1
        with:
          host:     ${{ secrets.GPU_SERVER_HOST }}
          username: deployer
          key:      ${{ secrets.GPU_SERVER_SSH_KEY }}
          script: |
            set -e
            VERSION="${{ github.event.inputs.model_version }}"

            # 기존 서비스 중단
            sudo systemctl stop rag-model

            # 모델 파일 rsync (M4 MacBook에서 미리 서버로 전송됐다고 가정)
            # 실제로는 별도 스토리지(NAS, S3 호환)에서 pull
            rsync -avz --delete \
              /srv/models/staging/$VERSION/ \
              /srv/models/fused/

            # 서비스 재기동
            sudo systemctl start rag-model
            sleep 15

            # 헬스체크
            curl -sf http://localhost:8001/health || \
              (echo "Model server health check failed"; exit 1)

            echo "Model $VERSION deployed"
```

## 5. 롤백 절차

배포가 실패했을 때 즉시 이전 버전으로 되돌리는 방법입니다.

```bash
# 앱 서버에서 직접 실행
# 이전 SHA 확인
docker images ghcr.io/org/rag-backend --format "{{.Tag}}"

# 이전 태그로 롤백
echo "ghcr.io/org/rag-backend:이전SHA" > /srv/rag/.image-tag-backend
echo "ghcr.io/org/rag-frontend:이전SHA" > /srv/rag/.image-tag-frontend

sudo systemctl restart rag-backend rag-frontend
```

GitHub Actions에서도 트리거할 수 있도록 `workflow_dispatch` + `sha` 입력을 `deploy.yml`에 추가해 두면 UI에서 원클릭 롤백이 가능합니다.

## 6. GitHub Secrets 설정 목록

|Secret 이름|내용|
|---|---|
|`APP_SERVER_HOST`|앱 서버 IP/도메인|
|`APP_SERVER_SSH_KEY`|deployer 계정 SSH 비밀키|
|`GPU_SERVER_HOST`|GPU 서버 IP|
|`GPU_SERVER_SSH_KEY`|GPU 서버 SSH 비밀키|
|`GITHUB_TOKEN`|GHCR 푸시용 (자동 제공)|

서버의 `/srv/rag/.env.prod`에는 `OPENAI_API_KEY`, `DATABASE_URL`, `SECRET_KEY` 등 민감 정보를 직접 관리하고, GitHub Secrets에는 절대 평문 DB 비밀번호를 넣지 않는 게 원칙입니다.

## 7. 모델 파일 서버 전송 흐름 (M4 → GPU 서버)

파인튜닝 완료 후 모델 파일(수~수십 GB)은 GitHub Actions를 거치지 않고 직접 전송합니다.

```bash
# M4에서 실행 — fuse 완료 후
cd finetuning

# 1. 어댑터 병합
uv run python scripts/fuse.py \
  --model     ~/.cache/huggingface/llama-3.1-8b \
  --adapter   outputs/adapters/llama-3.1-8b-rag-v1 \
  --output    outputs/fused/llama-3.1-8b-rag-v1

# 2. GPU 서버 staging 영역으로 전송
rsync -avz --progress \
  outputs/fused/llama-3.1-8b-rag-v1/ \
  deployer@gpu-server:/srv/models/staging/llama-3.1-8b-rag-v1/

# 3. GitHub Actions에서 workflow_dispatch로 모델 배포 트리거
# (Actions 탭 → Deploy Model → Run workflow → 버전명 입력)
```

모델 파일이 크기 때문에 NAS나 MinIO 같은 내부 스토리지를 중간 거점으로 쓰면 재전송 없이 여러 서버에 배포할 수 있습니다. 필요하면 MinIO 연동 구성도 잡아드릴 수 있습니다.
