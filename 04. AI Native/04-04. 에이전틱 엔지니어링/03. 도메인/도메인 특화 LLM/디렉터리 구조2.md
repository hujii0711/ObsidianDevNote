## `configs/lora_8b.yaml` — M4 48GB 최적화 설정

```yaml
model: "meta-llama/Meta-Llama-3.1-8B-Instruct"

# LoRA 하이퍼파라미터
lora_layers: 16          # M4 48GB: 16~32 가능, VRAM 여유 있음
lora_rank: 8             # 8~16 권장 (품질 vs 속도 균형)
lora_alpha: 16

# 학습 설정
batch_size: 4            # 48GB에서 8B 모델은 배치 4~8 가능
learning_rate: 1.0e-4
num_epochs: 3
max_seq_length: 2048
grad_checkpoint: true    # 메모리 절약 (속도 약 20% 감소)

# 저장
output_dir: "outputs/adapters/llama-3.1-8b-rag-v1"
save_every: 100          # 100 스텝마다 체크포인트

# 데이터
train_data: "data/processed/train.jsonl"
valid_data: "data/processed/valid.jsonl"
```

## `scripts/train.py` — 핵심 학습 스크립트

```python
import subprocess
import yaml
from pathlib import Path

def train(config_path: str):
    config = yaml.safe_load(Path(config_path).read_text())

    cmd = [
        "uv", "run", "python", "-m", "mlx_lm.lora",
        "--model",        config["model"],
        "--train",
        "--data",         config["train_data"],
        "--batch-size",   str(config["batch_size"]),
        "--num-layers",   str(config["lora_layers"]),
        "--lora-rank",    str(config["lora_rank"]),
        "--learning-rate",str(config["learning_rate"]),
        "--iters",        "1000",
        "--adapter-path", config["output_dir"],
        "--grad-checkpoint",
    ]
    subprocess.run(cmd, check=True)

if __name__ == "__main__":
    train("configs/lora_8b.yaml")
```

## `model-serving/server.py` — RAG generator 교체 핵심

```python
# mlx_lm 내장 OpenAI 호환 서버를 래핑
# backend의 generator.py가 이 서버를 바라봄
import subprocess
from config import MODEL_PATH, ADAPTER_PATH, PORT

def start():
    cmd = [
        "uv", "run", "python", "-m", "mlx_lm.server",
        "--model",       MODEL_PATH,    # finetuning/outputs/fused/
        "--port",        str(PORT),     # 8001
        "--host",        "0.0.0.0",
    ]
    # 어댑터 미병합 상태면 --adapter-path 추가
    if ADAPTER_PATH:
        cmd += ["--adapter-path", ADAPTER_PATH]

    subprocess.run(cmd, check=True)

if __name__ == "__main__":
    start()
```

`backend/app/rag/generator.py`의 OpenAI 클라이언트 `base_url`을 `http://localhost:8001/v1`로 설정하면 RAG 파이프라인이 파인튜닝 모델로 자동 전환됩니다.

## `Makefile` — 전체 워크플로 단축 명령

```makefile
# ── 학습 워크플로 ──
prepare:
	cd finetuning && uv run python scripts/prepare_data.py

train-8b:
	cd finetuning && uv run python scripts/train.py configs/lora_8b.yaml

eval:
	cd finetuning && uv run python scripts/evaluate.py

fuse:
	cd finetuning && uv run python scripts/fuse.py \
		--model meta-llama/Meta-Llama-3.1-8B-Instruct \
		--adapter-path outputs/adapters/llama-3.1-8b-rag-v1 \
		--output-path  outputs/fused/llama-3.1-8b-rag-v1

# ── 서빙 ──
serve-model:
	cd model-serving && uv run python server.py

# ── 전체 개발 스택 ──
dev:
	docker compose up -d db chroma
	cd model-serving && uv run python server.py &
	cd backend  && uv run uvicorn app.main:app --reload --port 8000 &
	cd frontend && npm run dev

# ── 의존성 ──
install:
	uv sync --all-packages
	cd frontend && npm install
```

## M4 48GB 운용 전략 요약

|모델|4-bit 크기|학습 가능|권장 용도|
|---|---|---|---|
|Llama 3.1 8B|~5 GB|가능 (배치 4~8)|QLoRA 학습 주력|
|Llama 3.1 70B|~38 GB|불가 (메모리 초과)|추론 전용 서빙|

실용 전략은 **8B로 QLoRA 학습 → 어댑터 병합 → RAG generator로 서빙**이고, 70B는 필요 시 추론만 활용하는 방식이 M4 48GB에서 가장 안정적입니다.

`prepare_data.py`의 jsonl 포맷 예시나 `evaluate.py` 코드가 필요하면 말씀해 주세요!
