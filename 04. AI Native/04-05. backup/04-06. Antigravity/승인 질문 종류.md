에이전트가 명령어(예: `ps` 관련 명령어)를 실행하려 할 때 나타나는 승인 질문의 4가지 선택지는 **권한의 허용 범위와 유효 기간**에 차이가 있습니다.

---

### 1. `1. Yes` (1회성 허용)
* **설명**: **오직 이번 1회만** 명령어 실행을 허용합니다.
* **효과**: 이 명령이 끝난 후, 에이전트가 또다시 `ps` 관련 명령이나 다른 명령을 실행하려고 하면 **다시 권한 승인 요청 팝업**이 뜹니다. 
* **용도**: 신뢰할 수 없는 일회성 명령어이거나 실행 결과를 직접 모니터링해야 할 때 선택합니다.

---

### 2. `2. Yes, and always allow in this conversation for commands that start with 'ps'` (세션 내 임시 허용)
* **설명**: **현재 대화 세션(Conversation) 동안만** `ps`로 시작하는 모든 명령어의 실행을 항상 자동 승인합니다.
* **효과**: 현재 대화 창(세션)이 열려 있는 동안은 에이전트가 `ps -ef`, `ps ax` 등을 몇 번을 실행하더라도 물어보지 않고 바로 실행합니다. 단, 에이전트를 종료하고 **새로운 세션을 열면 다시 물어봅니다.**
* **용도**: 현재 대화 주제 안에서 반복적으로 명령을 실행해야 하지만, 보안 규칙을 전역적으로 영구히 남기고 싶지는 않을 때 선택합니다.

---

### 3. `3. Yes, and always allow for commands that start with 'ps' (Persist to settings.json)` (영구 허용)
* **설명**: **언제나, 세션이 바뀌거나 PC를 재부팅해도** `ps`로 시작하는 명령어를 항상 자동 승인하도록 영구 지정합니다.
* **효과**: 승인 정보가 설정 파일(`.claude/settings.json` 또는 `~/.claude/settings.json`)에 저장됩니다. 앞으로는 새 세션을 열든 다른 날 프로젝트를 열든 `ps` 명령어 계열에 대해서는 **절대 다시 팝업이 뜨지 않습니다.**
* **용도**: 빌드 도구나 테스트 도구(`npm test`, `git status`, `ps` 등)처럼 보안상 안전하고 개발 중 매우 자주 사용하는 도구를 매번 승인하기 번거로울 때 선택합니다.

---

### 4. `4. No` (거절)
* **설명**: 명령어 실행을 **거절**합니다.
* **효과**: 에이전트에 권한 거부 오류가 반환되어 명령어가 실행되지 않으며, 에이전트는 이 명령을 포기하고 다른 우회 로직을 찾거나 에러 상황을 인지하여 대안을 찾습니다.
* **용도**: 에이전트가 실수로 시스템에 위해를 가할 수 있는 명령을 실행하려 하거나, 불필요한 연산을 하려고 할 때 차단하기 위해 사용합니다.
* 
---

### Antigravity에서는 명시적 승인 필요

- 현재 대화 중인 IDE 에이전트(Antigravity)는 샌드박스 보안 설계에 따라 임의의 명령어 실행 시 반드시 사용자 명시적 승인을 거치도록 되어 있습니다.
- 다만, 빈번한 권한 요청을 줄이기 위해 에이전트 측에서 특정 디렉토리 읽기/쓰기 권한이나 명령어 접두사(예: `git`, `uv run` 등)의 **범위 권한(Scope)**을 일괄 요청할 수 있습니다. 이 일괄 요청을 승인해 주시면 해당 범위 내의 작업들은 추가 확인 없이 연속해서 처리됩니다.
